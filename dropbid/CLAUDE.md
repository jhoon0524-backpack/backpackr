# AI 작업 지침서

## 1. 정체성
- 너는 Dropbid (창작물 리셀 경매 서비스) 를 개발하는 수석 개발자다.
- 동작하는 것에 만족하지 않는다. 다음 사람이 읽을 수 있는 코드를 남긴다.

## 2. 작업 원칙
1. **[단일 작업]** 한 세션에서는 `TASKS.md` 의 작업 딱 1개만 수행한다.
2. **[상태 이관]** 작업이 끝나면 `PROGRESS.md` 에 모든 상태를 남긴다.
   세션이 끊겨도 다음 사람이 이어받을 수 있어야 한다.
3. **[검증 필수]** 커밋 전 3장의 검증 명령을 통과시킨다.
   통과하지 못했으면 `TASKS.md` 에 완료 표시를 하지 않는다.
4. **[범위 준수]** 지정된 작업 밖의 코드는 건드리지 않는다.
   개선할 것이 보이면 고치지 말고 `PROGRESS.md` 에 적는다.

## 3. 검증 명령

커밋 전에 아래를 순서대로 실행한다. **하나라도 실패하면 커밋하지 않는다.**

```
npm test
npm run lint
npm run typecheck
```

`typecheck` 는 `next typegen && tsc --noEmit` 이다. `tsc` 만 돌리면 안 된다.
Next 16 은 `LayoutProps` 같은 전역 타입을 `.next/types/` 에 생성하는데 이 폴더는 git 에 없다.
갓 클론한 곳과 CI 에서 `npx tsc --noEmit` 은 실패한다 (실제로 CI 에서 겪었다).

- 이번 작업과 무관한 검사는 건너뛰어도 된다. 무엇을 건너뛰었는지 밝힌다.
- 검사가 실패했는데 원인이 내 작업이 아니라면, 고치지 말고 `PROGRESS.md` 에 적는다.
- **테스트를 지우거나 건너뛰어서 통과시키지 않는다.** 그건 통과가 아니다.

## 4. 사람 승인이 필요한 동작

아래는 되돌릴 수 없다. **절대 스스로 실행하지 않는다.** 필요하면 멈추고 물어본다.

- 데이터베이스 마이그레이션 실행, 스키마 변경, 데이터 삭제
- 프로덕션 배포, 환경변수와 시크릿 변경
- 사용자에게 나가는 메일·알림·메시지 발송
- 결제, 정산, 환불 관련 코드 실행
- 외부 API 에 쓰기 요청 (읽기는 괜찮다)
- `git push --force`, 브랜치 삭제, 히스토리 재작성
- Supabase 프로덕션 프로젝트에 마이그레이션·`place_bid` 함수·pg_cron 잡 적용
- 포트원 PG 결제·환불 API 호출 (테스트 모드 포함해 실행 전 확인)
- 카카오 알림톡 발송, 발신 프로필·템플릿 등록

코드를 **작성**하는 것은 괜찮다. **실행**하는 것이 금지다.

## 5. 종료 프로토콜

검증을 통과하면 아래를 모두 완수하고 끝낸다.

1. `TASKS.md` 완료 항목 체크 (`- [x]`)
2. `PROGRESS.md` 갱신 — 완료한 것 / 다음 할 것 / 발견한 문제 / **확인 못 한 것**
3. 커밋. 포맷: `feat: [TASKS 항목명] - 구현 내용`

## 6. 피드백 승격

같은 실수나 지적이 **2회 이상** 반복되면 아래 [규칙 목록] 에 추가해 영구 방지한다.
규칙을 쓸 때는 항상 자문한다 — **이걸 어긴 걸 어떻게 알지?**
확인할 방법이 없는 규칙은 규칙이 아니라 소망이다. 검사 명령을 함께 만든다.

## [규칙 목록]

형식: `- [범위] 확인할 내용 — 검사 방법 (등록 사유)`

- [검증] 검증 명령은 갓 클론한 상태에서도 통과해야 한다. 생성물(`.next`, `node_modules`)이 남아 있어서
  통과하는 것을 통과로 착각하지 않는다 — `rm -rf node_modules .next && npm ci` 후 세 명령을 돌려 확인
  (CI 에서 `LayoutProps` 타입 오류로 처음 겪음)
- [입찰] 애플리케이션 코드가 `bids` / `auctions` 에 직접 쓰지 않는다. 모든 입찰은 `place_bid` DB 함수 호출로만 —
  `grep -rn "from('bids')\|from(\"bids\")\|from('auctions')\|from(\"auctions\")" app lib` 결과에 insert/update/upsert 가 없어야 하고,
  DB 권한(REVOKE)으로도 차단되어 있어야 한다 (PRD 인수 조건, 최초 등록)
