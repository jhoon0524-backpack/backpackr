**테스트로 고정되지 않은 것은 지켜진다고 말할 수 없다.**

## 여기서 "고정"이 뜻하는 것

`npm test` 가 진짜 Postgres 에 붙어 매번 확인한다. CI 도 푸시마다 같은 것을 돌린다.
각 항목은 만들 때 **일부러 깨뜨려 빨간불을 확인한 뒤** 되돌렸다. 초록불만 보고 넘어간 것은 없다.

## 아직 못 지키는 것

알림은 **"보낼 것을 적재하는 데까지"** 만 고정됐다. PRD 의 알림 6종
(낙찰·유찰·미결제·상위 입찰·결제 기한 임박·검수 반려)이 모두 적재되지만,
실제 발송(알림톡·이메일)은 외부 키가 있어야 하고 그 부분은 코드도 없다.
적재는 상태 변경과 같은 트랜잭션에서 일어나므로 "상태는 바뀌었는데 알림이 없는" 틈은 없다.

## 실제 환경 리허설

2026-08-31, `dropbid` Supabase 프로젝트에서 전 과정을 1회 완주했다.
상품 등록 → 검수 승인 → live 전환 → 입찰(마감 30초 연장 발생) → **스케줄러 자동 마감** →
낙찰 확정 → 24시간 주문 생성 → 알림 2건 적재. 사람이 개입하지 않았다.
리허설 데이터는 정리했고 스케줄러는 계속 돈다.

## 릴리즈 1단계 롤백 조건과의 관계

PRD 릴리즈 계획 1단계의 롤백 조건은 두 가지다.

- "동시 입찰 인수 조건 미통과" → 1번이 매 푸시마다 확인된다
- "마감 처리 누락 1건 이상" → 3번(멱등)과 9번(실행 기록)이 함께 감시한다.
  특히 처리 건수가 0인 실행도 기록하므로 **기록이 끊긴 구간이 곧 스케줄러가 멈춘 구간**이다
