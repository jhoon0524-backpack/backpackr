## 확인한 것

### [스모크] 배포본
- `/` `/sell` `/admin` 모두 200. 드롭 3건이 보인다
- 배포 보호(Vercel Authentication·비밀번호·IP)가 **모두 꺼져 있다** — 주소만 알면 누구나 본다.

- 서버 오류 로그: 현재 배포본(`dpl_CDV…`, 11:10Z)에서 **0건**.
  대시보드에 남은 24건은 전부 그 앞 배포본의 접속 실패라 이번 것이 아니다

### [구경] 드롭 목록
- 제목·금액·남은 시간·입찰 수가 보인다. 금액은 `50,000원` 으로 자릿수 구분이 붙는다
- 입찰 0회 상품은 "현재가" 가 아니라 **"시작가"** 로 나온다
- 사진 주소가 죽으면 자리표시("사진 없음")로 바뀐다 (검수 화면에서 확인)
- 드롭이 전부 끝난 뒤에도 홈이 백지가 되지 않는다 —
  "지금 진행 중인 경매가 없습니다" + **지난 드롭 결과** 가 낙찰/유찰/미결제와 함께 나온다

### [입찰] 상품 상세
- 현재가·남은 시간·입찰 수·최고입찰자가 보이고, 최고입찰자는 `박*후` 로 가려진다
- 거절 6종이 전부 **화면에 한국어 문구를 띄운다.** 조용히 실패하는 곳은 없었다

  | 상황 | 화면에 뜨는 문구 |
  |---|---|
  | 판매자 본인 입찰 | 본인이 올린 상품에는 입찰할 수 없습니다. |
  | 연락처 없는 사용자 | 연락처를 먼저 등록해야 입찰할 수 있습니다. |
  | 최소 입찰가 미만 | 입찰가가 최소 입찰가보다 낮습니다. 최소 55,000원부터 가능합니다. |
  | 빈칸으로 입찰 | 입찰가를 숫자로 입력해 주세요. |
  | 이미 최고입찰자 | 이미 최고입찰자입니다. |
  | 로그인 안 함 | 버튼이 눌리지 않고 "위쪽에서 사용자를 먼저 골라 주세요." |

- 정상 입찰이 반영된다 (50,000 → 55,000, 입찰 3회, 다음 최소 60,000원)
- **새로고침 없이 현재가가 갱신된다** — 관전 창을 열어 둔 채 다른 창에서 70,000원을 넣으니
  3초 안에 관전 창이 55,000 → 70,000 으로 바뀌었다

### [판매] 상품 등록
- 사용자를 고르기 전에는 폼이 열리지 않는다
- 연락처가 없으면 폼 대신 "연락처가 등록되어 있지 않아…" + 마이페이지 링크가 나온다
- 사진 3장 미만 / 후원 인증 없음 / 시작가 1,000원 미만이 각각 막히고 문구가 뜬다
- 23,500원처럼 1,000원 단위가 아닌 금액도 등록된다 (의도대로)
- 등록에 성공하면 확인 문구가 뜬다

### [검수] 운영자
- 일반 사용자 헤더에 "검수" 가 없다. 주소로 직접 들어가도 "운영자만 볼 수 있는 화면입니다."
- 운영자에게만 "검수" 가 보이고 검수 대기 목록이 열린다
- 승인하면 고른 회차에 배정된다. 사유 없이 반려하면 막힌다
- 날짜가 `2026년 9월 1일 오후 10:24` 로 나온다 — 회귀 목록 1번 통과

### [마감] 결과
- 낙찰 화면에 금액(70,000원)과 낙찰자(`박*후`)가 보인다
- 낙찰자에게만 결제 기한이 보이고, 낙찰자가 아닌 사람에게는 안 보인다
- 유찰 화면 / 미결제 종료 화면이 각각 뜬다
- 유찰·미결제 상품을 판매자가 "같은 내용으로 다시 올리기" 로 재등록할 수 있고 확인 문구가 뜬다

### [회귀]

## 발견 (심각도순 — 이 순서가 곧 고칠 순서다)

### 1. 없는 경매 주소가 영어 화면으로 뜬다 · 높음
```
어디서   /auctions/00000000-0000-0000-0000-000000000000 (아무 사용자, 비로그인 포함)
무엇을   존재하지 않는 경매 주소를 연다
기대     한국어로 "찾을 수 없는 경매입니다" + 드롭 목록으로 돌아가는 길
실제     한국어 레이아웃 안에 "404 / This page could not be found." 가 영어로 뜬다
다시 됨? 매번. 사용자 3종 모두 동일
```
`app/not-found.tsx` 가 없어 Next.js 기본 화면이 그대로 나온다.
**회귀 목록 1번("한국어 화면에 영어가 새어 나오지 않는다") 위반.**
링크가 만료됐거나 오타 하나만 나도 사용자가 이 화면을 본다.

### 2. 검수 화면 오류 문구가 잘려 뜻을 잃는다 · 높음
```
어디서   /admin, 운영자
무엇을   검수 화면을 두 창에 열어 두고, 한 창에서 승인한 뒤 다른 창에서 같은 상품을 승인
기대     "이미 처리된 상품입니다" 같은, 사람이 읽을 수 있는 안내
실제     화면에 "scheduled" 한 단어만 뜬다
다시 됨? 매번
```
DB 가 올리는 문구는 `검수 대기 상태가 아니다: scheduled` 인데,
`app/admin/actions.ts:27` 의 `e.message.replace(/^.*?:\s*/, '')` 가 **첫 콜론 앞을 전부 지운다.**
문장이 통째로 사라지고 값만 남는다. 같은 코드가 41행에도 있다.
탭을 열어 두는 것은 운영자가 실제로 하는 일이라 드물지 않다.

### 3. DB 예외 문장이 그대로 사용자 화면에 나온다 · 중간
```
어디서   /admin, 운영자
무엇을   반려 사유를 비운 채 "반려" 를 누른다
기대     "반려 사유를 입력해 주세요."
실제     "반려 사유가 있어야 한다" — DB 함수의 개발자용 문구가 그대로
다시 됨? 매번
```
막히기는 한다. 문제는 **막는 문구가 화면용이 아니라는 것**이고,
2번과 같은 경로라 앞으로 어떤 DB 오류든(영어 포함) 그대로 새어 나온다.

### 4. 결제 기한이 낙찰 금액보다 작고, 남은 시간이 세지 않는다 · 중간
```
어디서   /auctions/<낙찰된 경매>, 낙찰자 본인
무엇을   낙찰 화면을 연다
기대     놓치면 거래가 날아가는 결제 기한이 가장 크게, 남은 시간이 함께
실제     금액은 text-2xl, 결제 기한은 text-sm. "2026년 9월 2일 오후 8:35까지" 절대 시각만
다시 됨? 매번
```
`app/auctions/[id]/result.tsx` 47행(금액)과 57행(기한). `Countdown` 을 쓰지 않는다.
체크리스트의 "낙찰자에게 결제 기한이 보이고 **남은 시간이 센다**" 를 채우지 못한다.
디자인 시안에는 "결제 기한을 낙찰 금액보다 크게" 로 이미 적혀 있는데 앱에 들어오지 않았다.

### 5. 검수 화면에서 후원 인증 이미지가 상품 사진보다 작다 · 중간
```
어디서   /admin, 운영자
무엇을   후원 인증과 상품 사진이 다 보이는 검수 건을 연다
기대     판단 근거인 후원 인증이 가장 크게
실제     후원 인증 156×156, 상품 사진 158×158 — 사실상 같고 오히려 2px 작다
다시 됨? 매번
```
검수는 이 이미지 하나로 판단하는 일이다. 시안의 "가장 크게" 가 앱에 반영되지 않았다.

### 6. 모바일 폭에서 제목이 잘린다 · 중간
```
어디서   / (드롭 목록), 폭 390px
무엇을   목록을 본다
기대     제목을 끝까지 읽을 수 있다 (두 줄이라도)
실제     제목 칸이 121px 로 눌려 6개 요소가 전부 잘린다
         "미공개 일러스트집 <새벽 산책> 한정판" 은 필요한 276px 중 121px 만 보인다
다시 됨? 매번. 가로 스크롤은 생기지 않는다
```
오른쪽 금액 칸이 자리를 먼저 가져간다. 시안에는 "모바일 제목 두 줄 허용" 이 있으나 앱에는 없다.

### 7. 없는 경매 주소가 HTTP 200 으로 응답한다 · 낮음
화면은 404 인데 상태 코드는 200 이다. 스트리밍이 시작된 뒤 `notFound()` 를 부르기 때문.
`/없는페이지` 는 정상적으로 404 를 준다. 사람 눈에는 안 보이지만 크롤러·모니터링이 "정상" 으로 읽는다.

### 8. 잘못된 형식의 주소가 서버 오류 로그를 남긴다 · 낮음
`/auctions/not-a-uuid` → 서버에 `22P02 invalid input syntax for type uuid` 가 찍힌다.
화면은 404 로 보이지만, **아무나 주소를 쳐서 오류 로그를 채울 수 있다.**
프로덕션 오류 대시보드가 이걸로 덮이면 진짜 오류가 묻힌다.

### 9. 문서에 적힌 프로덕션 주소가 배포마다 바뀌는 주소다 · 낮음(문서)
`qa/SPEC.md` 와 배포 안내서의 `dropbid-8d1h6w77c-…` 는 **그 배포 하나만** 가리킨다.
다음 배포 뒤에도 이 주소를 나눠 주면 사람들이 옛 버전을 보게 된다.
항상 최신을 가리키는 주소는 `https://dropbid-khan-9759s-projects.vercel.app` 다.

## 확인 못 한 것

이 절이 이 문서에서 제일 중요하다.

- **프로덕션에서의 클릭 조작** — 입찰·등록·검수·마감은 전부 **로컬 프로덕션 빌드**에서 봤다.
  배포본은 열어 보기(GET)만 했다. 같은 커밋·같은 스키마지만 같은 것을 봤다고 말할 수는 없다
- **카카오 로그인 / 실제 결제·환불 / 알림 실제 발송 / 사진 업로드** — 미연동. `SPEC.md` 4장 경계
- **마감 임박 자동 연장(20회 한도)** — 시간을 조작해 마감만 시켰고 연장 동작은 보지 않았다
- **실제 기기·실제 브라우저** — 390px 는 창 크기만 줄인 것이다. 실제 휴대폰에서는 다를 수 있다
- **여러 명이 동시에 같은 경매에 입찰할 때** — 창 두 개까지만 봤다
- 접근성, 부하·성능

## 도구 한계

- 컨테이너에서 `*.vercel.app` 으로 나가는 길이 막혀 있다 (`curl` 이 000).
  프로덕션은 Vercel MCP 로만 열 수 있고 **쿠키·폼 전송이 안 된다.** 그래서 조작은 전부 로컬이다
- `next dev` 는 일부 청크가 403 이라 하이드레이션이 안 된다.
  프로덕션 빌드(`next build && next start -p 3100`)로 바꿔서 봤다
- Playwright 1.62.1 이 요구하는 브라우저(빌드 1234)가 없어 설치된 1194 를 직접 지정했다

발견으로 적을 뻔했다가 도구 문제로 밝혀진 것들. 다음 사람이 같은 길로 새지 않도록 남긴다.

uuid 검사 1건, 문구 매핑 5건이 정확히 실패했고, 원복하니 다시 통과했다.

검증 3종 통과 — 테스트 149개(+7), lint, typecheck.

### 이번에도 도구에 한 번 속았다

바꾼다. 옛 빌드가 그대로 떠 있는 줄 모르고 "8번 고쳤는데 오류가 그대로 난다" 고
