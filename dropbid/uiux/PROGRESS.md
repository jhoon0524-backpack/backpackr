# UI/UX 진행 기록

## 1회차 (2026-09-01)

**대상** 로컬 프로덕션 빌드 (프로덕션과 같은 커밋). 폭 390·900, 밝음·어두움.
**방법** 화면을 캡처해 **그림으로 열어 봤다.** DOM 만 훑으면 "글자는 다 있다" 로
통과시키게 된다. 잴 수 있는 것(대비·터치 크기·잘림)은 따로 쟀다.

**한 줄 결론**
네 사람 중 **입찰하려는 사람과 팔려는 사람이 각각 한 번씩 막힌다.**
막히는 곳은 둘 다 "화면이 알려 주지 않아서" 이지 고장이 아니다. QA 는 통과한 자리다.

## 본 것

- 홈(비로그인·마감 후) · 상품 상세(입찰 전·낙찰 후) · 상품 등록(비로그인·폼)
- 마이페이지(빈 사람·판매자·낙찰자) · 검수 · 없는 주소
- 폭 390 과 900, 밝은 테마와 어두운 테마

**잘 되어 있던 것도 적는다** — 다음 사람이 여기를 다시 파지 않도록.

- 낙찰 화면의 **결제 기한이 화면에서 가장 크고 남은 시간을 센다.** [원칙] 1번 통과
- 어두운 테마와 밝은 테마의 바탕색이 **완전히 같다.** [원칙] 3번 통과
- 홈 목록 제목이 390 에서 안 잘린다
- 빈 화면 중 "내 입찰" 과 마감 후 홈에는 나가는 길이 있다
- 입찰 거절 문구 6종이 모두 한국어로 이유를 말한다

## 발견 (세기순)

### 1. 입찰이 되돌릴 수 없다는 것을 누르기 전에 모른다 · 높음 · 근거 3
```
어디서   상품 상세, 입찰하려는 사람
무엇을   55,000원을 넣고 [입찰하기] 를 누르려 한다
막힌 곳  버튼 위아래 어디에도 "취소할 수 없다" 가 없다. 확인 단계도 없다
왜       근거 3 — 돈이 걸린, 되돌릴 수 없는 행동인데 확인을 받지 않는다.
         낙찰되면 24시간 안에 결제할 의무가 생기는데 그 사실도 입찰 전에는 안 보인다
대신     버튼 옆에 "입찰은 취소할 수 없습니다. 낙찰되면 24시간 안에 결제해야 합니다"
```

### 2. 후원 인증과 사진에 무엇을 넣으라는 건지 모른다 · 높음 · 근거 4
```
어디서   상품 등록 폼, 처음 팔아 보는 사람
무엇을   등록을 끝내려 한다
막힌 곳  "후원 인증 이미지 — 없으면 등록되지 않습니다" 가 전부다.
         무엇을 찍어서 올리라는 건지 없다.
         사진칸은 빈 여러 줄 입력칸이라 파일을 올리는 곳처럼 보이는데,
         실제로는 이미지 **주소**를 줄바꿈으로 넣어야 한다. 예시도 없다
왜       근거 4 — 필수 항목인데 다음에 뭘 할지 화면이 안 알려 준다
대신     각 칸에 예시를 넣는다. "후원 내역 화면을 캡처해 올린 주소",
         "https://... 로 시작하는 이미지 주소를 한 줄에 하나씩"
```

### 3. 결제 기한을 넘기면 어떻게 되는지 안 적혀 있다 · 높음 · 근거 3
```
어디서   낙찰 화면, 낙찰된 사람
무엇을   언제까지 얼마를 내야 하는지 확인한다
막힌 곳  "23시간 59분 남음" 은 크게 보인다. 그런데 **어기면 무슨 일이 나는지** 없다
왜       근거 3 — 기한을 넘기면 거래가 종료되고(payment_failed) PRD 에는
         "해당 사용자 입찰 제한 검토" 까지 있다. 잃을 것을 모르고 기다리게 된다
대신     기한 밑에 "기한이 지나면 낙찰이 취소되고 다시 판매됩니다" 한 줄
```

### 4. 마이페이지가 PRD 의 탭 구조가 아니고, 빈 낙찰 칸에 나가는 길이 없다 · 중간 · 근거 1
```
어디서   마이페이지, 아직 아무것도 안 한 사람
무엇을   내 상태를 본다
막힌 곳  "내 입찰 / 낙찰 / 판매" 가 탭이 아니라 세로로 다 펼쳐져 있다.
         빈 칸도 자리를 다 차지해 390 에서 스크롤이 길다.
         "내 입찰" 빈 칸에는 [드롭 목록 보기] 가 있는데 "낙찰" 빈 칸에는 없다
왜       근거 1 — PRD 화면 상태 설계: "마이페이지 | 기본 | 내 입찰 / 낙찰 / 판매 **탭**",
         "빈 화면 | 탭별 안내와 **드롭 목록 링크**". 둘 다 어겼다
대신     탭으로 묶고, 빈 칸마다 같은 링크를 둔다
```

### 5. 마이페이지 판매 목록의 제목이 잘리고, 누를 수도 없다 · 중간 · 근거 2·4
```
어디서   마이페이지 판매 칸, 판매자
무엇을   내가 올린 것이 지금 어떤지 본다
막힌 곳  "미공개 일러스...", "보드게임 <달..." — 무엇인지 알 수 없다.
         제목에 287px 이 필요한데 146px 만 준다 (390 폭 기준).
         게다가 이 항목들은 **링크가 아니다** (판매 칸 3개 중 링크 0개).
         눌러서 열어볼 수 없다
왜       근거 2 — 잴 수 있는 잘림. 홈 목록은 같은 문제를 이미 고쳤는데 여기는 안 고쳤다
         근거 4 — 내 상품을 보러 가는 길이 화면에 없다
대신     홈과 같이 좁은 화면에서 뱃지·금액을 아래로 내리고, 항목을 상세로 링크한다
```

### 6. 마감된 경매에 진행 중 정보가 그대로 남아 같은 것을 두 번 말한다 · 중간 · 근거 1·5
```
어디서   상품 상세(마감 후), 낙찰된 사람
무엇을   결과를 확인한다
막힌 곳  위 상자는 "현재가 50,000원 · 최고입찰자 박*후 · 마감 연장 0회/20회",
         아래 상자는 "낙찰 50,000원 · 회원님이 낙찰받았습니다".
         같은 금액이 두 번, 같은 사람이 "최고입찰자" 와 "회원님" 두 이름으로 나온다.
         끝난 경매에 "현재가" 와 "마감 연장" 은 이제 뜻이 없다
왜       근거 1 — PRD "마감 후 | 입찰 영역을 결과 표시로 교체". 입찰 폼만 바뀌고
         상태 상자는 진행 중 화면 그대로다
         근거 5 — 같은 것을 두 이름으로 부른다
대신     마감 뒤에는 "현재가"를 "낙찰가"로 바꾸고, 마감 연장은 감춘다
```

### 7. 손가락으로 누르는 것이 대부분 44px 보다 작다 · 중간 · 근거 2
```
어디서   모든 화면, 휴대폰을 쓰는 사람
무엇을   누른다
막힌 곳  잰 값 — 헤더 메뉴 20px, [전환] 24px, [연락처 변경] 32px,
         [같은 내용으로 다시 올리기] 30px, [드롭 목록 보기] 16px
왜       근거 2 — 잴 수 있다. 통상 기준 44px
대신     실제 버튼에 세로 여백을 준다
```

### 8. 목록의 남은 시간에 라벨이 없고, 같은 숫자가 세 번 반복된다 · 중간 · 근거 1·5
```
어디서   홈 목록, 처음 온 구경꾼
무엇을   언제 끝나는지 본다
막힌 곳  "입찰 2회 · 01:59:29" — 무엇의 시간인지 안 적혀 있다.
         상세에는 "남은 시간" 라벨이 있는데 목록에는 없다.
         또 한 회차는 같이 마감하므로 세 카드가 **같은 숫자를 세 번** 보여 준다
왜       근거 5 — 화면마다 말이 다르다
         근거 1 — 시안(design/)에 "회차 카운트다운을 상단에 한 번만" 으로 이미 적어 뒀다
대신     회차 마감을 목록 맨 위에 한 번만 두고, 카드에서는 뺀다
```

### 9. 처음 온 사람에게 "드롭" 과 "회차" 를 설명하지 않는다 · 낮음 · 근거 4
```
어디서   홈 첫 화면, 처음 온 구경꾼
무엇을   여기가 뭐 하는 데인지 안다
막힌 곳  "이번 드롭 / 마감 임박순입니다. 회차에 속한 경매는 같은 시각에 함께 마감합니다."
         "드롭"·"회차" 는 안에서 쓰는 말이다. 서비스 설명은 브라우저 탭 설명에만 있고
         화면에는 없다
왜       근거 4 — 처음 온 사람이 다음에 뭘 할지 모른다
대신     제목 아래 한 줄. "끝난 크라우드펀딩 굿즈를 정해진 시각에 함께 마감하는 경매로 사고팝니다"
```

### 10. 목록에서 "상태 A" 의 뜻을 알 수 없다 · 낮음 · 근거 5
```
어디서   홈 목록, 처음 온 구경꾼
무엇을   물건이 새것인지 쓰던 것인지 가려낸다
막힌 곳  목록은 "상태 A" 까지만 보여 준다. 상세에 들어가야 "상태 A · 미개봉/새것" 이 나온다
왜       근거 5 — 같은 것을 화면마다 다르게 말한다. 뜻풀이는 코드에 이미 있는데
         (lib/format.ts 의 CONDITION) 목록에서만 안 쓴다
대신     목록에도 "미개봉/새것" 을 함께 보여 준다
```

### 11. "상품 등록" 과 "검수 신청" 이 같은 일의 두 이름 · 낮음 · 근거 5
메뉴와 제목은 "상품 등록", 버튼은 "검수 신청". 사용자가 하는 일은 하나다.

> **리더 검사에서 반려됨** (`qa/TRIAGE.md` 나-1). 두 말이 같은 것을 가리키지 않는다 —
> "상품 등록" 은 하는 일이고 "검수 신청" 은 누른 뒤 일어나는 일이다. 기록만 남긴다.

### 12. "마감 연장 0회 / 20회" 가 무슨 뜻인지 모른다 · 낮음 · 근거 4
```
어디서   상품 상세, 입찰하려는 사람
무엇을   언제 끝나는지 믿을 수 있는지 판단한다
막힌 곳  "마감 연장 0회 / 20회" 라고만 적혀 있다. 무엇이 연장되는지,
         20회가 무엇의 한도인지 없다. 끝난 경매에도 그대로 남아 있다
왜       근거 4 — 남은 시간을 믿고 입찰 시점을 정하는데, 그 시간이 늘어날 수
         있다는 규칙을 화면이 안 알려 준다
대신     "마감 직전 입찰이 들어오면 시간이 늘어납니다" 를 곁들이고,
         끝난 경매에서는 감춘다
```

## 못 본 것

- **결제 화면** — 포트원 미연동. [결제하러 가기] 뒤가 없다 (경계)
- **카카오 로그인 화면, 사진 업로드 화면, 알림 문구** — 미연동 (경계)
- **반려된 상품을 판매자가 보는 화면** — 반려 상태를 만들지 못했다. 다음 회차
- **느린 연결에서의 로딩 화면** — 스켈레톤은 있으나 실제로 느리게 해 보지 않았다
- **키보드만으로 순회, 스크린 리더** — 경계 밖
- **실제 기기** — 창 크기를 줄인 것이다. 실제 휴대폰의 글꼴·터치와는 다를 수 있다

## 도구 한계

- 프로덕션은 컨테이너에서 막혀 있어 로컬 프로덕션 빌드로 봤다 (같은 커밋)
- 캡처는 `deviceScaleFactor: 2` 로 찍었다. 실제 기기의 픽셀 밀도와 다를 수 있다

- **7번 터치 크기를 숫자로만 들이댔다.** 문장 속 글 링크(16·20px)까지 44px 를
  요구했는데, 그러면 헤더가 두 배로 부푼다. **기준은 "잘못 눌리나" 이지 "44 냐" 가
  아니다.** 버튼·입력만 받아들여졌다
