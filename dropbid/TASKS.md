## [1단계 드롭] — 지금부터 여기만 본다

**2026-09-02 결정**: 라이브 경매는 보류다. 먼저 1단계 드롭을 실제로 돌려
"드롭만으로 경쟁이 붙는가" 를 잰다 (`PRD.md` 가설 절).

아래가 **실제 사람에게 실제 돈으로 한 회차를 돌리기 위해** 남은 전부다.
위에서부터 순서대로. 각 항목에 **누가 막고 있는지**를 적었다.

### 사장님이 먼저 신청해야 하는 것 — 달력 시간이 걸린다

- [ ] **포트원 가맹점 심사 신청** — 심사에 영업일이 걸린다. 오늘 넣어야 한다.
      결제 없이는 1단계를 "실제 결제 포함" 으로 돌릴 수 없다 (`PRD.md` 릴리즈 계획)
- [ ] **카카오 알림톡 발신 프로필 등록 + 템플릿 사전 승인** — 템플릿 심사도 시간이 걸린다.
      필요한 템플릿 3종: 상위 입찰 알림 / 낙찰·유찰 알림 / 결제 기한 3시간 전 알림
- [ ] **카카오 로그인 앱 키 발급** — 개발자 콘솔에서 앱 만들고 REST API 키·시크릿 전달
- [ ] 통신판매중개업 신고 상태 확인 (`PRD.md` 논의사항)

### 내가 붙일 것 — 위 키가 오는 대로

- [ ] 카카오 로그인 (Supabase Auth) — 지금은 쿠키로 아무나 남이 될 수 있다.
      **실제 돈이 오가는 회차에서는 이게 열려 있으면 안 된다.** 1단계 최우선
- [ ] 사진 업로드 (Supabase Storage) — **키가 필요 없다. 지금 할 수 있다.**
      지금은 판매자가 이미지 주소를 붙여넣어야 한다. 휴대폰으로 찍어 올리는 흐름이 필요하다
- [ ] 입찰 API 라우트 — `place_bid` 호출만. 앱(네이티브)도 이 길을 쓴다
- [ ] 알림 발송 모듈 — **이메일 폴백을 먼저 붙인다.** 알림톡 승인을 기다리는 동안에도
      상위 입찰 알림이 나가야 한다 (아래 참고)
- [ ] 결제 연동 1 — 포트원 결제 요청 생성, 낙찰 시 24시간 기한 부여
- [ ] 결제 연동 2 — 결제 완료 웹훅 처리, 판매자 배송 요청 상태 전환

### 알림이 가설 검증에 직접 걸린다 — 빼면 안 된다

측정하려는 것은 "경매당 유니크 입찰자 2명 이상" 이다.
**상위 입찰 알림이 없으면 사람들은 자기가 밀린 것을 모르고 다시 안 들어온다.**
그러면 성립률이 낮게 나오는데, 그건 **가설이 틀린 것이 아니라 측정이 틀린 것**이다.

그래서 알림톡 승인을 못 기다리더라도 **이메일로라도 상위 입찰 알림은 나가야 한다.**
