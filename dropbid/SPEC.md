# Dropbid — 창작물 리셀 경매 서비스

> 상세 근거는 `PRD.md` 에 있다. 이 문서는 작업 중 빠르게 참조하는 요약본이다.
> 두 문서가 어긋나면 `PRD.md` 를 따르고 이 문서를 고친다.

## 1. 개요
- **무엇:** 종료된 크라우드펀딩 창작 굿즈를 주 1회 드롭(동시 마감) 방식 경매로 거래하는 웹 서비스
- **누가 쓰나:** 종료 리워드 보유자(판매자), 펀딩을 놓친 구매자, 검수하는 운영자
- **성공 기준:**
  - 경매 성립률(유니크 입찰자 2명 이상인 경매 / 마감된 경매)이 드롭 회차마다 상승
  - 낙찰 후 미결제율(기한 내 미결제 / 낙찰)이 회차별 누적 상승하지 않음
  - 두 지표 모두 `auctions` / `bids` / `orders` 테이블만으로 계산 (별도 이벤트 로깅 없음)

## 2. 핵심 흐름
1. 카카오 로그인으로 가입한다 (연락처 미등록이면 등록·입찰 차단)
2. 판매자가 상품 + 후원 인증 이미지를 등록한다 → `pending`
3. 운영자가 승인하면 다음 드롭 회차에 배정된다 → `scheduled`
4. 드롭 시작 시각에 `live` 전환, 마감 시각까지 입찰 (마감 30초 전 입찰 시 30초 연장, 최대 20회)
5. 스케줄러가 마감 처리: 입찰 있으면 `sold`, 없으면 `unsold` (멱등)
6. 낙찰자가 24시간 내 PG 결제 → 판매자에게 배송 요청. 미결제 시 `payment_failed`

## 3. 기술 규격
- **스택:** Next.js (App Router) + TypeScript + Tailwind
- **데이터 저장:** Supabase Postgres (입찰은 `place_bid` DB 함수 + 행 잠금으로만), Storage(이미지)
- **외부 연동:** 카카오 로그인·알림톡(이메일 폴백), 포트원 PG, Supabase Realtime(현재가)·pg_cron(마감)
- **배포:** Vercel
- **금지:** 텀블벅 내부 데이터·API·계정 사용. 원 프로젝트 정보는 판매자 입력 + 공개 링크만

## 4. 경계

만들지 않는다 (PRD OUT 항목):
- 자동입찰(상한 위임), 즉시구매, 차순위 낙찰 이월
- 판매자 정산 자동화 (초기 운영자 수동 이체), 창작자 리셀 수수료 배분
- 배송 추적, 분쟁 조정, 판매자 등급, 리뷰
- 검색·필터, 모바일 앱 (웹 반응형만)
- 카테고리 1개로 한정 시작

## 5. 되돌릴 수 없는 지점

`CLAUDE.md` 4장과 짝을 이룬다.
- PG 결제 승인·환불 실행 (포트원)
- 카카오 알림톡·이메일 발송
- 프로덕션 DB 마이그레이션, `place_bid` 함수 교체, pg_cron 잡 등록
- 낙찰 확정 (`sold` 전환 — 이후 결제 의무 발생)
- 입찰 기록 (입찰은 취소 불가가 정책)
