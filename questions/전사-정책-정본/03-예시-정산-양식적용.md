## 1. 한 줄 정의

**다루는 것**: 펀딩 성공 확정 또는 상시 판매 확정 후 창작자에게 돈이 가는 규칙. 수수료율, 계산식, 정산일, 정산 상태, 분할 정산, 세금계산서·정산명세서.

**안 다루는 것**:
- 결제 승인·취소·예약결제(All-or-Nothing) 상태 → 「후원 · 결제」
- SNS 광고 수수료율, 후불광고, 비즈머니 → 「광고센터」
- 프로젝트 성공·실패 상태 전체 → 「프로젝트」 (여기서는 정산 관련 2개 상태만 다룸)

**흐름 (두 파이프라인은 서로 독립)**

```
[펀딩/프리오더]  성공(정산 전) → 정산일(결제 종료일+7영업일) 배치 자동 실행
                → 미결제 정리 → 세금계산서 항목 → 검증 → 금액 계산 → 창작자 송금 → 텀블벅 수익계좌 송금 → 성공/정산완료
[상시 프로젝트]  데이터 생성 중 → 데이터 생성 완료 → ★어드민 확정(FIXED) → 송금 처리 중 → 전체 입금 완료
```

## 2. 용어

| 용어 | 뜻 | 헷갈리는 이유 |
|---|---|---|
| 펀딩 정산 | 기간 펀딩 프로젝트 단위 정산. 정산일에 배치 자동 실행 | 상시 정산과 계산식·반올림·트리거가 다름 |
| 상시 프로젝트 정산 | 상시 판매 프로젝트의 월별·창작자별 집계 정산. 어드민 확정 후 송금 | 노션 Legacy 문서에 아예 없던 개념 |
| 서비스 수수료 | 텀블벅이 창작자에게 받는 정산 수수료. 요금제별 START 5% / RUN 9% / BOOST 15% | SNS 광고 수수료율(광고센터)과 별개 축 |
| 결제 수수료 | PG 결제 처리 수수료. 요금제 무관 3% 고정 | 창작자 정산금에서는 빠지지만 텀블벅 수익계좌로는 안 감 (R8) |
| 수수료 요금제 | 창작자가 고르는 요금제. 대외 명칭 START·RUN·BOOST (+DEFAULT 폴백) | 코드는 옛 이름 BASIC·PRO·PREMIUM 그대로 |
| MOU 예외 요율 | 협약 프로젝트에 어드민이 등록하는 개별 요율 | 요금제 요율보다 우선 |
| 결제 반영 금액 | 선물 금액 − 응원권 차감액 | 상시 정산 계산의 출발점 |
| 조건부 수동 분할 정산 | 1차 선지급 + 2차 지급. 2차는 AUTO 또는 MANUAL(운영자 지정일) | "수동"은 2차 날짜를 사람이 정한다는 뜻 |

## 3. 규칙

**파이프라인·수수료율**
- R1. 펀딩/프리오더 정산은 정산일에 배치가 자동 실행한다. 상시 정산은 어드민이 데이터를 확정(FIXED)해야만 송금까지 간다.
- R2. 서비스 수수료율은 요금제별로 START 5% / RUN 9% / BOOST 15% / DEFAULT(폴백) 5%다.
- R3. 결제 수수료는 요금제와 무관하게 3% 고정이며, 펀딩·상시 둘 다 같다.
- R4. MOU 예외 요율이 있으면 요금제 요율보다 우선한다. 상시 정산에서 한 프로젝트에 예외 요율이 여러 개면 가장 작은 값을 쓴다.
- R5. 상시 프로젝트를 새로 만들면 기본 요금제는 RUN이다.

**계산식**
- R6. 펀딩 정산금 = 총 모금액 − 서비스 수수료 − 결제 수수료 − 예치 수수료(현행 0) − 이 세 수수료의 부가세(각 10%) − 후불광고 차감액. 원 단위 절사.
- R7. 계산된 정산금이 0보다 작으면 그 프로젝트는 정산을 중단한다.
- R8. 결제 수수료는 창작자 정산금에서 차감하지만 텀블벅 수익계좌 송금액에는 넣지 않는다. 텀블벅 수익계좌 송금액 = 서비스 수수료 + 그 부가세 + 후불광고 차감액.
- R9. 반올림: 수수료 자체는 반올림, 수수료 부가세는 절사, 펀딩 최종 정산금은 절사. 상시는 건별 계산식에 이미 반영돼 별도 절사 없음.
- R10. 상시 정산 건별: 기준일 = min(구매확정일, 결제일+7일)이 정산 대상월에 속하면 그달 대상. 정산금 = 결제 반영 금액 − 서비스 수수료(반올림) − 그 부가세(절사) − 결제 수수료 3%(반올림) − 그 부가세(절사). 창작자별·월별 정산금은 건별 합계.

**정산일·상태**
- R11. 펀딩 정산일 = 결제 종료일 + 7영업일. 프리오더 = 마지막 배송일 + 14일(마지막 환불 처리 기한과 비교해 더 늦은 날) + 1영업일. 분할 1차 = 지정일 또는 펀딩 잔금 정산일. 분할 2차 = 지정일 → MANUAL이면 운영자 지정일 → 아니면 프리오더 기본 정산일.
- R12. 펀딩 "성공/정산완료"(SUCCEEDED_BALANCED) 전이는 "성공"(SUCCEEDED_NOT_BALANCED) 상태에서만 허용한다. 그 외 상태에서 시도하면 예외. 이것으로 중복 정산을 막는다.
- R13. 창작자 송금이 실패하면 상태를 유지하고 다음 배치에서 재시도한다. 텀블벅 수익계좌 송금이 실패해도 정산은 성공 처리하고 별도 재송금 절차는 없다.
- R14. 상시 정산 상태는 GENERATING_DATA → DATA_GENERATED → FIXED(어드민 수동) → PROCESSING_PAYMENT → FULLY_PAID 순서만 간다. MANUAL_ADJUSTING은 FULLY_PAID에서만, 데이터 재생성은 DATA_GENERATED·FAILED에서만 가능하다.
- R15. 창작자에게 보이는 정산 상태는 5개: 결제기간 / 정산 미확정 / 정산 확정 / 첫 정산 완료 / 정산 완료.

**분할 정산·문서**
- R16. 분할 정산은 1차·2차가 모두 완료돼야 완료다. 분할 대상 프로젝트는 일반 정산 대상에서 제외하고 1차/2차를 따로 처리한다.
- R17. 상시 정산 문서(세금계산서·정산명세서·판매대행 문서)는 DATA_GENERATED·FIXED·FULLY_PAID 상태에서만 만든다. 납세자 유형(개인사업자/법인사업자)에 따라 서식이 다르다. 분기 단위 일괄 잠금 가능.
- R18. 상시 정산 요약(SettlementSummary)은 납세자 정보와 계좌·예금주 정보를 암호화해 보관한다.

**요금제 변경**
- R19. 승인 전에는 창작자가 직접 요금제를 바꾼다. 승인 후에는 헬프센터 요청 → 운영셀이 어드민에서 바꾼다. `[확인 필요: 운영셀]`
