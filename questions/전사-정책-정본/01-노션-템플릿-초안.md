> 상태: **초안. 아직 노션에 만들지 않음.** 브리프 6항(노션 쓰기는 확인 후 진행)에 따라 여기서 먼저 확인.
> 생성 위치(제안): 「도메인 문서」DB (id `c79f0307-25e2-4f95-b4ab-e7bb6099e2b8`) 안에 새 페이지 1개. 제목 `[양식] 도메인 정본 템플릿`.

## C. 기존 12개 도메인 페이지에 적용하는 법 (갈아엎지 않음)

기존 페이지 구조는 대체로 `핵심 비즈니스 정책 / 기능별 정책 및 예외사항 / (용어)` 이므로:

| 기존 섹션 | 양식 칸 | 작업 |
|---|---|---|
| (페이지 맨 위 설명) | 1. 한 줄 정의 | "안 다루는 것" 한 줄만 추가 |
| 용어 | 2. 용어 | 그대로 |
| 핵심 비즈니스 정책 | 3. 규칙 | 문단을 번호 규칙(R1, R2…)으로 쪼갬. 내용은 안 바꿈 |
| 기능별 정책 및 예외사항 | 4. 예외·엣지 | 표로 정리. 내용은 안 바꿈 |
| (없음) | 5. 근거·출처 | **새로 추가.** 본문에 흩어진 "노션 SSOT에 미기재 — 코드/담당자 확인 필요"를 여기 표로 모음 |
| (없음) | 6. 변경 이력 | **새로 추가.** 첫 줄은 "2026-07-14 / 전체 / 기존 문서+코드 기반 재생성 / 블벅이" |

## D. 작업 순서 (Khan OK 후)

1. DB에 속성 3개 추가 (DRI · 최종 확인일 · 상태)
2. `[양식] 도메인 정본 템플릿` 페이지 생성 (B 본문 그대로)
3. 예시 페이지: 「정산 · 수수료 요금제」를 양식으로 리라이팅해 `[예시] 정산 · 수수료 요금제 (양식 적용)` 로 **새 페이지** 생성. 기존 페이지는 손대지 않음 → 작업팀이 둘을 나란히 보고 판단
