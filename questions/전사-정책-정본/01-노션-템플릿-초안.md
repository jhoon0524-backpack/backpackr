## C. 기존 12개 도메인 페이지에 적용하는 법 (갈아엎지 않음)

12페이지 모두 같은 H2 5개를 씀: `1. 기능 개요(+용어 정의)` / `2. 사용자 경험 프로세스` / `3. 핵심 비즈니스 정책` / `4. 기능 별 정책 및 예외사항(+4.N 미확정·확인 필요 항목, 4.N+1 관련 도메인 문서)` / `5. 참고 문서(+코드 정합 검증 콜아웃)`. 그래서 대응이 거의 1:1임.

| 기존 섹션 | 양식 칸 | 작업 |
|---|---|---|
| 1. 기능 개요 (기능 목적·이용 대상) | 1. 한 줄 정의 | "안 다루는 것 → 어느 페이지" 한 줄만 추가 |
| 1. 기능 개요 › 용어 정의 | 2. 용어 | 그대로 |
| 2. 사용자 경험 프로세스 (흐름도) | 3. 규칙 맨 위 | 칸을 늘리지 않고 규칙 칸 첫머리에 흐름도로 유지 (제안. 버려도 됨) |
| 3. 핵심 비즈니스 정책 | 3. 규칙 | 이미 번호가 있음. R1, R2… 로 이름만 붙이고 한 줄 = 규칙 하나로 쪼갬. 내용은 안 바꿈 |
| 4. 기능별 정책 및 예외사항 | 3. 규칙 / 4. 예외·엣지 | 규칙성 문장은 3번으로, "~인 경우"는 4번 표로. 상태값 표·계산식은 규칙에 붙임 |
| 4.N 미확정 · 확인 필요 항목 | 5. 근거·출처의 "확인 상태" 열 | **표를 옮기고 규칙 번호를 매김.** 본문에 흩어진 `[확인 필요]`도 여기로 모음 |
| 4.N+1 관련 도메인 문서 | 1. 한 줄 정의의 "안 다루는 것" | 링크만 옮김 |
| 5. 참고 문서 (Legacy 링크) | 5. 근거·출처 | 규칙별로 어느 Legacy 페이지·코드가 근거인지 붙임 |
| 코드 정합 검증 콜아웃 | 6. 변경 이력 첫 줄 | "2026-07-14 / 전체 / 기존 문서+코드 기반 재생성 / PO-agent" |

## D. 작업 순서 (Khan OK 후)

1. DB에 속성 3개 추가 (DRI · 최종 확인일 · 상태)
2. `[양식] 도메인 정본 템플릿` 페이지 생성 (B 본문 그대로)
3. 예시 페이지: 「정산 · 수수료 요금제」를 양식으로 리라이팅해 `[예시] 정산 · 수수료 요금제 (양식 적용)` 로 **새 페이지** 생성. 기존 페이지는 손대지 않음 → 작업팀이 둘을 나란히 보고 판단
