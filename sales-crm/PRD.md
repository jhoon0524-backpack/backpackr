## 1. 배경 및 문제 정의

영업팀은 현재 리드 발굴부터 계약 성사까지의 과정을 스프레드시트, 메신저, 개인 메모에 분산해 관리하고 있다. 이로 인해 다음 문제가 반복된다.

- **파이프라인 가시성 부재** — 이번 분기에 얼마짜리 딜이 어느 단계에 몇 건 있는지 아무도 즉답하지 못한다.
- **히스토리 유실** — 담당자가 바뀌면 고객과 무슨 대화가 오갔는지 알 수 없어 관계를 처음부터 다시 쌓는다.
- **후속 조치 누락** — 제안서 발송 후 회신 기한, 계약 예상 마감일 등을 개인 기억에 의존해 놓친다.
- **보고 비용** — 주간 영업 회의용 현황 집계를 매주 수작업으로 만든다.

외부 SaaS CRM(Salesforce, HubSpot 등)은 기능 과잉·비용·데이터 주권 문제로 도입 부담이 크다. **우리 영업 프로세스에 딱 맞는 경량 자체 CRM**을 만든다.

## 2. 목표 (Goals)

1. 영업사원이 **하루 5분 이내**의 입력으로 모든 고객 접점을 기록할 수 있다.
2. 팀장이 **집계 작업 없이** 실시간 파이프라인 현황(단계별 건수·금액)을 본다.
3. CRM에서 고른 수신자에게 **개인화된 단체메일을 발송**하고, 발송 이력이 고객별로 남는다.
4. 발송 메일이 **Gmail 받은편지함에 도달**한다 — 스팸함 직행률을 구조적으로 낮춘다.
5. 담당자 교체 시 **활동 히스토리만 읽고** 딜을 이어받을 수 있다.
6. 사내 인프라에서 **셀프 호스팅** 가능하고 운영 비용이 사실상 0이다.

### 성공 지표 (KPI)

| 지표 | 목표 | 측정 시점 |
|---|---|---|
| 영업팀 주간 활성 사용률 | 80% 이상 | 도입 후 1개월 |
| 딜의 활동 기록 보유율 (활동 1건 이상인 진행 딜 비율) | 90% 이상 | 도입 후 1개월 |
| 주간 영업 현황 보고 작성 시간 | 30분 → 5분 이하 | 도입 후 2주 |
| 예상 마감일 경과 후 방치된 딜 비율 | 10% 이하 | 도입 후 2개월 |
| 단체메일 하드바운스율 | 2% 미만 | 매 캠페인 |
| 단체메일 스팸 신고율 | 0.1% 미만 (Gmail 기준선) | 매 캠페인 |
| 단체메일 회신율 | 캠페인별 측정, 기준선 수립 | 도입 후 2개월 |

## 4. 유저 스토리

### 필수 (v0.1 — 구현 완료)

- [x] 영업 담당자로서, **고객사와 담당 연락처를 등록·검색**할 수 있다.
- [x] 영업 담당자로서, **딜을 생성하고 금액·예상 마감일·담당자를 기록**할 수 있다.
- [x] 영업 담당자로서, **칸반 보드에서 딜을 드래그해 단계(리드→컨택→제안→협상→성사/실패)를 옮길** 수 있다.
- [x] 영업 담당자로서, **통화/미팅/이메일/메모 활동을 딜에 남길** 수 있다.
- [x] 영업 팀장으로서, **대시보드에서 파이프라인 총액·단계별 현황·다가오는 마감·최근 활동**을 본다.
- [x] 사용자로서, **딜/고객사/연락처를 키워드로 검색**할 수 있다.

### v0.2~v0.3 (최우선 — 단체메일 & 전달률)

- [ ] 영업 담당자로서, **딜 단계·업종·고객사 기준으로 수신자를 골라** 단체메일을 보낼 수 있다.
- [ ] 영업 담당자로서, **{{이름}}, {{회사}} 같은 치환 변수가 있는 템플릿**으로 메일을 개인화할 수 있다.
- [ ] 영업 담당자로서, 발송 전 **내 주소로 테스트 발송**하고 실제 렌더링을 확인할 수 있다.
- [ ] 영업 담당자로서, **누가 언제 어떤 메일을 받았는지** 고객·딜 화면에서 확인할 수 있다.
- [ ] 수신자로서, **원클릭으로 수신거부**할 수 있고, 거부한 주소로는 다시 발송되지 않는다.
- [ ] 영업 팀장으로서, 캠페인별 **발송/실패(바운스)/수신거부 현황**을 볼 수 있다.
- [ ] 시스템은 **Gmail이 요구하는 발신 요건(SPF/DKIM/DMARC 정렬, List-Unsubscribe, 발송량 제한)**을 준수한다.

### v1.0 (정식 도입)

- [ ] 사용자로서, **로그인**하여 내 계정으로 작업하고, 딜에 실제 사용자를 담당자로 지정할 수 있다.

## 5. 기능 요구사항

### 5.1 데이터 모델

| 엔티티 | 주요 필드 | 관계 |
|---|---|---|
| 고객사 (Company) | 이름*, 업종, 웹사이트, 전화, 메모 | 1:N 연락처, 1:N 딜 |
| 연락처 (Contact) | 이름*, 직함, 이메일, 전화, 메모 | N:1 고객사 |
| 딜 (Deal) | 제목*, 금액, 단계*, 예상 마감일, 담당자, 메모 | N:1 고객사, N:1 연락처, 1:N 활동 |
| 활동 (Activity) | 유형*(통화/미팅/이메일/메모), 내용*, 작성 시각 | N:1 딜, N:1 고객사 |

딜 단계: `lead(리드) → contacted(컨택) → proposal(제안) → negotiation(협상) → won(성사) / lost(실패)`

### 5.2 화면 요구사항

| 화면 | 요구사항 |
|---|---|
| 대시보드 | 진행 중 파이프라인 총액/건수, 이번 달 성사 금액, 단계별 현황 바, 예상 마감 임박 딜 5건, 최근 활동 8건 |
| 파이프라인 | 6단계 칸반, 카드에 딜명·고객사·금액·마감일 표시, 드래그 & 드롭 단계 이동, 컬럼별 합계 금액 |
| 딜 목록 | 테이블 뷰, 키워드 검색 + 단계 필터, 행 클릭 시 수정 모달 |
| 고객사 / 연락처 | 테이블 뷰, 검색, 연결된 딜·연락처 수 표시, 수정/삭제 모달 |
| 활동 | 최신순 타임라인, 유형 아이콘, 관련 딜 표시 |

### 5.3 동작 규칙

- 딜 단계 변경 시 `updated_at` 갱신 (대시보드 "이번 달 성사" 집계 기준).
- 활동을 딜에 연결하면 고객사는 딜에서 자동 상속.
- 고객사 삭제 시 연락처·딜은 삭제하지 않고 연결만 해제(NULL), 활동은 딜 삭제 시에만 연쇄 삭제.
- 모든 입력은 서버에서 길이 제한·필수값·허용값(단계, 활동 유형) 검증.

### 5.4 단체메일 & 전달률 (v0.2~v0.3 핵심)

**발송 파이프라인**

1. **수신자 선택** — 연락처를 딜 단계 / 업종 / 고객사 / 최근 활동일 기준으로 필터해 세그먼트 구성. 이메일 없는 연락처·수신거부자·최근 하드바운스 주소는 자동 제외.
2. **템플릿 작성** — 제목/본문에 치환 변수(`{{이름}}`, `{{직함}}`, `{{회사}}`, `{{발신자}}`) 지원. 템플릿 저장·재사용.
3. **검수** — 발송 전 수신자별 렌더링 미리보기 + 본인 주소 테스트 발송 필수. 콘텐츠 사전 점검(아래 규칙) 경고 표시.
4. **발송** — Gmail API로 **수신자별 개별 메일** 발송 (BCC 대량 발송 금지). 발송 간격 쓰로틀(기본 5~10초/통) + 일일 발송 한도 관리.
5. **기록** — 캠페인·수신자별 발송 상태(성공/실패/바운스/수신거부)를 저장하고, 해당 연락처의 활동 타임라인에 자동 기록.

**Gmail 스팸 회피 요구사항** (Google 대량 발신자 가이드라인 준거)

| 영역 | 요구사항 |
|---|---|
| 발신 경로 | 자사 Google Workspace 계정에서 **Gmail API로 발송** → 구글 인프라가 SPF/DKIM 서명, From 도메인(backpac.kr)과 자동 정렬 |
| 도메인 인증 | backpac.kr의 SPF·DKIM·DMARC 레코드 상태를 앱에서 진단(DNS 조회)하고 미비 시 설정 가이드 제공 |
| 수신거부 | 모든 단체메일에 `List-Unsubscribe`(원클릭) 헤더 + 본문 수신거부 링크. 거부 즉시 발송 대상에서 영구 제외 |
| 발송량 | 일일 한도(기본 400통, Workspace 한도 2,000의 20%에서 시작) + 신규 발송 초기는 소량부터 점증(워밍업). 한도 초과 시 자동으로 다음 날로 이월 |
| 바운스 처리 | 반송 메일 감지 시 해당 주소 하드바운스 마킹, 이후 캠페인에서 자동 제외 |
| 콘텐츠 규칙 | 텍스트 중심(HTML 최소화), 링크 단축 URL 금지, 첨부 대신 링크, 이미지 과다 경고, 제목 낚시성 문구(전액 무료, 긴급 등) 경고 |
| 개인화 | 수신자별 치환 변수 사용 권장(동일 본문 대량 발송 감지 회피가 아니라, 실제 회신율·평판 개선 목적) |
| 발신자 평판 | 회신 가능한 실제 영업 계정에서 발송(no-reply 금지), Google Postmaster Tools 등록 가이드 |

**범위 주의**: 오픈 트래킹 픽셀은 도입하지 않는다(스팸 점수 상승 + 개인정보 이슈 대비 효용 낮음). 성과는 회신율·바운스율로 측정.

## 6. 비기능 요구사항

| 항목 | 요구사항 |
|---|---|
| 기술 스택 | Node.js 22+ 단독 (내장 `node:sqlite`, 내장 `http`), 프론트 바닐라 JS SPA — **외부 의존성 0, 빌드 불필요** |
| 배포 | 사내 서버에서 `npm start` 단일 명령. DB는 로컬 SQLite 파일(WAL 모드) |
| 성능 | 동시 사용자 ~30명, 딜 1만 건 규모에서 목록/검색 응답 500ms 이내 |
| 백업 | `data/crm.db` 파일 단위 백업 (v1.0에서 일 1회 자동 백업 스크립트 제공) |
| 보안 | v0.1은 사내망 전제. v1.0에서 로그인 도입 전까지 외부 공개 금지 |
| 브라우저 | 최신 Chrome/Edge/Safari (데스크톱 우선) |

## 10. 미결 사항 (Open Questions)
