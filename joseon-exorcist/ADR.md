# 결정 기록

왜 이렇게 만들었는지 적는다. 코드는 "무엇"을 보여주지만 "왜"는 보여주지 않는다.
기록이 없으면 다음 세션의 AI 가 같은 고민을 반복하거나, 이유를 모른 채 결정을 뒤집는다.

**언제 쓰나:** 나중에 바꾸기 어려운 선택을 했을 때만. 스택, 데이터 구조, 외부 서비스, 구조를 나누는 방식.
변수 이름이나 작은 구현 방식은 적지 않는다.

**고칠 때:** 지난 기록은 지우지 않는다. 새 항목을 쓰고 옛 항목의 상태를 "대체됨 → N번" 으로 바꾼다.

## 1. 파일 하나 안에서 규칙과 화면을 나누고, 규칙만 Node 로 검사한다
- **날짜:** 2026-09-25
- **상태:** 채택
- **상황:** 기획서가 "HTML 파일 1개, 외부 라이브러리 없음" 을 요구한다. 그런데 AI 가 사람 없이 돌려면
  결과를 기계가 판정할 검사가 있어야 한다. 화면은 브라우저 없이는 검사하기 어렵다.
- **결정:** `index.html` 안에 `<script id="core">` 를 따로 두고 규칙(이동·피해·AI·턴·승패)을 전부 넣는다.
  core 는 화면(DOM)과 `Math.random` 을 직접 쓰지 않는다. `tests/` 가 파일에서 core 를 꺼내 Node 내장
  `vm` 으로 실행하고 `node --test` 로 검사한다.
- **이유:** 파일 1개 조건을 지키면서 설치 없이(Node 만으로) 규칙을 자동 검사할 수 있다.
  기획의 핵심(상성·피해·AI)이 규칙 쪽에 몰려 있어 여기를 잡으면 대부분을 잡는다.
- **포기한 대안:**
  - 규칙을 별도 `.js` 파일로 분리 — 검사는 쉬워지지만 "파일 1개" 조건을 어긴다
  - 브라우저 자동화(Playwright)로 화면까지 검사 — 설치가 필요하고 PC 마다 환경이 달라 루프가 자주 멈춘다.
    대신 화면은 사람이 확인한다
