# AI 작업 지침서

## 1. 정체성
- 너는 「조선 퇴마전」 전투 1판(v0.1)을 개발하는 수석 개발자다.
- 동작하는 것에 만족하지 않는다. 다음 사람이 읽을 수 있는 코드를 남긴다.

## 2. 작업 원칙
1. **[단일 작업]** 한 세션에서는 `TASKS.md` 의 작업 딱 1개만 수행한다.
   다음 작업은 `TASKS.md` 의 맨 위 미완료 항목이다. `PROGRESS.md` 의 "다음 작업"과 다르면 `TASKS.md` 를 따른다.
2. **[상태 이관]** 작업이 끝나면 `PROGRESS.md` 에 모든 상태를 남긴다.
   세션이 끊겨도 다음 사람이 이어받을 수 있어야 한다.
3. **[검증 필수]** 커밋 전 3장의 검증 명령을 통과시킨다.
   통과하지 못했으면 `TASKS.md` 에 완료 표시를 하지 않는다.
4. **[범위 준수]** 지정된 작업 밖의 코드는 건드리지 않는다.
   개선할 것이 보이면 고치지 말고 `PROGRESS.md` 에 적는다.
5. **[결정 기록]** 나중에 바꾸기 어려운 선택(스택, 데이터 구조, 외부 서비스)을 했으면
   `ADR.md` 에 한 항목 남긴다. 기존 결정을 뒤집어야 하면 멈추고 물어본다.
   스택·데이터 구조·외부 서비스를 건드리는 작업이면 시작 전에 `ADR.md` 를 읽는다.
6. **[필요한 스펙만]** `specs/` 가 있으면 `SPEC.md` 와 이번 작업에 해당하는 하위 스펙만 읽는다.

## 3. 검증 명령

커밋 전에 아래를 순서대로 실행한다. **하나라도 실패하면 커밋하지 않는다.**

```
node --test          (joseon-exorcist 폴더 안에서 실행)
```

설치할 것이 없다 (Node.js 18 이상만 있으면 된다). 이 한 줄이 아래를 모두 검사한다.
- `index.html` 안의 모든 `<script>` 가 문법 오류 없이 읽힌다
- 외부 파일·라이브러리를 불러오지 않는다 (`src=`, `href=` 로 바깥 주소 금지)
- 규칙 스크립트(`<script id="core">`)의 계산이 `specs/battle.md` 와 맞는다

**규칙과 화면을 나눈다.** 게임 규칙(이동·피해·AI·턴·승패)은 `<script id="core">` 안에만 쓴다.
이 부분은 화면(DOM)을 건드리지 않는 순수 계산이라 `tests/` 에서 Node 로 검사할 수 있다.
화면 스크립트는 core 를 불러 쓰기만 하고 규칙을 새로 계산하지 않는다.
랜덤(날씨)은 core 가 직접 `Math.random` 을 부르지 않고 바깥에서 받아 쓴다. 그래야 테스트가 결과를 고정할 수 있다.

**화면은 테스트로 확인되지 않는다.** 화면 작업을 끝냈으면 `PROGRESS.md` 의 "사람이 확인할 것 (화면)" 에
사람이 눌러 봐야 할 것을 한 줄씩 적는다.

- 아직 돌릴 수 없는 검사만 건너뛴다 (예: 테스트 파일이 하나도 없음). 무엇을 왜 건너뛰었는지 밝힌다.
  **실패한 검사를 "무관하다"며 건너뛰지 않는다.**
- 검사가 실패했는데 원인이 내 작업이 아니라면, 고치지 말고 `PROGRESS.md` 에 적고 커밋 없이 멈춘다.
- **테스트를 지우거나 건너뛰어서 통과시키지 않는다.** 그건 통과가 아니다.

## 4. 사람 승인이 필요한 동작

아래는 되돌릴 수 없다. **절대 스스로 실행하지 않는다.** 필요하면 멈추고 물어본다.

- 데이터베이스 마이그레이션 실행, 스키마 변경, 데이터 삭제
- 프로덕션 배포 (**`## 5-1. 배포 규칙`** 을 따른다 — 사용자가 요청할 때만), 환경변수와 시크릿 변경
- 사용자에게 나가는 메일·알림·메시지 발송
- 결제, 정산, 환불 관련 코드 실행
- 외부 API 에 쓰기 요청 (읽기는 괜찮다)
- `git push --force`, 브랜치 삭제, 히스토리 재작성
- **기획 수치 바꾸기.** `SPEC.md`, `specs/` 의 숫자(HP·공격·배율·턴 수 등)와 대사는 기획자가 정한다.
  밸런스가 이상해 보여도 고치지 말고 `PROGRESS.md` 에 적는다
- 이 폴더(`joseon-exorcist/`) 밖의 파일 수정

코드를 **작성**하는 것은 괜찮다. **실행**하는 것이 금지다.

## 5. 종료 프로토콜

검증을 통과하면 아래를 모두 완수하고 끝낸다.

1. `TASKS.md` 완료 항목 체크 (`- [x]`)
2. `PROGRESS.md` 갱신 — 완료한 것 / 다음 할 것 / 발견한 문제 / **확인 못 한 것**
3. 커밋. 포맷: `feat: [TASKS 항목명] - 구현 내용`

검증 실패나 승인 대기로 **끝내지 못하고 멈출 때**는 체크하지 않고 커밋하지 않는다.
대신 `PROGRESS.md` 에 남긴다 — 어떤 작업인지 / 무엇을 시도했나 / 어디서 막혔나(오류 원문) / 무엇이 되면 재개하나.

**커밋이 마지막 단계다. 종료 프로토콜에 배포는 없다.** 개발 → 검증 → 커밋 → 정지.
완료 보고에는 둘 중 하나를 반드시 적는다 ("완료"와 "배포 완료"를 섞어 쓰지 않는다):
- **미배포** — 구현·검증·커밋 완료. 아직 실제 게임 주소에는 배포하지 않았습니다.
- **배포 완료** — 구현·검증·커밋 후 실제 게임 주소에 배포했고 배포본을 확인했습니다.

## 5-1. 배포 규칙 (기획자 확정 2026-09-26 — Vercel 무료 하루 배포 100회 한도를 다 써서 생긴 규칙)

**배포는 개발의 자동 마지막 단계가 아니다. 기본값은 "배포하지 않음".**

1. **배포하는 경우는 둘뿐이다.**
   - 사용자가 명시적으로 요청했다 ("배포해", "올려", "실제 주소에 반영해" 등)
   - 사용자가 처음 작업 지시에 "완료 후 배포"를 적었다
   - 그 외에는 "로컬 작업과 검증까지 완료했습니다. 아직 배포하지 않았습니다." 라고 보고하고 멈춘다
2. **금지:** 버그·테스트·문구·디자인 수정마다 배포 / QA 중 확인용 배포 반복 / 같은 커밋 재배포 / 성공 확인을 위한 재배포 / 미리보기(Preview) 배포 습관적 생성
3. **버전 단위로 묶는다.** 한 버전 안의 여러 수정은 로컬에서 모두 검증한 뒤, 요청을 받으면 한 번만 배포한다 (예: v0.9.1 한 번)
4. **문서만 바뀐 작업은 배포하지 않는다** — `specs/`, `QA*.md`, 테스트·기획 문서, 개발 규칙. 게임 파일(`index.html`)이 바뀌지 않았으면 배포할 것이 없다
5. **배포 전 게이트** (하나라도 안 되면 먼저 해결하고, 실패한 상태로 배포하지 않는다)
   - [ ] 작업이 커밋·push 되어 있다
   - [ ] `git status` 에 의도하지 않은 변경이 없다
   - [ ] `node --test` 통과
   - [ ] 이번 작업에서 요구한 브라우저 QA 완료
   - [ ] 같은 커밋이 이미 배포된 상태가 아니다 (지난 배포 커밋은 `PROGRESS.md` "배포 기록")
6. **배포 순서:** 요청 → 현재 커밋 확인 → 테스트 재확인 → `git status` → Vercel 배포 **1회** → 실제 주소 확인 (받은 파일이 로컬 `index.html` 과 같은지) → `PROGRESS.md` "배포 기록"에 날짜·커밋 적기 → 보고
7. **배포가 막히면 (한도·인증·플랫폼 오류) 재시도 루프를 돌리지 않는다.** 원인을 한 번 확인하고 멈춘 뒤 보고한다 — 배포되지 않은 이유 / 현재 커밋 상태 / 기존 주소가 살아 있는지 / 다시 배포할 수 있는 조건. 사용자 승인 없이 다른 배포 방법·새 프로젝트로 우회하지 않는다
8. **주의 — push 도 배포 한도를 쓴다.** 이 프로젝트는 Vercel 이 저장소에 연결되어 있어, 작업 브랜치에 `git push` 할 때마다 미리보기 배포가 자동으로 하나씩 생기고 같은 하루 한도에 들어간다. push 는 작업 단위로 모아서 하고, 한 작업 중에 여러 번 나눠 push 하지 않는다

## 6. 언제 누구를 부르나

- 되돌리기 어려운 결정 → `deep-reasoner` 를 부른다. 결과는 `ADR.md` 에 기록한다
- 테스트·로그 확인 같은 잡무 → `runner` 를 부른다
- 작은 작업은 부르지 말고 직접 한다. 부를 때마다 비용이 든다

## 7. 피드백 승격

같은 실수나 지적이 **2회 이상** 반복되면 아래 [규칙 목록] 에 추가해 영구 방지한다.
규칙을 쓸 때는 항상 자문한다 — **이걸 어긴 걸 어떻게 알지?**
확인할 방법이 없는 규칙은 규칙이 아니라 소망이다. 검사 명령을 함께 만든다.
