## 추천 (Recommendation)

### 비슷한 프로젝트 추천 (상세페이지)

최근 본 프로젝트 A를 기준으로:
1. A와 태그가 겹치는 프로젝트 추출
2. 겹치는 태그 수가 많을수록 상위 정렬
3. 위 정렬 내에서 인기순(후원금 → 후원자) 정렬
4. 진행 중 프로젝트로 필터링
5. 총 60개 추출
6. 이미 후원한 프로젝트는 제외 후 제공(예: 10개 후원했으면 50개만 제공)

**폴백(비슷한 프로젝트 0개일 때)**: 동일 세부카테고리 → parent 동일 카테고리 → 다른 카테고리 순으로 정렬 → 진행 중 필터 → 60개 추출 → 후원한 프로젝트 제외.

### 같이 후원한 프로젝트 추천 (상세페이지)

기준 프로젝트 A(진행 중)에 대해:
1. A의 다른 후원자들(B)이 후원한 프로젝트 리스트(C) 생성, B 기준 C의 후원 횟수를 프로젝트 단위로 카운트(D) — 후원 취소 이력도 카운트에 포함
2. C는 진행 중 프로젝트만 대상
3. D 내림차순 정렬
4. D 동차 시: 좋아요 수 내림차순 → (후원수·좋아요 수도 동일하면) 달성률 내림차순 → 마감일 내림차순 → 후원금액 내림차순 → 목표금액 오름차순

**폴백**
- 추출 0개일 때: 진행 중 인기 프로젝트 60개 추출, 후원한 프로젝트 제외
- B가 적어 C가 적을 때(상세페이지 "같이 후원한 프로젝트" 영역 한정): 대중성 있는 카테고리 노출

### 추천 적용 영역

| 영역 | 개수 | 로직 |
|---|---|---|
| 후원완료 메일 | 4개 | 후원/후원취소 이력 프로젝트 제외 → 카테고리 우선순위(①동일 소카테고리 ②동일 대카테고리 ③무관) → 진행중+에디터추천 → 인기순 정렬 |
| 상세페이지 > 같이 후원한 프로젝트 | 4개 | 위 「같이 후원한 프로젝트 추천」 참조 |
| 후원취소 메일 | 4개 | 후원/후원취소 이력 프로젝트 제외 → 카테고리 무관, 진행중+에디터추천 → 인기순 정렬 |
| 결제성공 메일 | 4개 | 후원완료 메일과 동일(카테고리 우선순위 적용) |
| 후원변경 메일 | 4개 | 후원완료 메일과 동일(카테고리 우선순위 적용) |
| 후원완료(화면) | 6개 | 프로젝트 풀 30개 누적 추출 후 랜덤 제공. 로그인 시 후원/현재 프로젝트 제외, 진행중+에디터추천, 카테고리 우선순위 적용 |
| 좋아한 프로젝트(이력 없을 때) | 4개 | 카테고리 무관, 진행중+에디터추천, 인기순 정렬 |

### discovery 진행상태 버킷 매핑

둘러보기 소팅·필터는 프로젝트 상태(`ProjectState`, 전체 14종 — 03-project.md 참조)를 4개 버킷으로 재매핑해 사용한다.

| discovery 버킷 | `ProjectState` 코드값 |
|---|---|
| 진행중 | `ongoing_not_reached`, `ongoing_reached` |
| 공개예정 | `prelaunched` |
| 성사 | `succeeded_balanced`, `succeeded_not_balanced` |
| 무산 | `cancelled`, `failed` |

- 진행중·성사·무산 3버킷(6개 값)의 매핑은 노션 "진행상태의 매핑" 표와 be-api `ProjectState`의 `PUBLISHED_STATES` 상수가 정확히 일치한다.
- 공개예정(`prelaunched`) 버킷은 "인기순"·"카테고리-추천순" 등 정렬 로직의 진행상태 우선순위 기준에 명시적으로 등장하지만, 노션의 "진행상태의 매핑" 표(우선순위 숫자값 지정)에는 이 버킷에 대응하는 값이 빠져 있다. 코드에는 `prelaunched`가 정상적으로 별도 상태로 존재하므로 코드 쪽 문제는 아니며, 노션 문서의 숫자 매핑표 결측으로 판정한다.
