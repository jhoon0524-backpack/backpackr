# 텀블벅 서비스 개요 (Service Overview)

> **문서 성격**: 이 문서는 PRD·서비스라인 소스이며, `docs/grounding-doc-standard.md` §적용 대상에서 **명시적으로 제외**된 문서다(유형 A 도메인 정책 미러가 아님 — 노션 정책 페이지가 SSOT가 아니므로 노션→그라운딩 동기화 경로의 갱신 대상이 아니다). 도메인 정책 상세의 SSOT는 `01-user-auth.md` ~ `11-adcenter.md`이며, 이 문서는 그 인덱스·요약이다.
> **도메인 언어**: 한국어 서술은 "리워드" 대신 **"선물"**을 쓴다(코드 엔티티 `Reward`, 파일명 `04-reward.md` 등은 원문 유지).

---

## 서비스 한 줄 정의

텀블벅은 창작자가 프로젝트를 올리고 후원자가 후원하는 크라우드펀딩 플랫폼이다(운영사: 백패커). 창작자-후원자 양면시장 구조이며, 목표금액·마감·선물 이행 지연·프로젝트 성공/실패 상태머신이라는 크라우드펀딩 고유 특성을 가진다.

---

## 두 결제 모델

텀블벅은 결제 모델이 다른 두 프로젝트 계열이 공존한다(`ProjectType` 기준, 상세는 `03-project.md` 참조).

| 구분 | 기간 펀딩 (예약결제) | 상시 프로젝트 (즉시결제) |
|---|---|---|
| 결제 시점 | 마감 후 일괄 청구 | 후원 즉시 청구 |
| 핵심 불변식 | **All-or-Nothing** — 목표 미달 시 전액 미청구 | 다회 구매 가능 |

프로젝트 타입 세부·청구 배치 절차·상태 전이·허용 결제수단은 `05-funding-payment.md`, 취소·환불 계통은 `08-cancel-refund.md`, 정산 파이프라인은 `06-settlement.md` 참조.

## 핵심 액터와 여정

### 후원자 여정

1. **탐색/발견** — 검색·추천·홈 큐레이션·둘러보기 → `09-discovery.md`
2. **회원가입/인증** — 연락처 점유인증, 프로필·계정 정보 입력 → `01-user-auth.md`
3. **프로젝트 상세 조회 및 선물 선택** — 옵션·한정수량·디지털선물 → `04-reward.md`, `03-project.md`
4. **후원/결제** — 기간 펀딩(예약결제) 또는 상시 프로젝트(즉시결제) → `05-funding-payment.md`
5. **진행 중 소통** — 업데이트 글 확인, 커뮤니티 응원글·댓글, 알림 수신 → `10-community-notification.md`
6. **마감 결과 대응** — 성공 시 청구·정산 대기, 실패 시 미청구(All-or-Nothing) → `05-funding-payment.md`, `06-settlement.md`
7. **취소/환불 요청**(필요 시) → `08-cancel-refund.md`
8. **선물 수령 확인 → 후기 작성** — "받았다" 확인 후 후기 작성 화면 진입, 창작자/후원자 Pick 후기 → `07-fulfillment-review.md`

### 창작자 여정

1. **프로젝트 기획·등록** — 창작자 에디터, 책임심사 사전확인서(대상자만) → `03-project.md`
2. **선물 구성** — 옵션·한정수량 설정, 디지털선물 등록(요금제 제약) → `04-reward.md`
3. **심사 요청 → 승인 → (선택) 공개예정** — 공개예정은 RUN·BOOST 요금제만 사용 가능 → `03-project.md`
4. **펀딩 진행 중 관리** — 대시보드, 후원자 관리, 상태별 에디터 수정·관리 메뉴 접근 권한 → `02-creator.md`, `10-community-notification.md`
5. **마감 → 성공/실패 판정**(All-or-Nothing) → `03-project.md`, `05-funding-payment.md`
6. **성공 시 정산** — 수수료 요금제(START/RUN/BOOST), MOU 예외 요율, 조건부 분할 정산 → `06-settlement.md`
7. **선물 이행** — 발송·전달 처리, 디지털선물 전달 관리 → `04-reward.md`, `07-fulfillment-review.md`
8. **활동 성과 지표** — 창작자 칭호, 좋은창작자 뱃지, 창작생태계 기여도 → `02-creator.md`
9. **(선택) 광고 집행** — 비즈머니 충전·환불, SNS 셀프 광고(현재 메뉴 제거로 이용불가) → `11-adcenter.md`

## 도메인 지도

`docs/domain-overview/01-user-auth.md` ~ `11-adcenter.md` 11개 파일의 한 줄 요약과 담당 영역 경계다. 상세 정책은 각 파일이 SSOT이며, 여기서는 중복 서술하지 않는다.

| 파일 | 한 줄 요약 | 담당 영역 경계 |
|---|---|---|
| `01-user-auth.md` | 앱 토큰(액세스/리프레시), 연락처 점유인증, 프로필·계정·결제수단 및 배송지 입력 조건 | 필드 **입력 정책** SSOT. 프로필 필드의 **노출·활용**은 `02-creator.md` 소관 |
| `02-creator.md` | 창작자 칭호(2그룹 5종)·좋은창작자 뱃지·창작생태계 기여도·프로젝트 상태별 에디터 수정/관리 메뉴 접근 권한 | 상태별 권한 값만 다룸. **프로젝트 상태 축 자체의 정의**는 `03-project.md` 소관 |
| `03-project.md` | 프로젝트 상태(14종)·상태 전이(All-or-Nothing 판정)·프로젝트 타입(기간펀딩 4종/상시)·공개예정·책임심사 사전확인서·오픈런·빈자리알림·팬콜·업데이트Bar·카드 뱃지·예상 발송 시작일(추천 선물 단방향 연동) | 프로젝트 생애주기·상태머신 SSOT |
| `04-reward.md` | 선물·옵션 모델(`Reward`/`Item`/`AddInfo`), 한정수량 차감·복구 동시성(Redis+DB 이중검증), 디지털 에셋/디지털선물 | 선물·옵션 도메인 SSOT. 에디터 공통 필드(제목·목표금액 등)는 `03-project.md` 소관 |
| `05-funding-payment.md` | 결제수단(`PaymentType`)·예약결제(빌링) 상태머신(`ProjectWarrantyState` 12종)·All-or-Nothing 청구 배치·결제 수수료 | 결제·청구 SSOT. **취소·환불**은 `08-cancel-refund.md` 소관 |
| `06-settlement.md` | 수수료 요금제(START/RUN/BOOST)·펀딩/상시 두 정산 파이프라인 계산식·정산 상태머신·분할 정산(Two-Phase)·세금계산서 | 정산 SSOT(펀딩 배치 자동 실행 vs 상시 어드민 확정 게이트로 실행 방식 상이) |
| `07-fulfillment-review.md` | 후기 작성 가능 조건(결제성공+선물전달), PDP 후기 영역, 창작자/후원자 Pick 후기, 후원자명단(배송정보) 다운로드 | 선물 **이행 프로세스 자체**(발송·지연 대응)는 노션 SSOT 공백 — 후기 작성 조건에 걸치는 범위만 다룸 |
| `08-cancel-refund.md` | 취소(`CANCEL`, 자동승인)·환불(`REFUND`, 창작자 승인) 구분, 모델별 3계통(기간펀딩/프리오더/상시), 부분취소는 선물 단위 전량만 가능 | 전용 노션 페이지 없음 — 코드 확정 기반이 사실상 1차 소스 |
| `09-discovery.md` | 검색(3개 영역, 4비트 유니코드 제외)·추천 로직(비슷한 프로젝트/같이 후원한 프로젝트)·홈 히어로/큐레이션/콜렉션·둘러보기 필터·소팅(7종) | 탐색·추천 SSOT. 관리 어드민 도메인은 **`oneteam.tumblbug.com`**(PO 확인 2026-07-10) |
| `10-community-notification.md` | UGC(업데이트/커뮤니티/후기/메시지) 작성·조회·수정·삭제 권한, UGC 신고·자동 블라인드(코드 실질 6건째), 메시지 차단, 알림 발송 매체·우선순위·야간 지연 정책 | 후기 **노출·Pick** 정책은 `07-fulfillment-review.md` 소관. 이 문서는 후기 "작성 제한 조건"만 다룸 |
| `11-adcenter.md` | 광고센터 진입 게이트(3조건 AND)·비즈머니(충전/환불/환급)·SNS 셀프 광고(캠페인·소재·심사·정산) | ⚠️ **SNS 셀프 광고는 현재 메뉴 제거로 이용불가**(PO 확인 2026-07-10, 재오픈 미정). 요금제별 **SNS 광고 수수료율**은 `06-settlement.md`의 **정산 수수료율**과 저장 위치·용도가 다른 별개 축(요금제명은 같으나 수치 다름 — 혼동 주의) |

## 서비스 구성

상세는 `docs/projects.md`(텀블벅 repo 정의, GitHub `tumblbug` org)가 SSOT다. 여기서는 요약만 제공한다.

### 클라이언트

| 구분 | 플랫폼 | repo | 설명 |
|---|---|---|---|
| 서비스 클라이언트 (3종) | Android | `android` (tumblbug-aos) | 안드로이드 앱 (후원자·창작자 공용) |
| | iOS | `ios` (tumblbug-ios) | iOS 앱 (후원자·창작자 공용) |
| | Web | `fe` (tbb-frontend) | 프론트엔드 웹 |
| 어드민 | Web | `fe-admin` (tbb-fe-admin) | 어드민 프론트엔드 |

### 백엔드 — be-api (tumblbug-api-v2, Gradle 멀티모듈)

| 모듈 | 역할 |
|---|---|
| `api` | 후원자/창작자향 API 엔드포인트 |
| `admin` | 어드민/운영 API |
| `batch` | 배치(정산·상태 전이·집계 등) |
| `core` | 도메인 모델·비즈니스 로직 공통 |
| `gateway` | 게이트웨이/라우팅 |

> 정확한 모듈 경계·의존은 코드 대조 시 `sources/be-api`에서 확정한다(`docs/projects.md` 참조). `be-api-legacy`는 분석·심링크 대상에서 제외.

## 정책 참조 경로

도메인 정책 확인은 **3계층 폴스루**로 이뤄진다(위에서부터 순서대로 확인하며, 상위에서 못 찾으면 자동으로 하위 계층까지 내려가 식별한다 — `persona/po.md` 참조).

1. **1차 — 로컬 그라운딩**: `docs/domain-overview/01-user-auth.md` ~ `11-adcenter.md`(도메인 정책 미러, 유형 A) + `domain-glossary.md`(용어집, 유형 B) + `notion-index.md`(노션 페이지 트리 미러)
2. **2차 — 노션 정책 SSOT**: "🔑 텀블벅 서비스 정책" (`f851d23d81b1410081c20d0454efb831`)
3. **3차 — repo 코드**: `docs/code-map.md`를 입구로 `sources/be-api` 등 확인

그라운딩과 노션·코드 사이에 불일치가 발견되면 **코드 실동작을 SSOT**로 판정한다(각 도메인 파일의 "노션 ↔ 코드 불일치" 섹션 참조). 3계층으로도 닫히지 않는 사안은 `[확인 필요]`로 남기되, 사용자에게 그대로 되묻지 않고 `domain-analyst-agent` 위임까지 완료한 뒤 남은 순수 비즈니스/외부 결정만 명시한다.
