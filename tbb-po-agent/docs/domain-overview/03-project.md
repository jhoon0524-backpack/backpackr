## 프로젝트 상태 (State)

프로젝트 생애주기 상태는 전체 14종이다. 표는 코드 Enum 값과 한글 라벨을 그대로 반영한다(축약 없음).

| # | Enum | 코드값 | 한글 라벨 | 구분 |
|---|---|---|---|---|
| 1 | `DRAFT` | `draft` | 작성 중 | 심사 전 |
| 2 | `SUBMITTED` | `submitted` | 승인요청 됨 | 심사 |
| 3 | `VERIFIED` | `verified` | 승인 됨 | 심사 통과 |
| 4 | `REJECTED` | `rejected` | 보완 요청 됨 | 심사(재요청 가능) |
| 5 | `FINAL_REJECTED` | `final_rejected` | 반려 됨 | 심사 최종 반려 |
| 6 | `CANCELLED` | `cancelled` | 취소 됨 | 종료(중단) |
| 7 | `FAILED` | `failed` | 실패 | 종료(무산) |
| 8 | `ONGOING_NOT_REACHED` | `ongoing_not_reached` | 진행 중 | 진행(목표 미도달) |
| 9 | `ONGOING_REACHED` | `ongoing_reached` | 진행 중/목표금액 도달 | 진행(목표 도달) |
| 10 | `SUCCEEDED_NOT_BALANCED` | `succeeded_not_balanced` | 성공 | 종료(정산 전) |
| 11 | `SUCCEEDED_BALANCED` | `succeeded_balanced` | 성공/정산완료 | 종료(정산 후) |
| 12 | `PRELAUNCHED` | `prelaunched` | 공개예정 중 | 공개예정 |
| 13 | `PAUSED` | `paused` | 일시 중지 | 상시 프로젝트 전용 |
| 14 | `ENDED` | `ended` | 판매 종료 | 상시 프로젝트 전용 |

> 노션 생애주기 문서는 draft·verified·rejected·prelaunch(선택)·ongoing(reached/not_reached)·succeeded(balanced/not_balanced)·failed 등 흐름 중심 9종으로 기재한다(코드 기준 14종 — SUBMITTED·FINAL_REJECTED·CANCELLED·PAUSED·ENDED가 추가로 존재). PAUSED·ENDED는 상시 프로젝트(STORE 타입) 전용 상태로, 기간 펀딩 흐름에는 등장하지 않는다.

**주요 상태 그룹(도메인 구분)**
- **PUBLISHED**(공개 노출): 진행 중/목표도달·목표미달, 성공(정산전/후), 실패, 취소
- **STARTABLE**(펀딩 시작 가능): 승인 됨, 공개예정 중
- **SUCCEEDED**(성공): 성공(정산전), 성공(정산후)
- **ONGOING**(진행 중): 목표미달, 목표도달
- **ENDED**(종료): 성공(정산전/후), 실패, 취소, 일시중지, 판매종료
- **STORE_ALL**(상시 프로젝트가 갖는 상태 집합): 작성 중, 진행 중/목표도달, 일시 중지, 판매 종료 — 상시 프로젝트는 심사 대기·보완요청 등 기간 펀딩 전용 심사 상태를 거치지 않는다.

## 프로젝트 상태 전이 (State Machine)

상태 전이는 이벤트 단위로 발생하며, 전이 이력은 별도 로그 테이블에 `(이벤트, from, to)`로 기록된다(정적 상태머신 정의가 아니라 전이 이력 로그).

**확정된 전이**

| From | 이벤트 | To | 설명 |
|---|---|---|---|
| 작성 중 / 공개예정 중 / 승인 됨 | `start` | 진행 중(목표 미도달) | 펀딩 시작. 시작 가능 상태는 승인 됨·공개예정 중(STARTABLE)뿐 |
| 승인 됨 | (공개예정 예약) | 공개예정 중 | 공개예정 전환. PRO·PREMIUM 요금제에서만 가능(아래 「공개예정」 참조) |
| 진행 중(목표 미도달) | `go_over_goal` | 진행 중/목표금액 도달 | 모금액이 목표액 이상으로 도달 시 실시간 승격 |
| 진행 중/목표금액 도달 | `fall_under_goal` | 진행 중(목표 미도달) | 후원 취소 등으로 모금액이 목표액 미만으로 감소 시 실시간 강등 |
| 진행 중/목표금액 도달 | `end_with_success` | 성공(정산 전) | 마감 배치 처리 — 목표 도달 상태로 마감 |
| 진행 중(목표 미도달) | `end_with_failure` | 실패 | 마감 배치 처리 — 목표 미도달 상태로 마감 |
| 성공(정산 전) | `complete_balance` | 성공/정산완료 | 창작자 정산 완료 |
| 작성 중 | `open_store` | 진행 중/목표금액 도달 | 상시 프로젝트 오픈. 별도 심사 대기 없이 곧바로 진행 중/목표도달 상태로 시작 |
| 진행 중/목표금액 도달(상시) | `pause_store` | 일시 중지 | 상시 프로젝트 판매 일시중지 |

다음 이벤트는 코드값(전이 이벤트 Enum, 전체 14종)은 확정되어 있으나, 세부 트리거 조건은 이번 분석 범위에서 서비스 로직까지 추적하지 않았다: `user_submit`(작성 중/보완요청 됨 → 승인요청 됨), `admin_verify`(승인요청 됨 → 승인 됨), `admin_reject`(승인요청 됨/보완요청 됨 → 보완요청 됨), `forcely_rejected`(→ 반려 됨), `end_with_cancel`(→ 취소 됨), `revert_balance`(성공/정산완료 → 성공/정산전).

**핵심 불변식**: 마감 시 목표 도달 상태(진행 중/목표금액 도달)만 성공(정산 전)으로, 목표 미도달 상태는 실패로 전이한다 — **All-or-Nothing**. 진행 중에는 모금액↔목표액 교차에 따라 도달/미도달 상태가 실시간으로 양방향 전이한다(마감 배치를 기다리지 않음).

> 프로젝트 기간(최소 7일·평균 30일·최대 60일), 취소 가능 시점(기간 중만), 마감 후 재결제(7일, 미납 시 결제실패·부담은 창작자, 결제실패율 평균 2%) 등 예약결제 관련 세부 정책은 `05-funding-payment.md` 소관이다.

## 프로젝트 타입 구분

| 타입 | 의미 | 결제 모델 |
|---|---|---|
| `FUNDING` | 펀딩(기간 펀딩) | 예약결제(All-or-Nothing) |
| `PREORDER` | 프리오더 | 예약결제 계열 |
| `PREORDER_FANCALL` | 프리오더 팬콜 | 예약결제 계열(재오픈) |
| `PREORDER_GLOBAL` | 프리오더 글로벌 | 예약결제 계열(글로벌) |
| `STORE` | 상시 후원 프로젝트 | 즉시결제, 다회 구매 |

**기간 펀딩 vs 상시 프로젝트 구분 필드 = 프로젝트 타입(`ProjectType`) + 상태(`state`).**
- 상시(STORE)는 상태가 작성 중·진행 중/목표도달·일시중지·판매종료만 사용하며, 오픈 시 곧바로 진행 중/목표도달 상태로 시작한다(승인요청·승인 등 기간 펀딩 심사 흐름을 거치지 않음).
- 예상 청구일: 상시(STORE) 타입은 청구예정 개념이 없음(즉시결제이므로 `null`). 그 외 타입은 마감일 + 1일이 예상 청구일이다.
- 타입 그룹: `PREORDER_TYPE_LIST`(프리오더·프리오더팬콜·프리오더글로벌), `TYPES_WITHOUT_STORE`(펀딩·프리오더·프리오더팬콜·프리오더글로벌 — 상시 제외 4종).

## 공개예정 (Prelaunch)

- **사용 조건**: 상태가 「승인 됨」**AND** 요금제가 PRO 또는 PREMIUM일 때만 사용 가능하다. BASIC·DEFAULT 요금제는 공개예정을 사용할 수 없다.
  - 요금제(`RatePlanType`) 전체 4종: BASIC(수수료 5%) · PRO(9%) · PREMIUM(15%) · DEFAULT(5%). 수수료 요금제 상세는 `06-settlement.md` 참조.
- **공개예정 기간**: 최대 15일. 종료일 = 펀딩 시작일(오픈 시점). 15일 미만이면 프로젝트 오픈 시점에 공개예정이 종료된다.
- **노출**: 홈·둘러보기에 노출. 노출 종료(오픈) 후에도 검색·링크로는 계속 접근 가능하다. 노출 판정은 「공개 상태」 AND 「공개예정 이후 상태」의 조합이다.
- **알림 신청**: 알림 신청 프로젝트는 오픈 후 좋아요로 전환된다.
- **펀딩 시작일 표기**: 공개예정 기간 중에는 변경 가능하나, 15일 노출 종료 후에는 변경 불가.
- **알림 발송 시점**: 푸시 = 오픈 시점 / 알림톡 = 오픈 2시간 전 + 오픈 시점.
- 공개예정 전환 시 상태는 「공개예정 중」으로 바뀌며 전환 시각이 기록된다. 예약형(사전 예약 설정)은 예약 시각만 먼저 저장하고 배치가 실제 전환을 수행한다.

## 책임심사 사전확인서 (Responsibility Review)

프로젝트별이 아니라 **창작자 단위** 제도로, 대상 창작자의 funding 타입 프로젝트에 한해 적용된다.

| 상태 | 의미 |
|---|---|
| `NOT_REQUIRED` | 책임심사 확인서 제출 불필요 |
| `REQUIRED` | 책임심사 확인서 제출 필요 |
| `SUBMITTED` | 책임심사 확인서 제출함 |

- **대상 판정**: 프로젝트 타입이 펀딩(FUNDING)이고, 창작자가 책임심사 대상 명단에 활성(Is Active=true) 상태로 등록돼 있을 때 대상이 된다.
- **상태 계산**: 대상이 아니면 `NOT_REQUIRED` / 대상이며 제출 완료면 `SUBMITTED` / 대상이며 미제출이면 `REQUIRED`.
- 최초 심사요청 시 확인서가 노출·제출되며, 보완요청으로 재요청하는 경우에는 다시 노출되지 않는다.
- 창작자가 대상 명단에서 비활성(Is Active=false) 전환되면 기존 제출분은 삭제된다.
- 책임심사 통과 시 영업일 1일 이내 빠른 심사 승인이 적용된다.

## 오픈런 신청 (공개예정 프로젝트 선예약)

> 코드 매핑: 노션 "오픈런"은 코드상 **선예약(PreBacking)** 도메인이며, 신청 단위 엔티티는 **PreProjectWarranty** 계열이다. 결과 알림 타입도 "오픈런 결과 푸시"로 한글 대응된다. 앱 전용 기능이다.

공개예정 중인 프로젝트의 선물을 시작 전 1개 선예약(신청)하는 기능.

**신청 단위 상태 (전체 5종)**

| 상태 | 의미 |
|---|---|
| `APPLIED` | 신청(결과 확정 전 대기) |
| `INVALID` | 무효 처리 |
| `SUCCEEDED` | 성공(자동 후원 전환) |
| `CANCELLED` | 취소 |
| `FAILED` | 실패 |

> 노션(오픈런 신청 페이지)은 성공·실패·취소 3종으로 서술한다(코드 기준 5종 — 결과 확정 전 대기 상태인 `APPLIED`, 무효 처리인 `INVALID`가 추가로 존재한다). 그라운딩은 코드 기준 5종을 SSOT로 기재한다.

**프로젝트 단위 상태 (전체 2종)**: `APPLIED`(해당 프로젝트에 오픈런 신청이 있음) / `NOT_APPLIED`(미해당).

- **중복 방지**: 기존 신청이 취소 상태가 아니면 동일 프로젝트에 재신청할 수 없다.
- **취소 조건**: 프로젝트가 「공개예정 중」 상태일 때만 취소 가능하다 — 즉 프로젝트 시작(결과 발표) 전까지만 취소할 수 있다.
- **결과 확정**: 프로젝트 시작일에 결과가 확정된다. 신청 수가 한정 수량 미만이면 전원 성공, 초과하면 랜덤 추첨으로 성공자를 정한다. 성공 시 자동 후원으로 전환되며 응원권이 자동 적용된다. 프로젝트가 중단되면 신청자 전원이 실패 처리된다.
- 신청자가 있는 선물은 창작자가 수정·삭제하는 데 제한이 걸린다.
- 오픈런 결과 확정 배치의 구체 트리거 조건과 응원권 자동적용·자동후원 로직의 세부 구현은 이번 분석 범위에서 서비스 로직까지 추적하지 않았다.

## 빈자리 알림

> 코드 매핑: 노션 "빈자리 알림"은 코드상 **Reward Slot Availability**(선물 재고 자리) 도메인이다. 앱 전용 기능이다.

진행 중인 프로젝트에서 수량 제한이 있는 선물이 품절된 경우, 재입고 알림을 신청할 수 있는 기능.

- **발송 조건**: 품절 상태였던 선물의 재고가 다시 1개 이상으로 회복되면(다른 후원자의 후원 취소·수량 감소, 또는 창작자의 제한수량 증가) 신청자 전원에게 앱 푸시가 동시에 발송된다. 기본 선물(옵션이 없는 대표 선물)은 알림 대상에서 제외된다.
- 신청한 선물을 실제로 후원하면 해당 알림 신청은 자동 해제된다.

## 예상 발송 시작일 (프로젝트 ↔ 추천 선물 연동)

> 노션 근거 — 선물/아이템 변경 지원 정책: https://app.notion.com/p/25d1f5a7134480fd9774dda6e3fe4ffd (연동 방향 명문화 2026-07-15 반영 — 코드 확정 기반) / 구현 tech doc — 에디터-추천 선물, 예상 발송 시작일: https://app.notion.com/p/3441f5a71344815caac7de06a88353ed
> 코드 확인 2026-07-15 (경로는 `docs/code-map.md` §03 참조)

- **필드**: 프로젝트 단위 `projects.expected_delivery_date`("예상 발송 시작일") — 창작자 에디터 "목표 금액 및 일정" 탭의 datepicker 입력값. 결제 종료일(paymentDeadline)+1일 이후 ~ +4년 이내. 과거 null 허용이었으나 현재는 필수.
- **추천 선물**: 코드명 `Reward.recommended`(Boolean). REGULAR 선물 중 **프로젝트당 1개만** 설정 가능(초과 시 `EXCEED_RECOMMENDED_REWARD_COUNT`).
- **연동 방향(단방향, 코드가 SSOT)**: **프로젝트 예상 발송 시작일(master) → 추천 선물의 예상 발송일(slave)**. 프로젝트 저장 시 추천 선물에 복사되고, 선물을 추천으로 지정하는 순간에도 프로젝트 값으로 덮어써진다. 추천 선물의 발송일 입력은 에디터에서 잠김(disabled). **역방향(추천 선물 → 프로젝트) 경로는 코드 부재 확정.**
  - ⚠️ 흔한 오인: fe 툴팁이 "추천 선물을 기준으로 첫 발송을 시작한 날"이라고 **의미**를 정의해 "프로젝트가 추천 선물을 따라간다"로 기억되기 쉬우나, **데이터 흐름은 반대**다. 명문화 위치: 에디터 추천 선물 설정 문구("추천 선물의 선물 예상 발송 시작일은 프로젝트 예상 발송 시작일과 동일하게 적용되어 변경할 수 없습니다") + 노션 "선물/아이템 변경 지원 정책" 추천 선물 변경 행 참고사항(방향 명시 — 2026-07-15 코드 확정 기반으로 프로덕트가 추가).
- **수정 가능 조건**: 어드민은 항상 / 창작자는 펀딩 시작 전(공개예정 포함)까지, 진행 중에는 값이 비어 있을 때 1회만(기능 배포 이전 프로젝트 구제용).
- **마감일 변경 시**: 전체 REGULAR 선물의 예상 발송일이 마감일 이동폭만큼 일괄 shift되지만 **프로젝트 예상 발송 시작일은 shift되지 않는다**(잠재 desync — 엔지니어링 확인 대상).
- **심사요청 게이트**: "선물 예상 발송일 + 추천 선물 설정 완료" 조건은 **fe 에디터 완성도 체크 단독 강제**이며 서버(be-api 심사요청 `requestSubmit` 검증)에는 해당 검증이 **없다**(부재 확정 — API 직접 호출 우회 가능).

## 업데이트Bar

프로젝트 상세에 노출되는 진행 상황 표시줄.

- **진행바**: 최근 등록된 업데이트 글의 상태 + 선물 전달 지연 태그를 표시한다. 최근 글이 "수정" 글이면 연동에서 제외된다. 글이 삭제되면 삭제된 글은 제외하고 가장 최근 등록 글의 상태로 노출된다.
- **선물 전달 지연 태그**: 선물 예상 발송일 기준으로 자동 지연 처리된다.
- **노출 범위**: [후원자만 공개] 체크 시 후원자에게만 노출된다(프리오더의 환불요청 유저도 후원자로 구분). 미체크 시 전체 공개.
- **상단 고정**: 자동 고정(최근 진행상황 글 등록 시 이전 고정 글은 해제됨)과 수동 고정(진행상황·펀딩안내 글) 두 방식이 있다.
- **심사요청 신규 조건**: 선물 예상 발송일 + 추천 선물 설정을 완료해야 심사요청이 가능하다. (fe 에디터 완성도 체크 단독 강제, 서버 검증 부재 — 코드 확인 2026-07-15, 위 「예상 발송 시작일」 참조)
- 펀딩 종료 4상태: 성공(정산 전) · 성공(정산 후) · 실패 · 취소 — 위 「프로젝트 상태」 14종 중 종료 그룹과 정합한다.

## 프로젝트 카드 뱃지

프로젝트 카드(홈·PLP 등 리스트 노출)에 붙는 뱃지 정책.

- **노출 개수**: 최대 2개.
- **노출 우선순위**: 마감 > 좋은창작자 > 오늘 마감 > 남은 기간 > 후원금액 > 에디터픽.
- **PLP 노출 우선순위**: 스타창작자 > 에디터픽. bar 영역에 후원금액·마감시간이 이미 노출 중이면 후원금액 뱃지·마감임박 뱃지는 제외된다.
- 뱃지 속성은 노션 인라인 데이터베이스(`프로젝트카드뱃지`)에서 관리되며, 속성은 뱃지명·노출 기준·노출 영역(홈/PLP)으로 구성된다. 개별 뱃지 행(뱃지명별 상세 노출 기준)은 이번 분석 범위에서 전체 목록을 확보하지 않았다.

## 팬콜 프로젝트 (Fancall)

후원자 요청으로 종료된 프로젝트를 재오픈한 프로젝트. 코드 타입은 `PREORDER_FANCALL`. 원본이 되는 최초 프로젝트를 "오리지널"이라 부른다.

- **팬콜 투표 가능 조건**(매일 배치로 전날 상태 기준 판정): 오리지널 프로젝트가 성공/정산완료 상태 + 선물 전달 완료 + 팬콜 프로젝트 미오픈 + 성과 기준(후원자 100명 이상 또는 후원액 500만 원 이상, 후원 상태는 결제완료·환불거부 기준, 펀딩종료일 2023-01-01 이후) 충족.
- 투표는 기본값 off이며 창작자가 수동으로 켠다. 팬콜이 오픈되면 투표는 자동으로 off 전환된다.
- 투표 요청은 로그인 유저가 프로젝트당 1회만 가능하며, 요청 수는 누적 집계된다.
- 팬콜 횟수는 프로덕트 관점에서 프로젝트 1개당 1회이나, 운영 관점에서는 횟수 제한이 없다.
- **팬콜 오픈 조건 확정** — 1차 도입 이후 결과를 분석해 최종 결정할 예정이며 아직 확정되지 않았다. 검토 중인 1차 안은 오리지널 후원자 수 대비 요청 수 100% 이상, 후기 5개 이상 중 "다시 후원할래요" 응답 90% 이상이다. `[확인 필요]`
- **팬콜 2단계([팬콜 오픈] 기능) 수수료 정책** — 논의 필요 상태로 미확정이다(타사 유사 사례로 10%+VAT 참고 중). `[확인 필요]`
- **팬콜 투표 성과 기준**(후원자 100명 이상 또는 후원액 500만 원 이상)은 배치 서비스 내 코드 상수로 확정되어 있다(운영 파라미터·외부 설정이 아님).
