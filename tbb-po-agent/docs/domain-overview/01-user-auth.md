## 연락처 점유인증

**재인증을 통한 번호 변경 가능 주기**: 월 1회 — **캘린더월 기준 리셋**(변경일 기준 30일이 아니라 다음 달 1일부터 재변경 가능. 예: 05.25 변경 시 06.01부터 재변경 가능).

**점유인증 적용 지점 (4곳)**
1. 이메일 회원가입
2. 네이버/카카오 회원가입 (연락처 제공 동의 시)
3. 설정 > 연락처 변경
4. 후원 결제 상세 > 연락처

**연락처 인증 상태 2종**

| 상태 | 의미 |
|---|---|
| 점유인증 (점유인증됨) | 해당 연락처의 소유를 배타적으로 증명한 상태 |
| 일반 인증 | 점유인증이 아닌 일반 상태의 연락처 인증. 점유인증 발생 시 자동 해제 대상 |

**점유인증 케이스 2종**
1. **이미 점유인증되어 있는 연락처로 인증 시도** → 회원가입 불가 + 해당 번호로 등록 불가 + 해당 번호로 변경 불가 (전면 차단)
2. **다른 계정에 등록은 되어 있으나 점유인증은 안 된 연락처** → 회원가입은 불가하나 해당 계정으로 점유인증은 가능. 점유인증 시 **다른 계정의 일반 인증은 모두 해제**됨

## 설정 > 회원 정보 입력 및 첨부 조건

노션 원문 기준, 유형별 3개 인라인 DB(프로필/계정/결제수단 및 배송지)의 전체 조건.

> **경계**: 아이디어스 주소(idusUrl) 등 프로필 필드의 **입력 정책(글자수·형식 제약)** SSOT는 본 문서다. 창작자 프로필에서의 **노출·활용** 관점은 `02-creator.md` 소관.

|---|---|---|
| 프로필 사진 | 용량 10Mb 이하, jpg/gif/png | |
| 이름 | 2자 이상 20자 이하, 4바이트 유니코드 입력 불가 | 최소 글자수는 「노션 ↔ 코드 불일치」 1번 참조 |
| 소개 | 4바이트 유니코드 입력 불가 (노션 원문 자체가 "확인 필요"로 표기) | 「노션 ↔ 코드 불일치」 2번 참조 |

## 노션 ↔ 코드 불일치

`설정 > 회원 정보 입력 및 첨부 조건` 페이지와 `프로필 정보 입력 조건` 페이지가 이름·소개·웹사이트·아이디어스 주소 항목에서 서로 다른 값을 제시해, 프로필 수정 API의 실제 검증 DTO를 코드로 확정했다. 아래는 코드 실동작을 기준으로 판정한다.

1. **이름 최소 글자수** — 노션 문서는 두 페이지(설정 DB·프로필 정보 입력 조건) 모두 "2자 이상"으로 기재(코드 기준 `@UserFullname` 자체 애노테이션에 min=1이 내장되어 **1자부터 허용**). 코드가 SSOT이므로 노션 두 페이지 모두 오기 가능성 — 노션 갱신 권고.
2. **소개(자기소개) 문자 제한** — 설정 DB는 "4바이트 유니코드 입력 불가(확인 필요)"로 기재(코드 기준 `shortDescription`에 문자 제한 애노테이션 **없음**, 2,500자 이하만 적용). 프로필 정보 입력 조건 페이지("2500자 이하, 모든 문자 허용")가 코드와 일치 = 정답. 설정 DB 행은 낡은 오기로 판단.
3. **웹사이트 형식** — 설정 DB는 "프로토콜 외 100자 이하, @포함 이메일 형식이어야 함"으로 기재(코드 기준 255자 이하 + 일반 URL 정규식, **이메일 형식 아님**). 프로필 정보 입력 조건 페이지("유효한 웹사이트 주소")가 코드와 부합. 설정 DB 행은 다른 필드(이메일 검증 규칙)가 잘못 복사된 것으로 추정.
4. **아이디어스 주소 슬래시 뒤 글자 수** — 설정 DB는 "`/` 다음 1글자 이상 입력 필요"로 기재(코드 기준 정규식상 `/` 뒤 **0글자도 허용**). 실질 영향은 작으나 빈 경로 등록 사례 발생 가능 — 노션 문구 정정 권고.
5. **이름 허용 특수문자 중 쌍따옴표(`"`) 포함 여부** — 프로필 정보 입력 조건 페이지 원문 표기상 쌍따옴표가 포함된 것으로 읽힌다(코드 기준 정규식·에러 메시지 모두 쌍따옴표 **미포함**, 대신 작은따옴표·백틱·리터럴 백슬래시 포함). 노션 원문이 코드 에러 메시지를 복사하며 이스케이프 표기 실수를 냈을 가능성이 있으나 확신도가 낮아 표기로만 남긴다.
6. **스테디오 주소 존치 여부** — 프로필 정보 입력 조건 페이지는 취소선 처리로 정책 폐기를 표시(코드 기준 필드·검증·정규화 로직 **모두 현존**, 길이 제한(`@Size`)조차 없어 사실상 무제한). **해소(PO 확인 2026-07-10)**: 스테디오 서비스 종료로 미사용 확정 — 정책 폐기가 맞고, 코드 잔존은 미정리 상태(정리 시점은 엔지니어링 백로그).

## 커버리지 공백

노션 트리의 **'회원 (후원자/창작자)' 섹션은 헤더만 있고 하위 페이지가 없다.** 이번에 참조한 4개 페이지(+하위) 어디에도 다음이 커버되지 않는다 — 노션 SSOT에 미기재, 필요 시 코드/담당자 확인:

- 회원가입 방식(이메일/네이버/카카오 등 채널별 절차·화면)
- 로그인 방식·세션 정책
- 후원자↔창작자 계정 전환/겸용 규칙
- 소셜 계정 연동·해제 정책
- 탈퇴·휴면 정책
- 앱 토큰 "상세 사양" 하위 페이지 — 접근 불가(404, 권한 문제인지 페이지 삭제인지 불명). 리프레시 토큰 "6개월 경과 후 재발급"의 정확한 트리거 메커니즘(자동/수동, 기준일)이 이 페이지에 있을 것으로 추정되나 확인 불가

> **예외 근거**: 위 공백은 노션 SSOT 자체의 얇음에서 기인한다 — '회원(후원자/창작자)' 섹션이 헤더만 있고 하위 정책 페이지가 없어, 참조 가능한 원본 분량 자체가 제한적이다. 없는 사실을 추정으로 채워 분량을 맞추지 않는다.
