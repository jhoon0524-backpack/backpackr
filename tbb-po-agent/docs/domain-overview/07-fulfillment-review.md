## 후기 작성 시점

선물을 선택해 후원한 후원자가 후기를 작성할 수 있게 되는 시점과 조건을 정의한다. 선물 이행(발송·전달) 자체를 다루는 전용 정책은 노션에 없으며(아래 「커버리지 공백」 참조), 이행 상태는 후기 작성 가능 여부를 판정하는 조건 중 하나로만 이 문서에 등장한다.

### 후기 작성 진입 흐름 (순서)

1. 결제 완료
2. a) 창작자가 선물 전달 완료 처리 **또는** b) 예상 전달일 경과
3. 후원자가 후기작성 버튼 클릭 → "선물을 받았습니까?" 확인 UI 노출 (후원자가 "받았다"를 선택할 때까지 지속 노출)
4. "받았다" 선택 시 `project_warranties.delivered_at`에 날짜 기록 → 후기 작성 화면 진입 가능

"받았다" 버튼을 누르지 않으면 리뷰 작성 화면으로 넘어가지 않는다.

### 후기 작성 가능 조건 (AND, 노출 시점)

| 조건 | 상세 |
|---|---|
| 삭제되지 않음 | `is_deleted = false` |
| 결제 성공 | 노션 표기 "결제 성공한 경우(PAID)". ⚠️ 코드 기준 실제 판정 범위는 더 넓음 — 아래 「노션↔코드 불일치」 참조 |
| 선물 후원 | "선물 없이 후원하기"로 후원한 경우는 후기 작성 대상에서 제외 |
| 선물 전달 조건 | 아래 둘 중 하나를 충족: ① `project_warranties.reward_state`(선물 전달 상태)가 `전달완료`(4)인 경우, 또는 ② `reward_state`가 전달완료가 아니어도 선택한 선물 중 예상전달일(`rewards.expected_delivery_date`)이 지난 것이 존재하거나 `project_warranties.delivered_at`(후원자가 "받았다"고 확인한 날짜)에 값이 있는 경우 |
| 미작성 | 해당 후원건에 작성한 후기가 없음 |

### 선물 전달 상태 (`reward_state`, 전체 값)

| 값 | 코드명 | 한글 라벨 |
|---|---|---|
| 0 | STAND_BY | 대기 |
| 1 | INFO_REQUESTED | 정보요청 |
| 2 | DUMMY | 더미 |
| 3 | RESPONDED | 응답완료 |
| 4 | DELIVERED | 전달완료 |
| 5 | REFUNDED | 환불됨 |

후기 작성 가능 판정에는 이 중 `전달완료`(4) 여부만 직접 관여한다. 나머지 값은 CS·배송 흐름 등 이 문서 범위 밖에서 쓰이며, 선물 이행(발송·전달) 정책 자체는 「커버리지 공백」 참조.

### 후기 작성 제출 시점 검증

후기 작성 화면에서 실제 제출 시에는 아래 조건을 다시 검증한다.

- 선물을 선택하여 후원한 경우
- `project_warranties.delivered_at`이 null이 아닌 경우 (= 후원자가 "받았다"고 확인한 날짜가 있는 경우)
- 작성한 후기가 없는 경우

## 창작자/후원자 Pick 후기

특정 후기를 창작자 또는 후원자가 대표 후기로 선정해 노출을 강조하는 기능. 프로젝트 1개당 창작자 Pick·후원자 Pick 각각 최대 2개까지 선정 가능하다.

### 창작자 Pick

| 항목 | 내용 |
|---|---|
| 설정 영역 | 창작자 프로필 > 프로젝트 후기(`/u/product/review`), 프로젝트 > 후기(`/v/community/review`) |
| 설정 방법 | 원하는 후기 > 우측 상단 `...` 버튼 (클릭 가능 조건은 노션 원문에 상세 미기재) |
| Pick 개수 제한 | 프로젝트 1개당 최대 2개. 제한 수(2개)가 이미 있으면 오래된 픽 해제 |
| Pick 가능 조건 | 숨김처리된 후기는 픽 불가. 창작자가 아니면 픽 불가 |

후기 숨김·게시중단 등 일반 콘텐츠 모더레이션 정책은 `[10-community-notification.md 참조]`.

### 후원자 Pick

| 항목 | 내용 |
|---|---|
| Pick 개수 제한 | 프로젝트 1개당 최대 2개 |
| Pick 선정 기준 | 노션 원문에 "조건 확인하기"로만 기재되어 있고 실제 기준 내용은 없음 |

창작자 Pick·후원자 Pick 모두 오래된 픽 자동 해제 여부·업데이트 시점·선정 기준 세부는 노션 원문 자체 TODO로 남아 있다 — 「[확인 필요]」 참조.

## 후원자명단 다운로드 항목

창작자가 배송정보 등 후원자명단을 다운로드할 때 포함되는 항목과 조회 가능 기간을 정의한다.

### 배송정보 유형 (다운로드 포함 항목)

받은 사람 / 연락처 / 우편번호 / 주소 / 택배사 / 운송장번호

### 배송정보 조회 기간 조건

배송정보는 민감정보로 분류되어 아래 기간에만 조회 가능하다.

| 조건 | 조회 가능 기간 |
|---|---|
| 결제완료된 후원건, 배송 완료 전 | 예상 전달일로부터 90일 이내 |
| 배송 완료 후 | 배송 완료일로부터 30일 이내 |

코드 확인 결과 이 조회 기간 조건은 실제 서비스 로직과 정합한다.

## 노션↔코드 불일치

1. **후원 엔티티 테이블명**: 노션 문서는 "project_warranty 테이블"(단수형)로 기재(코드 기준 실제 테이블명은 `project_warranties`, 복수형).
2. **후기 작성 가능 "결제 성공(PAID)" 판정 범위**: 노션 문서는 "결제 성공한 경우(PAID)"로 기재(코드 기준 `PAID`·`REFUND_REQUESTED`(환불요청)·`REFUND_REJECTED`(환불거절) 3개 상태 모두 포함). 즉 환불을 요청했거나 환불이 거절된 후원건도 후기 작성이 가능하다 — 노션 문서가 코드보다 좁게 서술되어 있다.

## 커버리지 공백

- **선물 이행(발송·전달·지연) 정책 자체** — 발송 처리 프로세스·지연 시 대응·미이행 시 조치를 다루는 전용 노션 하위 페이지가 없음. 노션 SSOT에 미기재 — 필요 시 코드/담당자 확인.
  - 다만 이행 상태와 후기 작성이 엮이는 조건 자체는 위 「후기 작성 시점」에 정리된 대로 명확히 존재한다: 창작자의 "선물 전달 완료 처리"(= `reward_state` → `전달완료`(4) 전이) 또는 "예상 전달일 경과" 중 하나가 후기 작성 가능의 전제 조건이다. 즉 이행 완료 또는 예상 전달일 경과 중 하나가 충족되어야 후기 작성 플로우에 진입하며, 이행 프로세스 자체(발송 처리 방법·지연 대응·미이행 조치)는 이 조건식 밖의 별도 공백 영역이다.

## [확인 필요]

2. 창작자 Pick — "숨김처리된 후기 픽 불가" 조건에 "삭제 리뷰"가 동일하게 포함되는지 별도 조건인지
3. 후원자 Pick — 이미 2개일 때 자동 해제 여부
4. 후원자 Pick — 업데이트 시점
5. 후원자 Pick — Pick 선정 기준 자체가 미정("조건 확인하기"만 기재, 실제 기준 부재)
6. PDP 후기 영역 — "명확한 프로젝트 상태값" 미정 + 창작자 이전 리뷰 조회 시 정렬 로직 미정
