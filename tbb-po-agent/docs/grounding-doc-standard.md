# 그라운딩 문서 표준 (Grounding Doc Standard)

> **목적**: 로컬 그라운딩 문서(`docs/domain-overview/`)는 PRD·도메인분석·티켓화가 매번 먼저 읽는 **세션 그라운딩 SSOT**다. 이 문서는 그 그라운딩이 노션 정책 페이지 수준의 품질로 갱신되도록 하는 단일 표준이다. (노션 정책 페이지 쪽 표준은 `docs/notion-policy-page-standard.md` *(Phase 4+ 도입 예정)* — 이 문서는 그 **로컬 짝**이다.)
>
> **적용 주체**: 노션→그라운딩 동기화는 `sync-domain-overview-from-notion` 계열 스킬이 담당한다 *(Phase 4+ 도입 예정 — 현재는 `domain-analyst-agent` + `tbb-domain-analysis`가 노션·코드를 직접 대조해 수동/반자동으로 그라운딩을 갱신한다)*. 코드 경로(코드 SSOT→그라운딩 동기화, 가칭 `sync-notion-policy-from-code`류)·PRD 경로(PRD→노션 반영 후 그라운딩 동기화) 모두 향후 도입 시 노션 반영 후 이 표준을 따르는 동일 스킬을 위임 호출하도록 설계해, 입력이 코드든 PRD든 결과 그라운딩 품질이 이 표준 하나로 수렴하게 한다.
>
> **적용 대상 파일 (이 표준이 책임지는 범위)**:
> - **유형 A — 도메인 정책 미러**: `01-user-auth.md` ~ `11-adcenter.md`
> - **유형 B — 용어집**: `domain-glossary.md`
> - **제외**: `service-overview.md`(PRD·서비스라인 소스) / `projects.md`(repo 구조 소스) — 노션 정책 페이지가 SSOT가 아니므로 이 동기화 경로의 갱신 대상에서 제외한다. `notion-index.md`는 미러(스킬 자체 규칙).
>
> **원칙**: 기존 콘텐츠는 **보존**(모순만 해당 라인 수정), 신규 정책은 표 행·섹션 **추가**. 파일 전체를 갈아엎지 않는다. 추측 금지 — 노션 정책 페이지로 확인된 사실만(코드 미검증 PRD 기준은 라벨로 구분).

## A. 공통 품질 규율 (유형 A·B 모두)

노션 작업에서 확립한 품질 규율을 그라운딩에 그대로 적용한다.

| 규율 | 내용 |
|------|------|
| **① 완성본(thin diff 금지)** | dry-run에 제시하는 변경분은 "X 추가" 요약이 아니라 **파일에 그대로 들어갈 완성 본문**(표는 헤더+모든 행, 문단·다이어그램 전체). Enum/상태는 전체 값+한글 라벨을 다 나열(“N종”으로 줄이지 않음). |
| **② 보존 + 증분** | 기존 표 구조·톤·헤더 메타(`관련 레포`·`관련 엔티티`·출시일 등)를 보존. 모순은 **해당 표 행/문단만** 노션 기준으로 수정, 신규는 행/섹션 추가. 전체 헤더 재생성·파일 덮어쓰기 금지. |
| **③ 중복 금지** | 이미 그라운딩에 있는 내용은 다시 적지 않는다(변경·추가만). 같은 정책을 두 파일에 복붙하지 않고, 한 파일에 두고 다른 파일은 `[N-domain.md 참조]`로 가리킨다. |
| **④ 노션 메타는 본문으로 옮기지 않음** | 노션 §5 「🔧 코드 기준 정책 보강」의 **정책 사실(Enum·계산식·상수·에러코드)**은 반영하되, 노션의 검증 푸터(`🔎 코드 정합 검증 …`)·§8 변경 이력·상태 라벨 **자체**는 메타이므로 그라운딩 본문 정책으로 옮기지 않는다. |
| **⑤ 출처 헤더 유지** | 각 파일 상단 `> 노션 원본 — {라벨}: {URL}` 라인을 매핑된 현행 하위페이지 URL로 유지·갱신. 휘발성 근거(`파일경로:라인`)는 그라운딩 본문에 박지 않는다. |
| **⑥ 성숙도 라벨** | 코드 미검증 PRD 기준 정책은 `[PRD 기준 — 코드 미검증]`, 코드로 확인된 정책은 라벨 없음(확정). 비즈니스/외부 확인 대기는 `[확인 필요]`. (§E) |
| **⑦ 반영 후 검증** | `Edit` 직후 해당 파일을 다시 `Read`해 **표 행 수·신규 섹션·헤더 출처 라인**이 의도대로 들어갔는지 대조한다. 누락분은 재반영. (그라운딩 품질의 마지막 게이트) |
| **⑧ dry-run 승인 게이트** | 파일당 표 1개 초과 또는 3개 파일 초과 변경이면 dry-run diff(아래 §D 양식)를 먼저 제시하고 승인 후 반영. |

## B. 유형 A — 도메인 정책 미러 (`01`~`11`) 골격

```
# {도메인 한글명} ({English})

> 노션 원본 — {라벨}: {현행 하위페이지 URL}   ← 복수면 다줄
> 관련 레포: `repo` (...)                      ← 보존
> 관련 엔티티: ...                             ← 보존(있으면)

---

## {정책 흐름/상태/규칙 섹션}
{흐름 다이어그램 / 상태표 / 정책 표}

---

> **마지막 업데이트**: YYYY-MM-DD ({반영 주체 — 현재는 `domain-analyst-agent`/수동 반영; `sync-domain-overview-from-notion` 자동화는 Phase 4+ 도입 예정})
```

- **상태/Enum 표**는 노션 §5 정규 스키마를 따라 **전체 값 + 한글 라벨**을 보존한다(예: `03-project.md`의 프로젝트 상태머신이나 `05-funding-payment.md`의 예약결제 상태를 일부만 남기고 줄이지 않음, 새 값은 행 추가).
- **계산식·상수**는 단위·반올림 모드까지 노션/코드 기준으로 그대로 일치시킨다(예: 모금액 집계·수수료 계산의 반올림 모드 — 확인된 값을 임의로 바꾸지 않음).
- 헤더의 `노션 원본` 라인만 갱신, 나머지 메타 라인은 그대로 둔다(공통 규율 ②·⑤).

## C. 유형 B — 용어집 (`domain-glossary.md`) 골격 + 등재 규칙

골격: 카테고리(후원자/창작자/프로젝트/리워드/펀딩결제/정산/…)별 표.

```
## {N}. {카테고리}

| 한국어명 | 영문명 / 코드명 | 설명 |
|---------|----------------|------|
| 예약결제 | Reserved Payment / `ReservedPayment` | 기간 펀딩에서 후원 시점에 카드는 승인만 해두고, 마감 후 목표 달성 시에만 일괄 청구되는 결제 방식(All-or-Nothing). 05-funding-payment.md 참조 |
```

**등재 규칙** (용어집은 이제 1급 갱신 대상 — 기존 "충돌 시만 보수적 보강"에서 격상):

1. **신규 등재 트리거** — 정책 페이지에 **새 용어·엔티티·Enum/상태 라벨**이 등장하면 용어집에 1행 등재한다. 특히 도메인 미러(유형 A)에 새로 추가한 **상태값·정책 상수의 한글 라벨**은 용어집에도 표제어로 올린다.
2. **코드명 일치** — `영문명/코드명` 칸의 Enum·클래스·엔티티 표기는 **코드 SSOT**와 정확히 일치시킨다(현재는 `sources/be-api` 코드베이스를 직접 대조; 전용 동기화 스킬 `sync-notion-policy-from-code`는 *Phase 4+ 도입 예정*). 코드명을 추측으로 짓지 않는다(불명확하면 한글 라벨만 등재 + `[확인 필요]`).
3. **정의 정합** — 한 줄 설명은 유형 A 정책 본문과 모순되지 않게. 상세는 `{NN-domain.md} 참조`로 가리킨다(중복 금지, 공통 규율 ③).
4. **보존** — 기존 표제어·정의는 보존, 모순될 때만 해당 행 수정. 표제어 중복 금지(동의어는 한 행에 `/`로 병기).
5. **카테고리 배치** — 새 표제어는 의미상 맞는 기존 카테고리 표에 넣는다. 카테고리 신설은 지양(필요 시 dry-run에서 제안).

## D. dry-run 제시 양식 (AS-IS / TO-BE — 완성본)

변경분을 사용자에게 제시할 때, 파일별로 **그대로 반영될 본문**을 AS-IS와 대비해 보인다(요약·불릿 금지).

```
[그라운딩 반영본] {파일명}

■ AS-IS (바뀌는 부분 — 현재 본문 그대로 인용)
{현재 표 행 / 문단}

■ TO-BE (반영 후 본문 — 완성본; 표는 헤더+모든 행)
{표 전체 / 문단 / 다이어그램}

■ [확인 필요]: {노션으로 못 닫는 값 — 추측으로 채우지 말고 비고}
■ 성숙도: 확정 / [PRD 기준 — 코드 미검증]
```

## E. 성숙도 라벨 (그라운딩용 — 통일)

| 라벨 | 의미 |
|------|------|
| (라벨 없음) | 노션 정책 페이지(또는 코드)로 확인된 확정 정책 |
| `[PRD 기준 — 코드 미검증]` | PRD 기획 의도 기준. 배포 후 코드 기준 재검증 대상 |
| `[확인 필요]` | 노션·코드로 못 닫음(비즈니스·외부 확인 대기) |

> 코드 검증이 완료되면(코드 경로 동기화 시) `[PRD 기준 — 코드 미검증]` 라벨을 제거해 확정으로 승격한다.
