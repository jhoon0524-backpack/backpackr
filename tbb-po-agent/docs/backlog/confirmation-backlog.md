## P1 — 즉시 확인 (6건)

- [ ] **B-01** · BE 엔지니어 — **상시 취소 시 한정수량 선물의 Redis 주문수 복구 비활성(주석 처리)**. 기간 펀딩 진행중 취소는 복구 활성인 것과 비대칭 — 버그 의심. 사실이면 상시 프로젝트 취소분이 재고로 복구되지 않아 한정수량 매진 오탐 유발. *(출처: 08 §확인필요 3 · code-map 취소·환불 상세 엔트리)*
- [ ] **B-02** · 엔지니어링 + 운영셀 — **성공 후 프로젝트 무산(비프리오더 기간 펀딩) 시 후원 일괄 환불 경로**. be-api 전 모듈 부재 확정 — 실제 처리 위치(레거시 Ruby/어드민 수동/운영 프로세스) 불명. 불변식 "무산 시 전액 환불"의 실행 경로가 미확인 상태. *(출처: 08 §확인필요 1)*
- [ ] **B-03** · 운영셀 + PO — **신고 창작자 운영셀 리스트 임시처리(2024-11-28 배포 + 1년) 만료 후 연장·시스템화 여부**. **만료일 2025-11-28이 이미 약 7.5개월 경과** — 현재 처리 근거가 공백일 수 있음. *(출처: 02 §심사·제재)*
- [ ] **B-05** · PO 결정 + BE — **선물 옵션 100자·문자셋 검증의 서버 강제 추가 여부**. 프론트 단독 검증으로 **확정됨(fe 코드 확인 2026-07-13)** — 에디터가 글자수 100자, 후원 폼이 허용 문자셋을 입력단에서 강제하고 be-api는 검증하지 않는다. API 직접 호출 우회 리스크 실재 — 서버 검증 추가 여부는 프로덕트 결정. *(출처: 04 §확인필요 3 · code-map 04 fe 행)*
- [ ] **B-06** · 기획 — **프리오더 환불 승인 화면 안내 문구 정정 여부**. 화면 위치·불일치 내용 **확정됨(fe 코드 확인 2026-07-13)**: fe next-web 후원자 관리 콘솔의 환불 승인 모달 문구 "즉시 후원자의 결제가 취소됩니다"가 계좌결제 건에 부정확(실제로는 환불 처리중 전이 후 Slack 수동 처리 대기). 결제수단별 처리 시점 안내로 문구 정정할지 결정 필요. *(출처: 08 §확인필요 5 · code-map 08 fe 행)*
- [ ] **B-42** · BE 엔지니어(레거시 접근 가능자) — **(신규 2026-07-23)** 창작자 업데이트 알림의 **실발송 팬아웃(be-api-legacy Ruby) 검증**. be-api v2에는 업데이트 알림 3종 발송 코드가 없고 Ruby delayed_jobs 위임만 확정(2026-07-16 푸시 VOC 분석). 과거 push_setting_type 오지정(설정 우회 발송) 버그 이력이 v2 주석에 잔존 — 후원자 VOC "설정 해제에도 푸시 수신"의 원인 후보. Ruby 측 대상 선정·설정 타입 지정 로직을 확인해 설정 우회 경로 존부를 닫아야 함. *(출처: 10 §확인필요 5 · code-map 10 알림 파이프라인 행)*
