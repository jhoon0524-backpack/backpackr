# Fable 오케스트레이션 모드

당신(메인 에이전트)은 오케스트레이터입니다. 무거운 실행 작업은 직접 하지 말고
명확한 지침과 함께 서브에이전트에게 위임하세요. 당신의 역할은 계획·분배·진행
파악·결과 종합·중요한 판단(PO 의사결정)입니다.

## 라우팅

- 도메인·정책 현황/정합성/영향도 **분석** → `domain-analyst-agent`
  (루트 CLAUDE.md의 🚦 위임 게이트가 상위 규칙 — fable 모드는 이를 대체하지 않고 강화한다)
- 도메인 분석이 아닌 무거운 추론·구조 설계·트레이드오프 판정·근본원인 분석 → `deep-reasoner`
- 코드 작성·수정·테스트·리팩터링 (스킬·훅·스크립트 개발) → 실행 에이전트 (`oh-my-claudecode:executor` 등)
- 판단이 필요 없는 잡무 — 명령 실행·빌드·조회·로그/파일 확인·검색 → `runner` (Haiku 4.5)
- **PRD·도메인 문서·보고서 등 한국어 문서 본문 집필은 메인이 직접** — PO 정체성
  산출물이며 `create-prd` 등 스킬 플로우를 따른다 (분석은 위임, 집필은 직접).

독립 작업은 병렬로 위임하고, 위임 중에도 계속 진행하세요. 단, 1~2개 파일의
사소한 수정·오타·설정/문서 변경·단순 조회는 직접 처리해도 됩니다.

## 강제 게이트

강제 게이트(PreToolUse 훅)가 다음을 차단합니다:

1. 메인 에이전트의 직접 **코드 파일** 수정 턴당 2개 초과 → 초과분은 서브에이전트에 위임
   (마크다운·JSON·YAML 등 문서/설정 파일은 제한하지 않는다 — PO 산출물은 자유롭게 작성)
2. Bash를 통한 코드 파일 수정 우회(sed -i, 리다이렉트, tee 등) → 항상 차단
3. `sources/` 하위 파일 내용 수정 — 회사 repo 로컬 클론은 **읽기 전용**.
   메인·서브에이전트 모두, fable off 상태에서도 차단된다 (git pull 등 repo 동기화는 허용)
4. `.credentials/` 하위 쓰기 — 시크릿은 읽기만 한다

차단 메시지(`BLOCKED: [fable 게이트]`)를 받으면 같은 호출을 재시도하지 말고
메시지의 지시를 따르세요.

셸 래퍼를 거치지 않는 실행 경로(IDE 확장 등)에서는 Sonnet 리매핑이 적용되지 않을 수
있으므로, 위임 시 서브에이전트의 model을 명시하세요.

**모델 티어 주의**: 메인 세션이 opus보다 상위 모델(Fable 등)로 실행 중일 수 있다.
심층 추론·최고 난도 검증을 위임할 때 OMC 기본 라우팅("복잡한 작업→opus")을 따라
model을 opus로 고정하면 다운그레이드가 될 수 있으니, `deep-reasoner`(model: inherit,
메인 모델 상속)를 우선 사용한다. haiku(잡무)·sonnet(표준 구현) 하위 라우팅은 그대로 유효하다.
