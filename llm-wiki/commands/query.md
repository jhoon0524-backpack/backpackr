# /query

날짜가 필요하면 `date +%Y-%m-%d`로 확인한다.

## 1. index부터

1. `99_system/index.md`를 **먼저** 읽는다.
2. 관련 있어 보이는 페이지만 골라서 읽는다. `wiki/` 전체를 훑지 않는다.
3. 읽은 페이지가 다른 페이지를 가리키고 그게 필요하면 따라간다. 필요한 만큼만.
4. index만으로 후보를 못 찾겠으면 그때 `wiki/`를 검색한다.

## 2. 답하기

- 근거가 된 페이지는 `[[링크]]`로 인용한다. 어느 주장이 어느 페이지에서 왔는지 알 수 있게.
- **위키에 없는 건 지어내지 않는다.** 일반 지식이나 학습된 내용으로 빈틈을 메우지 않는다.
- 근거가 부족하면 그냥 **"위키에 확실한 답이 없다"**고 말한다.
  - 무엇이 없는지, 어떤 소스를 `00_raw/`에 넣으면 답할 수 있는지 같이 말한다.
  - **이런 답은 위키에 저장하지 않는다.** 저장 제안도 하지 않는다.
- 부분적으로만 답할 수 있으면 답할 수 있는 범위와 없는 범위를 나눠서 말한다.
- 위키 내용끼리 상충하면 한쪽을 임의로 고르지 말고 양쪽과 각각의 근거를 보여준다.

## 3. 저장 제안

근거가 충분한 답이고 나중에 또 쓸 만하면, 답한 뒤에 위키에 저장할지 물어본다.
묻기만 하고, 승인 없이 저장하지 않는다.

승인하면:

- 보통 `type: synthesis`. 답이 사실상 새 개체·개념의 정리라면 `entity`/`concept`.
- `sources:`에는 근거로 읽은 위키 페이지가 아니라, 그 페이지들이 딛고 있는 `00_raw/` 원문을 적는다.
- 관련 페이지에서 링크를 걸어 고아로 만들지 않는다. 양쪽 `related:`를 맞춘다.
- `99_system/index.md`에 추가.
- `99_system/log.md`에 `## [YYYY-MM-DD] query | 질문 요약` + 만든 페이지.

저장하지 않은 질문은 log에 남기지 않는다.
