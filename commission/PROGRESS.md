## 알고 있는 문제
- **아직 아무것도 배포되어 있지 않다.** 그리고 카카오 로그인이 붙기 전에는 진짜 공개가 없다 (`DEPLOY.md` 0장).
  팀 안에서 눌러 보려면 `DEMO_LOGIN=on` 과 Vercel Deployment Protection 을 **함께** 켜야 한다. 둘은 한 몸이다.
- `requests` 에 **거절 시각 열이 없다**(`declined_at`). 그래서 기록 줄이 "거절" 을 시각과 함께 못 보여 준다 —
  `decline_reason` 만 남는다. 열 추가는 스키마 변경이라 이번 범위 밖에 뒀다. 12차에서 발견.
- 유예 3일은 **결제가 없다는 전제** 위에 있다. 돈이 오간 뒤라면 의뢰인이 혼자 물리게 두면 안 된다.
  결제가 붙을 때 이 정책을 다시 본다 (`SPEC.md` 2장 4번).
- 피치색 버튼 위 흰 글자는 대비가 3.4 라 작은 글자 기준(4.5)에는 못 미친다. 텀블벅 실제 버튼과 같은 선택이라 따랐고,
  그래서 굵은 16px 이상에서만 쓴다 (`app/ui.ts`). 접근성 기준을 올리려면 버튼색을 `--color-accent-deep` 보다 더 어둡게 잡아야 한다.
- 모바일 상세에서 의뢰 패널이 맨 아래에 있다. 텀블벅 모바일은 "후원하기" 를 화면 아래에 고정한다 — 같은 장치를 붙일지는 실제 기기 QA 뒤에.
- 채점자가 근거 없이 기록만 한 것: 의뢰도 넣고 커미션도 연 사람은 커미션을 여는 순간 "내가 넣은 의뢰" 칸이 맨 위에서 맨 아래로 이동한다. 탭 줄에 현재 탭 표시가 없다. 의뢰 취소에는 확인이 없다(수락 전이라 되돌릴 수 있는 일이라 뺐다).
- 없는 id 로 들어오면 "찾을 수 없는 페이지" 가 보이지만 HTTP 상태는 200 이다. `loading.tsx` 때문에 껍데기가 먼저 나가고 404 는 스트리밍으로 뒤에 온다. 사람 눈에는 문제없고 dropbid 도 같다. 검색엔진 대응이 필요해지면 그때 본다.
- 커미션을 열고 나면 가격·기간을 못 바꾼다 (열기/닫기만). 바꾸려면 새로 연다.

## 다음 사람이 헷갈릴 만한 것
- **로그인이 없다.** 화면 위 "로그인 대신" 전환기로 사람을 바꿔 가며 창작자·의뢰인 양쪽을 본다. 시연 데이터의 김창작·이글꼴이 창작자, 박덕후·최의뢰가 의뢰인이다 (누구나 커미션을 열 수는 있다).
- 슬롯은 `accepted` + `delivered` 만 센다. `requested` 는 안 센다 — 대기 의뢰가 아무리 쌓여도 창작자가 고를 수 있어야 한다. 전달만 해서는 자리가 안 비고 **의뢰인이 완료를 눌러야** 빈다 (테스트로 고정).
- 의뢰 상태는 `requests` 에 직접 쓰지 않고 DB 함수로만 바꾼다 (`CLAUDE.md` 규칙 목록). 권한으로도 막혀 있다.
- `npm test` 는 로컬 DB 를 통째로 지우고 다시 만든다. 화면을 보려면 그 뒤 `npm run db:seed`.
- 시연 데이터에서 박덕후는 로고 커미션에 이미 대기 의뢰가 있다. 같은 커미션에 또 넣으면 "이미 수락을 기다리는 의뢰가 있습니다" 가 뜨는데, 그건 의도된 동작이다 (브라우저 검증 중 한 번 헷갈렸다).
