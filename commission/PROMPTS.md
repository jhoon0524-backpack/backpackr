# 프롬프트 모음

복사해서 그대로 던진다. 상황별로 다섯 개뿐이다.

---

## 1. 처음 한 번 — 작업 목록 만들기

`SPEC.md` 와 `CLAUDE.md` 를 채운 뒤 딱 한 번 던진다.

```
너는 CLAUDE.md에 정의된 개발자다. 지금부터 이 프로젝트를 총괄한다.

1. SPEC.md를 상세히 분석해라.
2. 이 서비스를 완성하기 위한 개발 작업을 30분 이내에 끝낼 수 있는
   가장 작은 단위로 쪼개서 TASKS.md에 `- [ ]` 체크리스트로 작성해라.
   - 카테고리: [기반] [데이터] [기능] [화면] [마무리]
   - 각 항목은 "무엇이 되면 끝인지" 판단할 수 있어야 한다.
   - 앞의 20개는 손이 바로 움직일 만큼 구체적으로, 뒤쪽은 대략만.
3. PROGRESS.md의 "다음에 진행할 작업"을 첫 번째 항목으로 맞춰라.
4. 전체 작업 개수와 첫 작업 1개를 요약해서 보고해라.

아직 코드는 작성하지 마라.
```

## 2. 매일 — 작업 1개 실행

**이 한 줄이 전부다.** 새 대화를 열고 던진다.

```
CLAUDE.md 규칙에 따라 PROGRESS.md를 읽고 다음 작업 1개만 실행해
```

작업 하나에 대화 하나. 끝나면 대화를 닫는다.
길게 끌면 AI 가 앞에서 정한 것을 잊고, 잊은 채로 다음 작업에 들어간다.

---

## 3. 이미 코드가 있는 프로젝트에 얹을 때

새로 시작하는 게 아니라 기존 서비스에 킷을 넣는 경우.
`SPEC.md` 를 상상으로 쓰면 안 된다. 코드에서 읽어내야 한다.

```
이 코드베이스를 분석해서 SPEC.md를 채워라.

- 무엇을 하는 서비스인지, 누가 쓰는지
- 사용자가 거치는 핵심 흐름
- 실제 스택과 데이터 저장소, 외부 연동
- 되돌릴 수 없는 지점: 마이그레이션, 결제, 메일 발송, 데이터 삭제가
  실제로 일어나는 파일과 함수를 찾아서 경로와 함께 적어라

추측해서 적지 마라. 코드에서 확인한 것만 적고,
확인하지 못한 항목은 "확인 필요" 라고 남겨라.
```

그다음 `CLAUDE.md` 3장 검증 명령을 채운다.

```
package.json과 CI 설정을 읽고, 이 프로젝트에서 실제로 돌아가는
테스트·린트·타입체크 명령을 CLAUDE.md 3장에 채워 넣어라.
실제로 한 번씩 실행해서 통과하는지 확인하고 결과를 보고해라.
```

## 4. 작업이 너무 클 때

한 작업이 30분을 넘겼거나, 항목을 보고 뭘 해야 할지 모르겠을 때.

```
TASKS.md의 "<항목 이름>" 이 한 번에 하기엔 크다.
30분 안에 끝낼 수 있는 단위로 쪼개서 그 자리에 대체해 넣어라.
쪼갠 각 항목은 "무엇이 되면 끝인지"가 분명해야 한다.
코드는 작성하지 마라.
```

---

## 5. 같은 문제가 두 번 나왔을 때

규칙으로 승격시킨다. 이걸 안 하면 같은 지적을 계속 하게 된다.

```
방금 지적한 문제가 두 번째다. CLAUDE.md의 [규칙 목록]에 항목으로 추가해라.

형식: - [범위] 확인할 내용 — 검사 방법 (등록 사유)

"검사 방법" 칸에는 이 규칙을 어겼는지 확인할 실제 명령이나 절차를 적어라.
확인할 방법이 없으면 그건 규칙이 아니다. 그럴 때는 검사를 먼저 만들자고 제안해라.
```
