# 커미션 — 창작자 맞춤 작업 의뢰 서비스

## 1. 개요
- **무엇:** 창작자가 받을 수 있는 맞춤 작업(커미션)을 메뉴로 열어 두면, 의뢰인이 내용을 적어 의뢰하고 창작자가 수락·작업·전달까지 한 곳에서 처리하는 웹 서비스
- **누가 쓰나:** 일러스트·로고·글·음악 등 맞춤 작업을 받는 창작자, 그 작업을 맡기고 싶은 의뢰인
- **성공 기준:**
  - 의뢰 → 수락 → 전달 → 완료 흐름이 화면 밖(DM·메일)으로 새지 않고 끝나는 비율 (완료 / 수락)
  - 창작자가 정한 동시 진행 건수를 시스템이 넘기지 않는다 (동시 수락 20건 중 슬롯 수만큼만 성공 — 테스트로 고정)
  - 두 지표 모두 `requests` 테이블만으로 계산 (별도 이벤트 로깅 없음)

## 2. 핵심 흐름
1. 창작자가 커미션 메뉴를 연다 — 제목·설명·분류·기본가·작업 기간(일)·동시 진행 건수·샘플 주소
2. 의뢰인이 열린 커미션을 보고 의뢰 내용(10자 이상)과 참고 링크를 적어 보낸다 → `requested`
3. 창작자가 최종가를 정해 수락하거나 사유를 적어 거절한다 → `accepted`(마감일 = 수락일 + 작업 기간) / `declined`
4. 의뢰인은 수락 전까지만 취소할 수 있다 → `cancelled`
5. 창작자가 결과물 주소나 메모로 전달한다 → `delivered`
6. 의뢰인이 확인하면 완료된다 → `completed`. 이때 창작자의 자리가 하나 빈다
7. 슬롯(`accepted` + `delivered` 건수)이 동시 진행 건수에 닿으면 새 의뢰를 받지 않는다. 창작자는 언제든 메뉴를 닫을 수 있다 (진행 중 의뢰는 그대로)

## 3. 기술 규격
- **스택:** Next.js 16 (App Router) + TypeScript + Tailwind 4 — `dropbid` 와 같다
- **데이터 저장:** Postgres (Supabase 호환 마이그레이션). 의뢰 상태 변경은 DB 함수 6개(`submit/accept/decline/cancel/deliver/complete_request`)로만. 커미션 행 잠금으로 슬롯 초과를 막는다
- **로그인:** 아직 없다. 화면 위 사용자 전환기(쿠키)로 대신한다. 붙일 때 `lib/session.ts` 만 바꾼다
- **외부 연동:** 없음 (이미지는 주소 입력, 결제 없음)
- **배포:** Vercel + Supabase (dropbid 와 같은 절차, `dropbid/인터넷에-올리기.md`)

## 4. 경계

만들지 않는다:
- 결제·에스크로·정산 (완료 확정이 정산 의무의 기준점이지만 돈은 아직 밖에서 오간다)
- 채팅·메시지 (의뢰 내용과 전달 메모, 거절 사유 텍스트로만)
- 수정 요청 횟수 관리, 중간 시안 승인 단계
- 리뷰·평점, 검색·필터, 창작자 팔로우
- 이미지 업로드 (Supabase Storage 붙기 전까지 주소 입력)
- 운영자 화면 (분쟁 조정 없음)

## 5. 되돌릴 수 없는 지점

`CLAUDE.md` 4장과 짝을 이룬다.
- 완료 확정 (`complete_request` — 이후 정산 의무 발생, 되돌리는 함수가 없다)
- 수락 (`accept_request` — 최종가와 마감일이 박히고 자리를 차지한다)
- 프로덕션 DB 마이그레이션
