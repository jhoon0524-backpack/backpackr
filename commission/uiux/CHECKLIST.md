# 화면 검사표

이 표가 **채점 기준의 전부**다. 여기 없는 것은 채점하지 않는다.

## 왜 표로 고정했나

전에는 채점자에게 "얼마나 좋은지 10점 만점으로 매겨라" 고 물었다.
그러자 **40바퀴를 돌고도 5~6점을 오갔다.** 매번 다른 것을 지적했기 때문이다 —
"노랑을 한 번만 써라" 해서 줄이면 다음 바퀴에 "노랑이 한 번뿐이라 우연 같다" 고 했다.
점수를 목표로 두면 목표가 움직인다. 움직이는 목표는 도달할 수 없고, 그건 루프가 아니라 쳇바퀴다.

그래서 **묻는 것을 바꿨다.** "얼마나 좋은가" 가 아니라 **"이 사람이 하려던 걸 할 수 있는가"** 다.
항목은 세어지고, 하나하나 통과/실패가 갈리고, 다 통과하면 **거기서 끝난다.**

## 채점 방법

1. 채점자는 **이 표만** 받는다. 코드도, 앞 회차 기록도 안 본다.
2. 화면마다 표의 항목을 처음부터 끝까지 훑는다.
3. 항목마다 **통과 / 실패 / 해당 없음** 셋 중 하나를 적는다. 점수는 없다.
4. **실패에는 반드시** 어느 화면 어느 자리인지와 "대신 무엇이면 되나" 한 문장을 붙인다.
5. **판정: 실패 0건이면 통과.** 그때 이 화면은 끝이다.

## 항목을 늘리는 규칙

한 회차 안에서는 표를 **늘리지 않는다.** 회차가 시작될 때의 표로만 채점한다.
새로 알게 된 문제는 다음 회차 표에 넣는다. 이 규칙이 없으면 표가 채점 중에 자라서 다시 쳇바퀴가 된다.

새 항목의 조건 — **"이걸 어긴 걸 어떻게 알지?"** 에 한 문장으로 답할 수 있어야 한다.
답할 수 없으면 그건 항목이 아니라 취향이다.

## A. 다음에 뭘 할지 안다

| | 항목 | 확인 방법 |
|---|---|---|
| A1 | 이 화면이 무슨 화면인지 **첫 줄에** 적혀 있다 | 화면 맨 위 글자만 읽고 어디인지 말할 수 있는가 |
| A2 | 이 화면에서 **할 수 있는 일**이 눈에 띄는 곳에 있다 | 처음 온 사람이 다음에 누를 곳을 5초 안에 찾는가 |
| A3 | 목록이 **비었을 때 나가는 길**이 있다 | 데이터를 0건으로 두고 열어, 다음에 뭘 할지 적혀 있는가 |
| A4 | 막다른 화면이 없다 | 모든 화면에서 돌아가거나 다음으로 갈 길이 있는가 |
| A5 | 지금 어디에 있는지 길(내비)에 표시된다 | 머리의 길에서 현재 위치가 다른 것과 구별되는가 |

## B. 읽을 수 있다

| | 항목 | 확인 방법 |
|---|---|---|
| B1 | 작은 글자(18px 미만)의 대비가 **4.5 이상** | 색을 재서 확인. 굵은 18px 이상은 3.0 이상 |
| B2 | 글자가 잘리거나 상자 밖으로 나가지 않는다 | 폭 390 과 1440 에서 캡처해 확인 |
| B3 | **놓치면 손해 보는 숫자**가 그 화면에서 가장 크다 | 값·마감일·남은 자리가 곁글자보다 큰가 |
| B4 | 어두운 테마에서도 읽힌다 | 기기 테마를 어둡게 두고 확인 |
| B5 | 한글이 낱말 중간에서 줄바꿈되지 않는다 | 폭 390 에서 두 줄 넘어가는 글을 확인 |

## C. 손이 닿는다

| | 항목 | 확인 방법 |
|---|---|---|
| C1 | 누르는 것의 크기가 **44×44 이상** | 폭 390 에서 재기 |
| C2 | 누르는 것끼리 **8px 이상** 떨어져 있다 | 폭 390 에서 재기 |
| C3 | 가로로 밀어야 보이는 것이 없다 | 폭 390 에서 가로 스크롤이 생기는가 |
| C4 | 키보드만으로 끝까지 갈 수 있다 | Tab 만 눌러 주요 행동을 완료할 수 있는가 |
| C5 | 고정 막대가 내용을 가리지 않는다 | 폭 390 에서 맨 아래까지 내려 확인 |

## D. 되돌릴 수 있다

| | 항목 | 확인 방법 |
|---|---|---|
| D1 | **되돌릴 수 없는 행동**은 확인을 받는다 | 수락·완료·내리기를 눌러 확인 단계가 나오는가 |
| D2 | 실수했을 때 무엇이 틀렸는지 **그 자리에서** 알려 준다 | 빈 폼을 보내 보고, 오류가 해당 칸 옆에 뜨는가 |
| D3 | 오류 문구가 **다음에 뭘 하라고** 말한다 | "잘못된 입력" 같은 말이 아니라 고칠 방법을 말하는가 |
| D4 | 보낸 내용이 사라지지 않는다 | 오류가 났을 때 쓴 글이 남아 있는가 |

## E. 무슨 일이 일어났는지 안다

| | 항목 | 확인 방법 |
|---|---|---|
| E1 | 누른 뒤 **무슨 일이 일어났는지** 화면이 말한다 | 보내기·수락 후 확인 문구나 상태 변화가 보이는가 |
| E2 | 기다리는 동안 기다린다는 표시가 있다 | 느린 연결로 두고 확인 |
| E3 | 지금 상태가 화면에 적혀 있다 | 의뢰가 어느 단계인지 그 화면만 보고 아는가 |
| E4 | 못 하는 것은 **왜 못 하는지** 적혀 있다 | 마감된 메뉴에서 의뢰할 수 없는 이유가 보이는가 |

## F. 말이 하나다

| | 항목 | 확인 방법 |
|---|---|---|
| F1 | 같은 것을 두 이름으로 부르지 않는다 | 화면들을 나란히 두고 낱말을 대조 |
| F2 | 영어가 새지 않는다 | 화면 글자에 영어가 있는가 (고유명사 제외) |
| F3 | 사람 말이다 | 소리 내어 읽어 어색한 문장이 있는가 |
| F4 | 숫자의 단위가 붙어 있다 | 값·기간·자리 수에 단위가 있는가 |

## 채점할 화면

| 화면 | 주소 | 보는 사람 |
|---|---|---|
| 메뉴판 | `/` | 처음 온 의뢰인 |
| 메뉴 상세 | `/commissions/[id]` | 의뢰를 넣을지 정하는 사람 |
| 메뉴 붙이기 | `/open` | 처음 메뉴를 붙이는 창작자 |
| 메뉴 고치기 | `/commissions/[id]/edit` | 이미 붙인 메뉴를 손보는 창작자 |
| 내 의뢰 | `/me` | 자기 것을 확인하러 온 사람 |
| 의뢰 상세 | `/requests/[id]` | 창작자와 의뢰인 양쪽 |

## 판정 적는 곳

`uiux/PROGRESS.md` 맨 위에 이렇게 적는다.

```
**판정: 통과** (2026-09-03, 표 v1, 화면 6개, 실패 0건)
```

또는

```
**판정: 미통과 — 실패 3건** (2026-09-03, 표 v1)
- A3 / 내 의뢰 / 의뢰가 하나도 없을 때 화면이 비고 갈 곳이 없다
  → 대신: "메뉴판에서 마음에 드는 것을 골라 보세요" 한 줄과 메뉴판으로 가는 길
- ...
```
