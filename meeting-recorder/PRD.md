# PRD: 회의록 레코더 (Meeting Recorder)

| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.0 |
| 작성일 | 2026-07-16 |
| 상태 | v1 구현 완료, 검수 대기 |
| 플랫폼 | Android (minSdk 26, targetSdk 35) |

---

## 1. 개요

### 1.1 문제 정의

회의 내용을 기록하는 일은 필수적이지만 비용이 크다.

- 회의 중 필기를 하면 논의에 온전히 집중하지 못한다.
- 녹음 앱을 쓰더라도 "앱 찾기 → 실행 → 녹음 버튼"의 마찰 때문에 회의 시작 시점을 놓치기 일쑤다.
- 녹음을 해도 다시 듣고 회의록으로 정리하는 데 회의 시간 이상의 후처리 시간이 든다.
- 결과적으로 결정 사항과 액션 아이템이 유실되고, 참석하지 않은 사람에게 공유되지 않는다.

### 1.2 솔루션

**핸드폰 우측 버튼(사이드 키)을 두 번 누르는 것만으로** 녹음을 시작하고, 다시 두 번 눌러 정지하면 **음성 전사 → 구조화된 회의록 생성 → 저장/알림**까지 사람의 개입 없이 자동으로 완료되는 Android 앱.

핵심 가치: **"버튼 두 번" 이후 회의록이 나올 때까지 사용자가 할 일이 없다.**

### 1.3 목표 사용자

- 1차: 사내 구성원 중 회의가 잦은 실무자·리더 (PM, 팀장, 영업/파트너십 담당)
- 2차: 인터뷰·미팅 기록이 필요한 모든 스마트폰 사용자

## 2. 목표와 성공 지표

### 2.1 제품 목표

1. 녹음 시작까지의 마찰을 물리 버튼 두 번(2초 이내)으로 줄인다.
2. 녹음 정지 후 회의록 생성까지 전 과정을 무개입 자동화한다.
3. 결과물은 바로 공유 가능한 수준의 구조화된 회의록이어야 한다.

### 2.2 성공 지표 (KPI)

| 지표 | 목표 |
|---|---|
| 녹음 시작 소요 시간 (버튼 첫 입력 → 녹음 개시) | ≤ 2초 |
| 파이프라인 자동 완료율 (정지 → 회의록 저장 성공) | ≥ 95% (네트워크 정상 기준) |
| 회의록 생성 소요 시간 (30분 녹음 기준) | ≤ 3분 |
| 주간 재사용률 (첫 사용자 중 다음 주 재사용) | ≥ 40% |
| 회의록 수동 수정 없이 공유된 비율 | ≥ 60% |

## 3. 사용자 시나리오

### 시나리오 A — 정기 회의 (핵심 경로)

1. 회의 시작. 지훈은 주머니에서 폰을 꺼내지 않고 **우측 버튼을 두 번** 누른다. "녹음을 시작했습니다 🎙" 토스트 확인.
2. 회의에 집중한다. 필기하지 않는다.
3. 회의 종료. 다시 우측 버튼 두 번. "녹음 정지 — 회의록을 생성합니다" 토스트.
4. 2~3분 뒤 "회의록이 완성되었습니다 ✅" 알림. 탭하면 앱이 열린다.
5. 요약/결정 사항/액션 아이템을 확인하고 "공유"로 Slack 채널에 붙여넣는다.

### 시나리오 B — API 키 미설정 사용자

1. 키 설정 없이 녹음만 사용. 정지 시 녹음 파일만 저장되고, 알림으로 "전사 API 키를 등록하면 자동으로 회의록이 생성됩니다"를 안내받는다.
2. 설정에서 키 입력 후 다음 회의부터 전체 파이프라인 사용.

### 시나리오 C — 볼륨 키 보조 트리거

1. 제조사 사이드 키 리매핑이 불가능한 기기 사용자는 접근성 서비스를 켠다.
2. 화면이 켜진 상태에서 **볼륨 상(上) 키 두 번**으로 동일하게 토글한다.

## 4. 기능 요구사항

우선순위: **P0** = v1 필수 / **P1** = v1 포함, 실패 허용 / **P2** = 후속 버전

| ID | 요구사항 | 우선순위 | 상태 |
|---|---|---|---|
| TRG-1 | 사이드 키 두 번 누르기로 녹음 토글. 제조사 버튼 리매핑(갤럭시 사이드 키, 픽셀 빠른 탭)에 지정 가능한 무 UI 런처 항목("빠른 녹음 (회의록)") 제공 | P0 | ✅ `QuickRecordActivity` |
| TRG-2 | 토글 시 현재 상태를 토스트로 즉시 피드백 (시작/정지) | P0 | ✅ |
| TRG-3 | 볼륨 상 키 빠른 두 번 누르기로 토글 (접근성 서비스, 설정에서 on/off) | P1 | ✅ `SideKeyAccessibilityService` |
| TRG-4 | 볼륨 키 트리거는 기존 볼륨 조절 동작을 파괴하지 않는다 (이벤트 비소비) | P1 | ✅ |
| TRG-5 | 앱 내 화면의 녹음 시작/정지 버튼 | P0 | ✅ |
| TRG-6 | 마이크 권한 미보유 상태에서 트리거 시, 크래시 없이 메인 화면으로 유도 | P0 | ✅ |

## 5. 비기능 요구사항

| 분류 | 요구사항 |
|---|---|
| 성능 | 트리거 → 녹음 개시 2초 이내. 회의록 생성은 30분 녹음 기준 3분 이내 |
| 안정성 | 파이프라인 어느 단계가 실패해도 이전 단계 산출물(녹음/전사)은 보존. 처리 중 서비스 종료 시에도 녹음 파일 유실 금지 |
| 저장 | 앱 전용 저장소 사용 → 별도 저장소 권한 불필요. 파일명 규칙 `MTG_yyyyMMdd_HHmmss.*` |
| 보안·프라이버시 | 음성은 사용자가 지정한 전사 API로만, 전사문은 Anthropic API로만 전송. API 키는 기기 내 SharedPreferences에만 저장. 자사 서버 없음(서버리스 클라이언트 앱) |
| 권한 최소화 | RECORD_AUDIO, POST_NOTIFICATIONS, FOREGROUND_SERVICE(_MICROPHONE, _DATA_SYNC), INTERNET만 사용. 접근성 서비스는 키 입력 감지 전용이며 화면 내용을 읽지 않음 |
| 규정 준수 | 녹음 시작 시 명시적 피드백(토스트+상시 알림)으로 몰래 녹음 방지. 참석자 동의 안내 문구 제공. Play 스토어 접근성 서비스 정책에 따른 용도 고지 필요 |
| 호환성 | Android 8.0(API 26)+. 갤럭시(사이드 키), 픽셀(빠른 탭) 리매핑 검증 대상 |

## 6. 시스템 구성

```
[사이드 키 2번]──(제조사 리매핑)──▶ QuickRecordActivity ─┐
[볼륨 상 키 2번]──▶ SideKeyAccessibilityService ────────┼──▶ RecordingService (FGS)
[앱 내 버튼]────────────────────────────────────────────┘         │
                                                    녹음 m4a 저장 │ 정지 시
                                                                  ▼
                                    TranscriptionClient ──▶ Whisper 호환 API
                                                                  │ transcript.txt
                                                                  ▼
                                    MinutesClient ──▶ Claude API (claude-sonnet-5)
                                                                  │ minutes.md
                                                                  ▼
                                              완료 알림 + 앱 내 목록/공유
```

- 상태 공유: `RecorderState` (StateFlow) — 서비스 ↔ UI
- 저장: `MeetingStore` — `recordings/`, `minutes/` 디렉터리 관리
- 설정: `AppSettings` — SharedPreferences

## 7. 실패 처리 정책

| 상황 | 동작 |
|---|---|
| 전사 API 키 없음 | 녹음만 저장 + 키 등록 안내 알림 |
| Anthropic 키 없음 | 전사문 기반 간이 회의록 저장 + 안내 알림 |
| 전사/생성 API 오류 | 이전 단계 산출물 보존, 오류 내용 알림 (HTTP 코드 + 응답 요약) |
| 전사 결과 빈 문자열 | 녹음 보존, "전사 결과가 비어 있습니다" 안내 |
| 너무 짧은 녹음 | 파일 폐기, 오류 안내 (크래시 없음) |
| 백그라운드 FGS 시작 제한 | 예외 포착 후 상태 오류 표시 (크래시 없음) |
| 파이프라인 실패 후 | 기록 목록의 "재시도" 버튼으로 남은 단계부터 재실행 (전사문이 있으면 전사 생략, 재녹음 불필요). 분할 전사는 청크별 성공분을 보존해 실패한 조각부터 재개 |
| 재생성 시 키 미설정 | 기존 완성 회의록은 간이 회의록으로 덮어쓰지 않음 (다운그레이드 방지) |
| 녹음 시작 실패 | 토스트 + 시스템 알림으로 즉시 통지 (무확인 녹음 방지) |

## 10. 오픈 이슈

1. **백그라운드 마이크 정책 (실기기 검증 필수)**: Android 11+의 while-in-use 제한 때문에, 다른 앱을 보는 중(또는 화면 꺼짐)에 볼륨 키 트리거로 시작한 녹음은 **무음으로 저장될 수 있음**. 접근성 서비스가 면제 대상인지 문서상 불명확 — 실기기에서 반드시 확인하고, 안 되면 볼륨 키 트리거를 "화면 켜짐 + 본 앱/홈 화면" 조건으로 제한하는 방안 검토. (사이드 키 경유는 QuickRecordActivity가 잠깐 포그라운드가 되므로 안전)
2. ~~**장시간 녹음 업로드 한계**~~: ✅ 해결 — 20MB 초과 녹음은 10분 단위 자동 분할 업로드 (`AudioChunker`). 실기기 장시간 녹음 검증만 M2에 남음.
