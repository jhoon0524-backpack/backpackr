# PO 에이전트

기획 산출물을 만드는 스킬과, 그 스킬들이 참조하는 사실을 모아둔 곳.

```
po/context/     사실 — 사람이 관리한다
.claude/skills/ 작업 — 산출물 1개당 스킬 1개
```

## 왜 나눠져 있나

스킬 안에 회사 사실(수수료율·인력·기술 스택)을 적어두면 조직이 바뀔 때마다 스킬을 고쳐야 하고,
같은 사실을 쓰는 스킬이 늘어날수록 복사본이 늘어난다. 사실은 `context/`에 한 벌만 두고 스킬은 참조한다.

## context/ 관리 규칙

**1. 모든 파일에 기준일과 담당자를 단다.** 날짜 없는 사실은 6개월 뒤 조용히 거짓말이 된다.

**2. 모르는 건 비워두고 `[TODO: 담당자]`로 남긴다.** 그럴듯하게 채우면 그 위에서 쓴 PRD가 전부 틀린다.

**3. `decisions.md`는 사람만 쓴다.** 에이전트가 스스로 결정을 기록하기 시작하면 그 로그는 못 믿게 된다.
   에이전트는 대조만 한다 — "이 기획이 2026-07 결정과 충돌합니다"까지가 역할이다.

**4. 변경은 PR로 한다.** 컨텍스트 한 줄이 모든 PRD에 반영되므로 혼자 고치지 않는다.

## 쓰는 법

레포를 클론한 상태에서 Claude Code를 실행하면 `.claude/skills/`가 자동으로 잡힌다.

```
/prd 창작자가 정산 예정일을 미리 확인할 수 있게 하고 싶다
```

## 현재 상태 (2026-08-02)

**아직 레포에 편입된 스킬이 없다.** 스킬 실물이 여러 환경에 흩어져 있고 버전이 갈라진 상태다.
`context/`를 먼저 올린 이유는, 재패키징할 때 각 스킬에서 중복된 컨텍스트를 뽑아낼 기준이 필요해서다.

확인된 갈라짐 (두 환경에서 동일하게 구버전):

| 스킬 | 산출물 | 상태 |
|---|---|---|
| `prd` | PRD 1장 | **구버전** — 157줄, Step 2.5 게이트 리뷰 없음. v2로 교체 필요 |
| `validate` | 검증 리포트 | **구버전** — 집계 함정 taxonomy 병합 전 |
| `strategy-review` | 착수 게이트 판정 | **폐기 (2026-08-02)** — 편입하지 않는다 |
| `strategy-doc` | 전략 문서 갱신 | 개인 스킬로만 존재, 레포 이관 필요 |
| `plan-review` | 개발 계획 리뷰 | 미설치 |
| `weekly-report` | 주간 리포트 | 미설치 |
| `pre-prd` | PRD 전 정리 | 미설치 |
| `problem-discovery` | 문제 후보 | 미설치 |
| `diagnosis` | 진단 | 미설치 |
| `okr` | OKR | 미설치 |
| `handoff` | 개발 착수 문서 | 미구현 — `docs/prd/handoff.md`에서 역추출 예정 |
| `retro` | 출시 후 지표 대조 | 미구현 — 지표 접근 경로 확보 후 |

PO 업무가 아닌데 섞여 있는 것: `creator-trend-newsletter`, `tumblbug-trend-roulette` → 이관 대상.

## 정본이 어디인가

| 대상 | 정본 | 이유 |
|---|---|---|
| 스킬 · `context/` | **이 레포** | 에이전트 입력이다. 스킬과 함께 버전이 움직이고 PR 리뷰가 필요하다 |
| PRD · 기획 산출물 | **Notion** | 사람이 읽고 코멘트하는 문서다 |

겹치지 않는다 — **입력은 레포, 산출물은 노션.** `context/`의 사실을 Notion에도 적어두면 그 순간
갈라지므로, Notion에서는 레포를 링크로 참조한다.

## 재패키징 원칙

**결과물은 zip이 아니라 이 레포다.** zip은 누가 최신인지 알 수 없고, 두 환경에 각각 설치되는 순간
갈라진다. 지금 상태가 그 결과다. 팀 전체가 쓰면 인원 수만큼 갈라진다.

**한 번에 다 편입하지 않는다 — 쓸 때 하나씩 편입한다.** 12개를 3개 환경과 대조하는 비용은 크고,
실제로 손해가 나는 건 지금 돌리는 스킬뿐이다. 안 쓰는 스킬이 갈라져 있는 것은 손해가 아니다.
스킬을 다음에 쓸 때 그 스킬만 확정해서 커밋한다.

**내용을 새로 쓰지 않는다.** 흩어진 버전들이 담고 있는 게이트·taxonomy·필터는 대부분 한 번 실패해서
생긴 규칙이라 다시 앉아서 만들어지지 않는다. 갈라진 원인은 내용이 아니라 정본의 부재였다.

**오케스트레이터(라우팅 스킬)는 스킬 편입이 끝난 뒤에 넣는다.** 없는 스킬을 가리키면 오작동한다.
편입 완료 시 라우팅 테이블의 스킬명이 실제로 존재하는지 검사하는 CI를 함께 넣어 재발을 막는다.
