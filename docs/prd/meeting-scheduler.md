## PRD — 미팅 예약 링크 (사내 일정 조율 도구)

**문제 정의**
운영셀 3명(인원 축소 상태)은 심사 보완 상담, 신규 창작자 온보딩, 파트너십 미팅을 잡을 때마다 메일·카톡으로 가능 시간을 왕복 제안한다. 창작자는 텀블벅 계정과 무관한 채널에서 응답해야 하고, 담당자는 확정 전까지 캘린더를 수동으로 비워둔다. 내부 다자 회의(심사 리뷰 등)는 슬랙 스레드에 각자 가능 시간을 적는 방식이라 취합·확정이 주최자 수작업이다. 외부 SaaS(Calendly 등)는 유료이고 창작자 이름·연락처가 외부로 나가 개인정보 검토 부담이 있다.

**목표**
텀블벅 구성원이 예약 링크 하나로 창작자 1:1 상담과 내부 다자 회의 일정을 자체 서비스 안에서 확정한다.

**성공 지표**
| 지표 | 현재 값 | 목표 값 | 측정 방법 |
|---|---|---|---|
| 일정 확정 리드타임 (중앙값) — 분모: 생성된 예약 요청 수 / 분자: 요청 생성→확정 경과 시간 | 미측정 (릴리즈 전 2주간 운영셀 수기 기록으로 베이스라인 확보) | 24시간 이내 | `booking_request_created` / `booking_confirmed` 이벤트 → MySQL 집계, Datadog 커스텀 메트릭 대시보드 |
| 링크 확정 전환율 — 분모: 열람된 예약 링크 수 / 분자: 확정된 예약 수 | 미측정 | 60% | `booking_page_viewed` / `booking_confirmed` 이벤트 |
| (부작용) 노쇼·취소율 — 분모: 확정 예약 수 / 분자: 미팅 24시간 이내 취소 + 주최자 노쇼 처리 수 | 미측정 | 15% 이하 | `booking_canceled`(취소 시각 기준) + 주최자 노쇼 체크 |

**유저 스토리**
- 운영셀 담당자로서, 상담 일정 왕복을 줄이기 위해 내 가능 시간대가 담긴 예약 링크를 만들어 창작자에게 보내고 싶다.
- 창작자로서, 별도 가입 없이 링크에서 내 시간대 기준으로 가능 시간을 골라 상담을 확정하고 싶다.
- 심사 리뷰 주최자로서, 참석자 가능 시간을 한 화면에서 보기 위해 그리드형 조율 링크를 만들고 싶다.
- 회의 참석자로서, 응답 부담을 줄이기 위해 그리드에서 드래그로 가능 시간을 표시하고 싶다.
- 주최자로서, 확정 후 별도 캘린더 등록을 하지 않기 위해 확정 즉시 구글 캘린더에 일정이 생기길 원한다.

**기능 명세**

*예약 페이지 설정 (1:1) — P0*
- 구성원이 예약 유형을 생성하면 미팅명·소요시간(15/30/60분)·요일별 운영시간·최소 예약 리드타임(기본 4시간)·최대 예약 가능 기간(기본 14일)을 저장한다.
- 예약 유형이 저장되면 `/booking/{slug}` 공개 URL을 발급하고 슬러그 중복 시 재발급한다.
- 구성원이 링크를 비활성화하면 이후 열람자에게 "예약 마감" 화면을 노출하고 기존 확정 예약은 유지한다.

*슬롯 조회·예약 (1:1) — P0*
- (P1) 방문자가 예약 페이지에 진입하면 브라우저 타임존을 감지해 해당 타임존 기준으로 슬롯을 표시하고, 타임존은 직접 변경할 수 있다. P0에서는 KST 고정 표기.
- 운영시간에서 이미 확정된 예약과 리드타임 미달 구간을 제외한 나머지를 예약 가능 슬롯으로 계산한다. (P1) 연동 캘린더의 바쁨(busy) 구간을 추가로 제외한다.
- 방문자가 슬롯을 선택하면 이름·이메일·연락처(선택)·문의 내용을 입력받고 개인정보 수집 동의를 받은 뒤 예약을 확정한다.
- 예약 확정 요청이 들어오면 슬롯 단위 Redisson 분산 락을 획득한 뒤 중복 여부를 재검증하고, 실패 시 슬롯을 즉시 회색 처리하며 재선택을 요청한다.
- 예약자가 확정 메일의 토큰으로 접근하면 미팅 시작 2시간 전까지 취소할 수 있다. (P1) 동일 조건에서 다른 슬롯으로 1회 변경할 수 있다.

*그룹 가능시간 조율 (N:N) — P1*
- 주최자가 조율 이벤트를 생성하면 후보 날짜 범위(최대 14일)·시간 범위·30분 단위 그리드를 생성한다.
- 참석자가 그리드에서 드래그로 가능 시간을 표시하면 이름 기준으로 응답을 저장하고, 같은 이름으로 재진입 시 기존 응답을 수정한다.
- 응답이 저장되면 셀별 가능 인원 수를 히트맵 농도로 표시하고 셀 hover 시 가능/불가 인원 명단을 보여준다.
- 주최자가 특정 셀을 확정하면 해당 시간으로 미팅을 생성하고 전체 응답자에게 확정 알림을 발송한다.

*캘린더 연동 — P1 (OAuth 앱 검증 승인 시)*
- 구성원이 구글 캘린더를 연동하면 읽기(freebusy)·쓰기(events) 스코프 토큰을 저장하고, 슬롯 계산 시 freebusy를 조회해 바쁜 구간을 제외한다.
- 미팅이 확정되면 주최자 캘린더에 이벤트를 생성하고 예약자 이메일을 참석자로 초대한다.
- 캘린더 API 호출이 실패하면 예약 자체는 확정 처리하고 에러를 기록한다. (P2) 연동 실패를 미팅 상세에 배지로 표시하고 최대 3회 재시도한다.

*알림 — P0*
- 예약이 확정·변경·취소되면 RabbitMQ로 알림 이벤트를 발행하고, 기존 텀블벅 알림 모듈(AWS SNS)을 통해 주최자·예약자에게 메일을 발송한다.
- (P1) Quartz 배치가 10분 주기로 실행되어 미팅 시작 24시간 전·1시간 전 대상 예약에 리마인더를 발송하고, 발송 이력으로 중복 발송을 차단한다.
- (P2) 조율 이벤트 생성 후 48시간 동안 응답이 0건이면 주최자에게 독려 알림을 1회 발송한다.

**범위**

*P0 — MVP (2 스프린트 / BE 1.5 · FE 1 · 디자인 0.5)*
운영셀이 캘린더 연동 없이도 예약 왕복을 없앨 수 있는 최소 단위. 구글 OAuth 검증 결과와 무관하게 단독 릴리즈 가능해야 한다.
- 1:1 예약 유형 생성/수정/삭제(운영시간 수동 설정, 삭제 시 미래 확정 예약 있으면 차단)
- 공개 예약 페이지(비로그인, SSR) + 슬롯 계산(운영시간 − 기확정 예약 − 리드타임)
- Redisson 분산 락 기반 동시 예약 방지
- 예약 확정 + 개인정보 수집 동의
- 확정/취소 메일 발송(RabbitMQ → 기존 SNS 알림 모듈)
- 예약자 취소(미팅 2시간 전까지), 주최자 취소
- 모바일 웹 반응형
- 이벤트 로깅 + Datadog 대시보드(성공 지표 3종 측정 가능 상태)

*P1 — 조율·연동 (2 스프린트 / BE 1.5 · FE 1 · 디자인 1)*
P0 배포 후 리드타임 지표를 확인하고 착수. 그리드 조율은 캘린더 블로커와 독립이므로 OAuth 검증이 지연돼도 진행한다.
- N:N 그리드 조율(이벤트 생성, 드래그 응답, 히트맵, 셀 확정) — tumblbug-ui 신규 컴포넌트 2종 포함
- 구글 캘린더 연동: freebusy 조회로 busy 구간 제외 + 확정 시 이벤트 생성/참석자 초대 — **OAuth 앱 검증 승인 후 착수**
- Quartz 리마인더 배치(24시간 전 / 1시간 전)
- 예약자 일정 변경(1회)
- 방문자 타임존 자동 감지 및 수동 변경

*P2 — 운영 안정화 (1 스프린트 / BE 1 · FE 0.5)*
운영셀 3명 체제에서 장애·이탈 상황을 사람 손으로 수습하지 않게 만드는 범위. P1 운영 데이터에서 실제 발생 빈도를 확인한 뒤 착수 여부를 재판단한다.
- 관리자 화면: 담당자 이관, 미발송 알림 목록, 연동 실패 미팅 조회
- 캘린더 연동 실패 재시도/실패 배지, 알림 DLQ 재처리
- 조율 이벤트 응답 0건 독려 알림, 후보 기간 만료 처리

*OUT (전 페이즈)*
창작자 계정 로그인 연동, 결제·유료 상담, 반복 일정, 라운드로빈/팀 풀 배정, iOS·Android 네이티브 화면, Zoom/Meet 자동 회의실 생성(주최자 URL 수동 입력), Algolia 검색 연동, 아웃룩·애플 캘린더, 예약 페이지 외부 공개 검색 노출.

**엣지케이스**
| 카테고리 | 케이스 | 예상 동작 |
|---|---|---|
| 유저 행동 | 두 방문자가 같은 슬롯을 동시에 확정 | 분산 락 선점자만 확정, 후순위는 "방금 마감된 시간입니다" 안내 후 슬롯 목록 갱신 |
| 유저 행동 | 예약자가 미팅 1시간 전 취소 시도 | 변경/취소 차단, 주최자 직접 연락 안내 문구 노출 |
| 유저 행동 | 그리드 응답 중 이탈 후 다른 기기로 재진입 | 동일 이름 입력 시 기존 응답 불러오기, 이름 다르면 신규 응답으로 취급 |
| 유저 행동 | 예약자·주최자 타임존 불일치 (해외 창작자) | 양측 메일에 각자 로컬 시각 + UTC 오프셋 병기 |
| 데이터 | 운영시간 설정 후 이미 잡힌 예약이 운영시간 밖으로 벗어남 | 기존 예약 유지, 설정 저장 시 "기존 예약 N건은 유지됩니다" 경고 표시 |
| 데이터 | 주최자 계정 비활성화/퇴사 처리 | 링크 즉시 비활성, 미래 확정 예약은 운영셀 관리자 화면에서 담당자 이관 가능 |
| 데이터 | 조율 이벤트 응답자 0명 상태로 후보 기간 종료 | 이벤트 만료 처리, 주최자에게 재생성 링크 안내 |
| 외부 시스템 | 구글 OAuth 토큰 만료·권한 철회 | 슬롯 계산에서 캘린더 제외(운영시간만 사용), 주최자에게 재연동 요청 메일 발송 |
| 외부 시스템 | 구글 캘린더 API rate limit(429) | 지수 백오프 3회 재시도, 최종 실패 시 Sentry/Datadog 에러 이벤트 기록 후 연동 실패 배지 |
| 외부 시스템 | SNS 메일 발송 실패 | RabbitMQ DLQ 적재 후 3회 재시도, 최종 실패 시 관리자 화면에 미발송 목록 노출 |

**인수 조건**
- [ ] (P0) 예약 유형 생성 시 소요시간·운영시간·리드타임·예약 가능 기간이 모두 저장되고, 공개 URL 진입 시 설정대로 슬롯이 계산된다.
- [ ] (P0) 이미 확정된 슬롯이 예약 가능 슬롯에서 제외된다.
- [ ] (P0) 동일 슬롯 동시 요청 100건을 부하 테스트했을 때 확정 예약이 정확히 1건이며 나머지는 409로 응답한다.
- [ ] (P0) 예약 확정/취소 시 주최자·예약자 양측에 메일이 각 1회 발송되고, 재시도로 인한 중복 발송이 없다.
- [ ] (P0) 예약 유형 삭제 시 미래 확정 예약이 있으면 차단되고 사유가 안내된다.
- [ ] (P0) 비로그인 예약 페이지에서 개인정보 수집 동의 없이 확정이 불가하다.
- [ ] (P0) 로깅: `booking_page_viewed`, `booking_request_created`, `booking_confirmed`, `booking_canceled`(취소 시각·주체 포함), `slot_conflict`, `notification_failed`를 이벤트 테이블에 적재하고 Datadog 대시보드에서 성공 지표 3종이 조회 가능하다.
- [ ] (P1) 연동 캘린더의 busy 구간이 예약 가능 슬롯에서 제외되고, 확정 시 주최자 캘린더에 이벤트가 생성된다.
- [ ] (P1) 캘린더 연동이 실패해도 예약은 확정되고 `calendar_sync_failed`가 기록된다.
- [ ] (P1) 리마인더 배치가 24시간 전·1시간 전 각 1회 발송하며, 배치 재실행 시 중복 발송되지 않는다.
- [ ] (P1) 그리드 응답 저장 후 히트맵 농도와 셀별 가능/불가 명단이 응답 데이터와 일치한다.
- [ ] (P1) 주최자가 셀을 확정하면 미팅이 생성되고 전체 응답자에게 확정 알림이 발송된다. `booking_changed` 로깅 포함.
- [ ] (P2) 관리자 화면에서 담당자 이관·미발송 알림 재발송이 가능하고, 연동 실패 미팅에 배지가 표시된다.

**의존성**
- BE: `core` 신규 도메인(booking, availability, poll) + `api` 공개 엔드포인트, `batch`(Quartz 리마인더/만료 처리), Redisson 분산 락, RabbitMQ 알림 이벤트, 기존 알림 모듈(AWS SNS) 재사용. Algolia 미사용.
- FE: Next.js 13.5 — 공개 예약 페이지는 SSR(비로그인 진입·초기 슬롯 렌더), 슬롯 선택/그리드 드래그는 CSR. tumblbug-ui에 시간 그리드·타임슬롯 피커 컴포넌트가 없어 **신규 컴포넌트 2종 개발 필요(디자인 2명 리소스 선점)**.
- 외부: Google Calendar API(OAuth 2.0, freebusy·events 스코프) — GCP 프로젝트 발급 및 앱 검증 필요.
- 사내: 구성원 인증은 기존 `admin` 모듈 계정 재사용(별도 SSO 구축 없음).

- [개발 블로커] 구글 캘린더 OAuth 민감 스코프 앱 검증 및 개인정보 처리방침 갱신 주체 미정 — P1 캘린더 연동 착수 조건. P0는 이 블로커와 무관하게 진행하도록 범위를 잘랐으나, P1 진입 시점까지 미승인이면 캘린더 연동만 P2로 밀고 그리드 조율을 먼저 릴리즈한다.
- [개발 블로커] 창작자 대상 예약 링크 노출 채널 미정(심사 결과 메일 본문 삽입 vs 창작자센터 배너). 메일 본문 삽입이면 기존 심사 알림 템플릿 수정이 선행되어야 한다.
