# AI 결과물 검증 프롬프트

AI가 짜놓은 결과물을 사람이 검증할 때 쓰는 프롬프트 모음. 아래 블록은 그대로 복사해서 쓴다.

---

## 1. 개발 전 평가 기준(DoD) 수립 및 검수

AI가 이미 짜놓은 코드에 맞춰 기준을 만드는 편향을 막는다. **개발을 시작하기 전에** 기준을 먼저 정의한다.

### 1-1. 사전 평가 기준 작성 요청

```
[작성할 기능/앱 명칭] 작성을 시작하기 전에, 이 작업이 완전히 완성되었다고 판단할 수 있는 조건 10가지를 작성해 줘.

[작성 규칙]
1. 각 조건은 내가 직접 확인했을 때 통과/불통과(Pass/Fail)가 명확히 갈리도록 작성할 것.
2. "에러 처리가 잘 되어 있다"와 같은 추상적인 표현은 제외하고, 즉시 확인 가능한 명시적/정량적 조건으로 작성할 것. (예: "비밀번호 미입력 상태로 로그인 버튼 클릭 시 빨간색 경고 문구 노출")
```

### 1-2. 검수 진행 요청 — 새 창 / 서브 에이전트 전용

대화 맥락이 없는 새 창에 코드 파일과 위에서 만든 평가 기준 파일(`DoD.md` 등)을 함께 첨부해 실행한다.

```
첨부된 [코드 파일/변경사항]과 [평가 기준 파일]을 대조하여 검수해 줘.
조건을 하나씩 체크하고, 지켜지지 않았거나 미흡한 항목만 짚어서 목록으로 작성해 줘.
```

---

## 2. 맥락 없는 서브 에이전트 / 타사 모델 검수

개발한 창에 검수를 맡기지 않는다. 이전 대화 기록이 없는 새 세션이나 타사 AI 모델에 검수만 전담시킨다.

```
아래 [변경 사항 / 코드 파일]을 처음 보는 외부 검수자 관점에서 객관적으로 리뷰해 줘.

[검수 규칙]
1. 코드를 직접 수정하거나 고치지 말고, 발견된 문제점 및 개선점의 '목록'만 작성해 줘.
2. 예외 처리 누락, 로직상의 허점, 성능/보안 이슈 위주로 엄격하게 검토할 것.
(※ 수정 작업은 문제 목록 정리 후 원래 대화창에서 진행할 예정임)
```

---

## 3. 맥락 분리 및 이해를 위한 시각화 — `/branch`

개발 작업용 창과 별개로, 기존 맥락을 복사해 간 새 대화창(branch)에서 현재 구조와 진행 상황을 파악한다.

```
지금까지 진행된 작업 내용과 시스템 구조를 내가 한눈에 이해하고 검토할 수 있도록, 시각화되고 상호작용 가능한 HTML 형식의 UI/대시보드로 정리해서 만들어 줘.
```

---

## 4. 컨텍스트 요약 및 이관 — `/compact`

대화창이 꽉 차 새로 열어야 할 때, 후속 검수와 개발에 필요한 핵심 정보가 뭉개지지 않도록 구조화해 요약한다.

```
/compact
다음 세션으로 작업 맥락을 이관하기 위해 지금까지의 대화를 요약해 줘.
단, 아래 양식을 반드시 준수하여 핵심 내용만 정제할 것.

1. [완료된 작업 목록]
2. [미완료 / 남아있는 작업 목록]
3. [실행한 주요 명령어 및 그 결과]
4. [작업 중 발견된 주요 문제 및 다음 세션에서 필수적으로 알아야 할 맥락]
```
