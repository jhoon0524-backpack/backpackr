# agent-starter

AI 코딩 에이전트와 오래 일하기 위한 파일 네 장. 새 서비스 프로젝트에 복사해서 쓴다.

## 왜 필요한가

AI 는 세션이 끝나면 전부 잊는다. 그래서 기억을 대화가 아니라 파일에 둔다.
네 장이 각각 다른 질문에 답한다.

| 파일 | 답하는 질문 | 바뀌는 빈도 |
|---|---|---|
| `SPEC.md` | 무엇을 만드는가 | 거의 안 바뀜 |
| `CLAUDE.md` | 어떻게 일하는가 | 거의 안 바뀜 |
| `TASKS.md` | 지금 무엇을 하는가 | 가끔 |
| `PROGRESS.md` | 어디까지 왔는가 | 매 세션 |

## 쓰는 법

```
sh install.sh ../my-new-service
```

이미 있는 파일은 덮어쓰지 않는다. 복사한 뒤 순서대로 채운다.

1. **`CLAUDE.md` 3장 검증 명령** — 가장 먼저. 이게 비어 있으면 나머지가 무의미하다
2. **`CLAUDE.md` 4장 승인 필요 동작** — 이 프로젝트에서 되돌릴 수 없는 것
3. **`SPEC.md`** — 무엇을 만드는지. 숫자로 적는다
4. **`TASKS.md`** — 앞의 스무 개만 구체적이면 된다

## 매일 돌리는 법

새 대화를 열고 이 한 줄을 던진다.

```
CLAUDE.md 규칙에 따라 PROGRESS.md를 읽고 다음 작업 1개만 실행해
```

작업 하나에 대화 하나. 대화를 길게 끌면 AI 가 앞에 정한 것을 잊는다.

## 서비스에서 특히 중요한 두 가지

**검증 명령이 이 킷의 심장이다.** 그림이나 게임 화면과 달리 서비스는
`test`, `lint`, `typecheck` 로 결과를 기계가 판정할 수 있다.
AI 가 스스로 돌리고 스스로 고칠 수 있어서 사람 없이 한 바퀴가 완결된다.
`CLAUDE.md` 3장을 정확히 채우는 것이 이 킷을 쓰는 이유의 절반이다.

**되돌릴 수 없는 동작은 코드를 쓰게 하고 실행은 사람이 한다.**
마이그레이션, 배포, 메일 발송, 결제. `CLAUDE.md` 4장에 프로젝트별 항목을 추가한다.

## 팀에서 쓸 때

`PROGRESS.md` 는 매 세션 바뀌므로 여러 명이 동시에 고치면 git 충돌이 잦다.

- 혼자 하는 프로젝트 → 그대로 쓴다
- 팀 프로젝트 → PR 설명과 이슈가 `PROGRESS.md` 역할을 하게 하고, 이 파일은 브랜치별로 두거나 뺀다

## 규칙을 추가할 때

`CLAUDE.md` 에 새 규칙을 쓰기 전에 항상 묻는다.

> 이걸 어긴 걸 어떻게 알지?

답이 없으면 그건 규칙이 아니라 소망이다. 검사 명령을 함께 만들어 3장에 넣는다.
