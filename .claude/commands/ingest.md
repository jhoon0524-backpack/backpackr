# /ingest

날짜가 필요하면 `date +%Y-%m-%d`로 확인한다. 추측하지 않는다.

## 1. 대상 정하기

1. `99_system/processed.md`를 **먼저** 읽는다.
2. `00_raw/`의 파일 목록을 본다 (`00_raw/assets/`는 소스가 아니므로 제외).
3. processed.md에 없는 파일만 대상이다. 하나도 없으면 "미처리 소스 없음"이라고 말하고 끝낸다.
4. 인자로 파일명이 주어지면 그것만. 미처리 파일이 여럿이면 목록을 보여주고 하나씩 처리한다.

## 2. 읽기

- 소스를 끝까지 읽는다.
- 본문이 이미지를 참조하면 `00_raw/assets/`의 해당 파일을 따로 열어본다.
- `99_system/index.md`를 읽어 이미 있는 페이지를 파악한다. 겹치는 페이지는 본문도 읽는다.

## 3. 보고 후 승인 대기 — 반드시 여기서 멈춘다

페이지를 쓰기 전에 아래를 보고하고 승인을 받는다. **승인 전에는 어떤 파일도 만들거나 고치지 않는다.**

- 핵심 takeaway 3~7개
- 새로 만들 페이지: 제목 + `type` + 왜 독립 페이지여야 하는지
- 고칠 기존 페이지: 제목 + 무엇을 어떻게 바꿀지
- 기존 위키와 상충하는 내용이 있으면 어느 페이지의 어떤 주장과 부딪히는지 명시

승인이 없으면 4단계로 넘어가지 않는다.

## 4. 페이지 쓰기 (승인 후)

**새 페이지 vs 기존 수정**

- 다른 페이지에서 링크 걸 만한 독립 개체 → 새 페이지
- 이미 있는 개체의 속성·근황·추가 사례 → 기존 페이지 제자리 수정
- 애매하면 기존 수정. 나중에 쪼개는 게 합치는 것보다 쉽다.

**규칙**

- 소스마다 `type: source` 요약 페이지를 1개 만든다. `sources:`에는 그 원문 하나만 적는다.
- `wiki/` 아래 하위 폴더를 만들지 않는다.
- 내용을 고친 페이지는 `updated:`를 오늘 날짜로 바꾼다.
- frontmatter는 CLAUDE.md의 스키마를 그대로 따른다.
- 기존 페이지의 주장을 새 소스가 뒤집으면 지우지 말고, 바뀐 내용과 각각의 근거 원문을 병기한다.

## 5. 상호링크

- 새 페이지는 최소 1개의 기존 페이지에서 링크가 걸려야 한다. 고아로 두지 않는다.
- 본문에서 언급한 개체 중 페이지가 있는 것은 `[[링크]]`로 건다.
- 양쪽 `related:`를 맞춘다. 한쪽만 걸린 링크를 남기지 않는다.

## 6. 기록

- `99_system/index.md` — 새 페이지를 해당 type 섹션에 추가. 요약이 달라진 페이지는 갱신.
- `99_system/log.md` — 맨 아래에 추가:
  ```
  ## [YYYY-MM-DD] ingest | 소스 제목
  - 생성: [[페이지A]], [[페이지B]]
  - 수정: [[페이지C]] — 무엇이 바뀌었는지 한 줄
  ```
- `99_system/processed.md` — 맨 아래에 `- 00_raw/파일명 — YYYY-MM-DD` 한 줄 추가.

## 7. 마무리

바꾼 파일 목록을 보고한다. 3단계에서 승인받은 계획과 달라진 게 있으면 무엇이 왜 달라졌는지 밝힌다.
