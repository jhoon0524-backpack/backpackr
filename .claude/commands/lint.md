# /lint

날짜가 필요하면 `date +%Y-%m-%d`로 확인한다.

## 점검 항목

1. **모순** — 서로 다른 페이지가 같은 사실을 다르게 말하는 곳.
2. **뒤집힌 주장** — 나중에 들어온 소스가 기존 주장을 부정하는데 기존 페이지가 그대로인 곳.
3. **고아 페이지** — 어느 페이지에서도 `[[링크]]`가 걸리지 않은 페이지. `index.md`의 목록은 인바운드 링크로 치지 않는다.
4. **빠진 페이지** — 여러 페이지에서 언급되는데 자기 페이지가 없는 개체·개념.
5. **빠진 상호참조** — A가 B를 링크하는데 B의 `related:`에 A가 없는 경우. 본문에서 언급만 하고 링크는 안 건 경우.
6. **깨진 링크** — `[[X]]`인데 `wiki/X.md`가 없음.
7. **스키마 위반** — frontmatter 필드 누락, `type`이 enum(`entity|concept|synthesis|source`) 밖, `wiki/` 하위 폴더, `sources:`에 실재하지 않는 `00_raw/` 경로, `title`과 파일명 불일치.

## 하지 말 것

- **날짜만 보고 stale 판정하지 않는다.** `updated:`가 오래됐다는 이유로 문제 삼지 않는다. 낡은 페이지와 틀린 페이지는 다르다.
- 내용을 임의로 고치거나 다시 쓰지 않는다.
- 페이지를 지우지 않는다. 삭제를 제안하지도 않는다.

## 자동 수정 (승인 없이 해도 됨)

기계적인 링크 오류만:

- 한쪽만 걸린 `related:` 양방향으로 맞추기
- 파일명과 링크 표기의 대소문자·띄어쓰기 불일치
- frontmatter 필드 누락 중 파일에서 확정 가능한 것 (`title`은 파일명에서, `sources`는 본문에 명시된 경우에만). `type`은 추측하지 않는다.

## 제안만 (확인 필요)

내용에 관한 것은 전부 보고하고 승인을 받는다:

- 모순, 뒤집힌 주장 → 어느 쪽이 맞는지 근거 원문과 함께 제시하고 어떻게 고칠지 제안
- 빠진 페이지 → 만들 후보와 `type`
- 고아 페이지 → 어느 페이지에서 링크를 걸면 되는지 제안
- 본문 링크 추가 → 어느 문장에 어떤 링크를 걸지

## 결과

- 항목별 건수와 목록. **자동 수정한 것**과 **제안만 한 것**을 나눠서 보고한다.
- 문제 없으면 "이상 없음"이라고만 한다.
- `99_system/log.md`에 `## [YYYY-MM-DD] lint | 자동수정 N건, 제안 M건` 추가.
