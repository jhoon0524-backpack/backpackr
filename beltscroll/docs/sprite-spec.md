# 정식 캐릭터 스프라이트 규격 (교체용)

지금 게임 속 캐릭터는 `art.js` 가 코드로 그린 **임시 전투 스프라이트**다. 정식 스프라이트 시트(PNG)를 아래 규격대로 만들어 `data/sprites.js` 에 한 줄 적으면, 게임 코드를 고치지 않고 그 캐릭터 그림만 바뀐다. 판정·이동·타격감 숫자는 그림과 무관하게 그대로다.

## 아트 기준
`assets/reference/` 의 설정화 7장이 공식 아트 스타일 기준이다. 윤무겸은 `03_yun_mugyeom.webp`(3면도·주요 색상·장비 디테일)에 맞춘다.

## 시트 규격
- 투명 배경 PNG 한 장. 모든 칸(프레임)은 같은 크기 (예: 128×128).
- 캐릭터는 **오른쪽을 보는 방향**으로만 그린다 (왼쪽은 게임이 뒤집는다).
- 모든 칸에서 **발 기준점이 같은 자리**에 와야 한다 (`footX`, `footY`). 발 기준점 = 그림자 중심이 놓이는 바닥선 위의 몸 중심. **발바닥은 이 바닥선 아래로 3px 까지 내려 그린다** (지금 코드 그림과 같은 관례 — 시트와 코드 그림, 주인공과 적의 발 높이가 맞게. 예: 칸 128px·발바닥 아래끝 124 → `footY` 121). 점프 칸도 발 기준점은 같은 자리이고, 높이는 게임이 올린다.
- 칸 배치는 자유 (가로 한 줄, 여러 줄 모두 가능). 어느 칸이 어느 동작인지는 `data/sprites.js` 에 [열, 행] 으로 적는다.
- 크기: 지금 임시 윤무겸의 화면 키는 111px (상투 포함, 실측). 원귀 78px, 도깨비 117px (윤무겸보다 위압적으로, 오너 결정). `scale`(시트 1px 를 화면 몇 px 로)로 맞춘다. 예: 128px 칸에 키 111px 로 그렸으면 `scale: 1`.

### 선택 칸 (주인공 잡기용 맨손 4 + 점프 공격 1, 적 달려들기 2)
| 이름 | 쓰이는 때 | 없으면 (칼 든 캐릭터의 잡기 4칸·`airKick` 은 맨손 코드 그림, 아래 문단) |
|---|---|---|
| `hold` | 적을 붙잡고 있음 | 시트의 `punch` 칸 |
| `knee` | 붙잡고 무릎치기 | 시트의 `stomp` 칸 |
| `throwPrep` | 던지기 준비 | 시트의 `windup` 칸 |
| `throw` | 던진 직후 | 시트의 `punch2` 칸 |
| `airKick` | 점프 공격 (발차기, 사거리 적 중심 50px) | 시트의 `kick` 칸 |
| `rush0`, `rush1` | (적) 공격 직전 달려들기 2장 — 팔은 예고 자세로 당긴 채 앞으로 숙여 뜀 | 시트의 `windup` 칸 |
| `kickPrep` | (주인공) 3타 전용 준비 — 상체·어깨를 뒤로 당김 (3타 준비 구간에만, 2026-10-28) | 시트의 `windup` 칸, 그것도 없으면 코드 그림 `windup` |
| `kickRecover` | (주인공) 3타 전용 회수 — 칼을 거두며 기본 자세로 (3타 회수 구간에만) | 시트의 `idle0` 칸, 그것도 없으면 코드 그림 `idle0` |

칼을 쓰는 캐릭터는 `punch` 등 공격 칸에 칼을 들고 있으므로, 잡기 중에도 칼이 보이지 않게 하려면 잡기 4칸을 **맨손으로**, 점프 공격 `airKick` 은 **발차기로** 따로 그린다 (`kick` 칸은 3타 칼 찌르기).

빠진 칸은 코드 그림(임시)이 대신 쓰인다 (선택 칸은 위 표의 시트 칸이 먼저). 단 **칼 든 캐릭터(윤무겸)의 잡기 4칸·`airKick` 이 시트에 없으면 시트의 칼 든 칸이 아니라 맨손 코드 그림**을 쓴다 — 잡는 동안 칼이 보이거나 점프 공격이 찌르기로 보이지 않게 (2026-10-28 P1 시범에서 바꿈). 흰 번쩍임(맞을 때)은 게임이 자동으로 만든다.

## data/sprites.js 에 적는 법
```js
BB_DATA.sprites = {
  "mugyeom": {
    "src": "assets/sprites/mugyeom.png",
    "frameW": 128, "frameH": 128,
    "footX": 64, "footY": 121,
    "scale": 1,
    "face": [44, 8, 40, 40],
    "height": 111,
    "frames": { "idle0": [0, 0], "idle1": [1, 0], "walk0": [2, 0], "walk1": [3, 0], "walk2": [4, 0], "walk3": [5, 0],
                "windup": [0, 1], "punch": [1, 1], "punch2": [2, 1], "kick": [3, 1], "jump": [4, 1], "stomp": [5, 1],
                "hurt": [0, 2], "down": [1, 2] }
  }
};
```
- 적 시트를 바꿀 때는 걷는 그림 실루엣의 몸 앞끝(뻗은 주먹 제외)을 재서 `data/enemies.js` 의 `hurtHalfWidth` 와 맞춘다 (지금 원귀·도깨비 27px). 칼이 그림에 닿았는데 안 맞는 일이 없게.
- 가드 주먹 판정 (2026-10-28 오너 결정): 서 있기·걷기 칸에서 몸 앞끝 밖으로 나온 주먹은 칼날이 겹치면 맞는다. 지금은 코드 그림이 주먹·칼날 위치를 함께 기록해 쓰므로(`ART.hitShapes`), **시트로 바꾸면 판정은 여전히 코드 그림의 주먹·칼날 자리**다 (지금 도깨비 주먹 몸 중심 앞 12~36px, 원귀는 몸 앞끝 안). P1 에서 시트에 칸별 주먹 사각형(`idle0`~`walk3`)과 칼날 칸을 적는 칸을 더하고, `tests/fists.js` 로 경계를 다시 잰다 — 시트의 주먹·칼날이 코드 그림과 3px 넘게 다르면 그 전까지 판정과 그림이 어긋난다.
- 이름(`mugyeom`)은 art.js 의 캐릭터 이름 (주인공 `mugyeom`, 적은 `data/enemies.js` 의 art: `wongwi`·`dokkaebi`).
- `height`: 화면 키 px (맞을 때 불꽃·적 체력바 높이에 씀, 판정과 무관). 없으면 코드 그림 키. `downHeight`: 누운 그림 높이 px (누운 적 추가타 불꽃 높이), 없으면 코드 그림 값.
- `face`: HUD 얼굴 사진으로 쓸 영역 [x, y, 너비, 높이] (idle0 칸 기준). 없으면 코드 그림 얼굴.
- 발 높이: 위 "시트 규격"대로 발바닥 아래끝은 `footY` 보다 3px 아래 (코드 그림과 같은 관례). `tests/sheets.js` 의 발바닥 높이가 코드 그림과 같아야(−3) 칸이 바뀌거나 적과 나란히 서도 발이 튀지 않는다.
- 그림 파일을 못 불러오면 코드 그림 그대로 (게임은 멈추지 않음).
- 확인: `node tests/sprites.js` (가짜 시트로 교체·빠진 칸·파일 없음 경우를 잰다), `node tests/sheets.js` (지금 적힌 시트 실측: 반투명 테두리 0, 발바닥 높이, 키, 1·2·3타 칼끝 vs 판정 57px·칼끝 높이, 3타 칼날 길이, 3타 준비 → 찌르기 상체 이동, 도깨비 펀치 끝 ≤ 52px).
