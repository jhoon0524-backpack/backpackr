# 5단계 — 소리 비교 설계와 상태 겹침 점검표

지시(plan.md 5단계): WebAudio로 합성한 타격음 1종(normal·heavy 피치·길이만 다르게). 기본 꺼짐, `M` 키로 켜고 끈다. 오디오 파일을 쓰지 않는다.
실무자 추가: 휴대폰엔 M 키가 없어 전체화면 버튼 옆에 소리 버튼(🔇/🔊) 1개. 켤 때 확인용으로 normal 타격음 1번.

## 소리 (숫자는 `index.html` 의 `SOUND` 한 곳)
- 구성(1종): 낮은 사인파 "퍽"(음높이가 빠르게 떨어짐) + 짧은 잡음 "탁"(음높이에 맞춘 대역 필터). 시작 2ms 만에 최대, 지수로 사라짐.
- normal: 음높이 220Hz, 길이 0.09초 / heavy: 음높이 110Hz, 길이 0.20초. 그 밖의 값은 같다.
- 어떤 타격이 어떤 소리인지는 타격감(`FEEL`)을 따른다 → `impact()` 한 곳에서 낸다. F 키로 타격감을 강제하면 소리도 따라간다.

## 상태 겹침 점검표

| 새 상태 | 설정 / 진행 / 비움 | 그 상태 중 입력 | 겹침 처리 | 증명 |
|---|---|---|---|---|
| 소리 켜짐 `debug.sound` | M 키(키 누름 이벤트에서 바로) 또는 소리 버튼 / — / 다시 누르면 꺼짐. 재시작(reset)해도 유지 | 게임 입력과 무관 (M 은 조작 키와 안 겹침) | 타이틀·게임오버·클리어 화면에서도 전환됨 / 세로 일시정지 중엔 타격이 없어 소리도 없음 / 0.25배속(G)에서도 소리는 실제 속도 | sound #1, #2 |
| 오디오 장치 `audio` | 처음 켤 때 만들고 깨움(브라우저 자동 재생 규칙: 사용자 입력 안에서) / — / 안 지움 | — | 만들 수 없는 브라우저면 소리 버튼 숨김, 게임은 그대로 | sound #3 |
| 이번 프레임 소리 `pendingSound` | 타격 순간(`impact`)에 모으기만 함, 이미 heavy면 그대로 / update() 끝에서 1번 내고 비움 / reset() 에서도 비움 | — | 한 프레임에 여러 적을 맞혀도 순서와 상관없이 가장 센 것 1개 / 프레임 번호(time)를 저장하지 않으므로 재시작으로 time 이 0이 돼도 영향 없음 / 켤 때 확인음은 모으지 않고 바로 / 히트스톱 중엔 새 타격이 없음 | sound #4, sound3 |
| 소리 버튼 | 항상 보임(PC·휴대폰) / — / — | 클릭·탭 | 버튼에 포커스가 남으면 Enter 가 버튼을 누르므로 누른 뒤 blur (전체화면 버튼과 같은 처리) / 전체화면 중에도 게임 화면 안 | sound #5, combo |

## 진동 (오너 요청, 2026-10-27)
- 휴대폰 진동 1종. 약타격 12ms 한 번, 강타격 35ms 한 번(길이만 다름). 숫자는 `HAPTIC` 한 곳.
- 기본 꺼짐. 소리 버튼 옆 진동 버튼(📳). 켤 때 확인 진동 1번. 진동을 지원하지 않는 브라우저(아이폰 사파리, PC 대부분)에선 버튼 숨김.
- 타격 순간 `impact()` 에서 소리와 같은 방식으로 모아 두고 프레임 끝에 가장 센 것 1번.

| 새 상태 | 설정 / 진행 / 비움 | 그 상태 중 입력 | 겹침 처리 | 증명 |
|---|---|---|---|---|
| 진동 켜짐 `debug.vibe` | 진동 버튼 / — / 다시 누르면 꺼짐. 재시작해도 유지 | 게임 입력과 무관 | 소리와 독립(소리 비교 실험은 진동 끈 채로) / 타이틀·게임오버에서도 전환됨 / 버튼 누른 뒤 blur | vibe #1, #2 |
| 이번 프레임 진동 `pendingVibe` | 타격 순간 모으기(이미 heavy면 그대로) / update() 끝에서 1번 내고 비움 / reset() 에서도 비움 | — | 순서 상관없이 가장 센 것 1번 / 프레임 번호를 저장하지 않아 재시작 영향 없음 | vibe #3 |
| 진동 버튼 위치 | 소리 버튼 왼쪽. 전체화면 버튼이 없으면 한 칸씩 오른쪽으로 | 탭 | 게임 화면 안 / 진동 미지원이면 숨김 | vibe #4 |
