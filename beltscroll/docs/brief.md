새 게임 프로젝트를 시작한다. 이 폴더의 CLAUDE.md를 먼저 읽고 그 규칙을 따른다.

## 만들 것
브라우저 2D 벨트스크롤 액션 게임의 "최소 손맛 데모".
플레이어 1명이 적 1종(팔레트 스왑 2색)을 상대로 이동·기본 공격 3연타를 할 수 있고, 맞을 때 타격감이 느껴지는 상태까지.
이 데모의 목적은 "애니메이션 대신 이펙트와 타격감으로 손맛을 낼 수 있는가"를 검증하는 것이다.

## 기술 조건
- Vite + 순수 JavaScript + Canvas 2D. 게임 엔진 라이브러리는 쓰지 않는다 (데이터→렌더러 구조를 직접 통제하기 위해).
- 캐릭터는 이미지 파일 없이 코드로 그린다. 도형 파츠(머리·몸통·팔·다리)를 JSON으로 정의하고 렌더러가 조립한다.
- 동작은 키프레임 + 보간으로 만든다. 각 파츠에 각도·오프셋·스케일을 두고, 렌더러가 키프레임 사이를 이즈아웃으로 보간한다. 적은 키프레임으로도 부드럽게 움직이는 것이 도형 파츠 방식의 강점이다.
- 게임 루프는 고정 스텝(1/60초, 누적기 방식)으로 돌린다. 화면 갱신 속도와 상관없이 같은 입력이면 같은 결과가 나와야 한다.
- 모든 랜덤은 시드 고정 난수 함수 하나를 거친다. `Math.random()`을 직접 쓰지 않는다.
- URL 파라미터 `?scene=<이름>&frame=<N>&seed=<수>&paused=1`을 받으면 해당 장면을 시드 고정으로 N프레임까지 진행한 뒤 멈춘다. `scene`에는 스크립트로 정해진 상황(예: `hit-test` = 플레이어가 적에게 3연타를 넣는 장면)을 등록한다.
- `tools/snap.js` (Playwright 사용)
  - 실행 시 `vite build` 후 `vite preview`를 직접 띄우고, 끝나면 종료한다. 오너가 서버를 따로 켤 필요가 없어야 한다.
  - 기본 모드: 위 URL 파라미터로 장면을 열어 PNG 1장을 `snaps/`에 저장한다.
  - `--strip` 모드: 지정 장면에서 타격(hit) 이벤트가 일어나는 시점 전 2프레임~후 10프레임, 12장을 가로로 이어붙인 PNG 1장을 만든다. 각 칸 아래에 프레임 번호, 시간배율, 카메라 흔들림 오프셋, 적 x좌표를 작은 글씨로 찍는다. 같은 구간의 프레임별 수치를 `snaps/<장면>.json`으로 저장한다.
  - 저장한 PNG에 쓰인 색 중 해당 캐릭터·이펙트 팔레트 밖의 색 개수를 출력한다 (안티에일리어싱 중간색은 RGB 각 ±8 허용).
- `package.json` 스크립트: `dev`(개발 서버), `snap`(= `node tools/snap.js`), `snap:strip`(= `node tools/snap.js --strip`).

## 게임 사양 (1차 출발값 — 바꾸면 이유와 함께 보고에 적는다)
- 내부 해상도 640×360, 브라우저 창 크기에 맞춰 정수 배율로 확대. 60fps 고정 스텝.
- 이동 가능한 바닥(깊이 띠)은 y 240~340. 그리기 순서는 y 오름차순(아래쪽이 앞). 모든 캐릭터 발밑에 타원 그림자.
- 공격 판정: x 범위가 겹치고, 두 캐릭터의 깊이(y) 차이가 24px 이내일 때만 맞는다.
- 조작: 방향키 이동(상하 = 깊이 이동), Z 공격. 방향키의 브라우저 기본 스크롤은 막는다.
- 3연타: 공격 동작이 끝나기 전 200ms 안에 Z가 다시 눌리면 다음 타로 이어지고, 없으면 1타로 돌아간다. 피격 중에는 입력을 무시한다.
- 적 행동: 플레이어 쪽으로 걷기 → 거리 48px 안이면 1초 간격으로 공격 → 맞는 중에는 행동 중단. 체력 3(3연타 1세트로 쓰러짐). 쓰러지고 1초 뒤 화면 밖에서 다시 등장.
- 타격감 출발값: 1·2타 히트스톱 4프레임, 3타 10프레임. 흔들림·넉백도 3타를 1·2타보다 크게. 정확한 값은 오너가 눌러보고 조정한다.

## 진행 순서 (단계마다 끝나면 짧게 보고하고 git 커밋)

### 1단계 — 뼈대 세팅
- CLAUDE.md의 폴더 구조대로 프로젝트를 만든다. `git init`, `.gitignore`(node_modules, dist, snaps)를 만든다.
- `npm install` 후 `npx playwright install chromium`까지 실행한다. 설치가 실패하면 오너에게 칠 명령을 코드블록으로 그대로 보고하고 멈춘다.
- 확인할 것: 빈 화면이 뜬다 / snap이 PNG 1장을 찍는다 / 같은 장면·프레임·시드로 두 번 찍은 PNG가 완전히 같다.
- 보고에 오너가 직접 게임을 띄우는 명령 2줄(`npm install`, `npm run dev`)과 열 브라우저 주소를 적는다.

### 2단계 — 룩 시안 3종, 여기서 멈춤
세 가지 스타일로 시안을 만든다. 각 시안은 PNG 1장 안에 3칸으로 찍는다: ① 대기 ② 3타가 적에게 맞는 순간(타격 이펙트·흔들림 포함) ③ 적이 맞고 밀려나는 순간. 룩은 이펙트가 터지는 순간으로 판단해야 하기 때문이다.
- A. 실루엣형: 검은 실루엣 + 포인트 컬러 1색, 이펙트만 화려하게
- B. 저해상도 픽셀형: 320×180 캔버스에 그린 뒤 이미지 보간을 끄고 정수 배율로 확대
- C. 플랫 벡터형: 단색 면 + 굵은 외곽선

세 시안은 렌더 방식만이 아니라 캐릭터 생김새 설계도 서로 다르게 한다 (같은 막대인간에 필터만 바꾼 결과는 실패로 본다). 공통 조건:
- 실루엣만 봐도 플레이어와 적이 구분되고, 공격 포즈가 읽힌다.
- 실사 비율 금지. 머리 1 : 몸통 1.5 : 다리 1.5 정도의 과장된 비율에서 시작한다.

세 장을 보여주고 **오너가 고를 때까지 다음 단계로 가지 않는다.** 각 시안에 "이 스타일로 적 바리에이션을 늘리기 쉬운 정도"를 한 줄씩 붙인다.
오너가 고른 시안 PNG를 `data/_reference/look.png`로 저장하고 결정을 `docs/decisions.md`에 적는다.

### 3a단계 — 손맛 먼저 검증, 여기서 멈춤
선택된 스타일로 아래만 만든다. 나머지 포즈는 아직 만들지 않는다.
1. 플레이어: 대기 + 공격 1타 (예비 1 → 타격 1 → 복귀 1, 키프레임 3개). 타격 키에서 공격 팔 스케일 1.3 / 몸통 스케일 0.9(찌그러짐)를 출발값으로 둔다.
2. 적: 대기 + 피격 1포즈
3. 타격 이펙트 1종
4. 타격감 프리셋 2종: 기본 / 강 (강은 기본을 복제해 값만 키운다)

브라우저에서 Z를 눌러 서 있는 적을 때려볼 수 있게 하고 디버그 키를 넣는다:
- `F`: 타격감 프리셋 기본 ↔ 강 전환 (같은 공격으로 비교)
- `S`: 직전 타격 구간을 0.25배속으로 다시 재생
- `H`: 히트박스 표시 켜기/끄기

`npm run snap:strip -- hit-test`로 두 프리셋의 콘택트 시트와 수치를 찍어 보고에 붙이고, 오너에게 세 디버그 키 사용법을 적는다.
**오너가 직접 눌러보고 손맛 방향을 확인할 때까지 멈춘다.**
같이 보고할 것: 코드로 그린 캐릭터가 데모 설득력에 못 미친다고 판단되면, 선택지로 "파츠 설계 1회 재작업" 또는 "캐릭터만 외부 스프라이트 1세트 도입"을 제시한다.

### 3b단계 — 기준 에셋 완성
오너 확인을 반영해 나머지 포즈를 채운다. 키프레임 수 기준:
- 플레이어: 대기 2, 걷기 2, 공격 각 타 3(총 9), 피격 1
- 기본 적: 대기 2, 걷기 2, 공격 3, 피격 1, 쓰러짐 2

완성된 플레이어·기본 적·타격 이펙트·타격감 프리셋 2종을 `data/_reference/`에 저장한다. 이 에셋들이 이후 모든 바리에이션의 원본이다.
JSON 규격은 미리 크게 설계하지 말고 이 에셋을 만들면서 필요한 필드만 정의한 뒤 `data/_reference/SCHEMA.md`에 정리한다.
각 에셋은 CLAUDE.md 5번 자기 검수 루프를 거친다.

### 4단계 — 플레이 가능 데모
- 게임 사양대로 이동·3연타·적 행동·재등장이 동작한다.
- 적 2마리 등장: 기본 적 원본 1 + 팔레트만 바꾼 복제 1. 복제는 `data/characters/`에 JSON 파일을 추가하는 것만으로 등장해야 한다 (바리에이션 규칙 검증).
- 3타에만 "강" 타격감 프리셋을 적용한다.
- 3a단계의 디버그 키 3개는 그대로 유지한다.

## 완료 기준
- `npm run dev`로 브라우저에서 바로 플레이할 수 있다.
- 적 복제본이 엔진 코드 수정 없이 `data/` 파일 추가만으로 등장했다.
- `snap:strip` 수치 로그 기준으로 3타가 1·2타보다 히트스톱 프레임 수 2배 이상, 화면 흔들림 최대 진폭 2배 이상, 넉백 거리 1.5배 이상이다. 세 수치를 보고에 적는다.
- 같은 장면·프레임·시드의 snap PNG가 두 번 찍어도 완전히 같다.
- 최종 보고: 플레이 화면 PNG 1장 + 3타 콘택트 시트 1장 + 디버그 키 사용법 + 오너가 다음에 정할 것 2~3개.
