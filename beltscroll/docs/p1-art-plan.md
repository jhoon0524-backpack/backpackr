# P1 제안: 정식 아트 스타일과 전투 스프라이트 제작 계획 (제안, 오너 확인 전)

P0(조선 퇴마전 시각 전환)는 **기술적 전환 단계**로 마무리한다. 지금 게임 속 그림(윤무겸·원귀·도깨비·마을)은 `art.js` 가 코드로 그린 **임시 그림이며 정식 그래픽으로 확정하지 않는다.** P1 은 정식 그래픽을 정하고 만들어 `data/sprites.js` 구조로 바꿔 끼우는 단계로 제안한다. 전투 판정·타격감·콤보·잡기·적 AI 는 P1 에서도 그대로 두고, 새 직업·스킬은 만들지 않는다.

## 1. 지금 화면에서 본 아트 스타일 차이 (P0 전후 비교 사진 `docs/joseon-p0/compare-*.png`)
| 요소 | 지금 | 설정화와의 거리 |
|---|---|---|
| 캐릭터 | 3px 칸의 굵은 픽셀, 단색 면 + 검은 외곽선 1칸, 키 약 37칸 | 설정화(01~05)는 먹선·채색 일러스트, 07 은 세밀한 픽셀 일러스트(인물 키 약 230~250px). 얼굴·옷 무늬가 거의 안 읽힘 |
| 마을 건물·하늘·산 | 캐릭터와 같은 굵은 코드 픽셀 | 스타일은 캐릭터와 맞지만 설정화보다 단순 |
| 바닥 | 06 설정화를 잘라 1/3 로 줄인 세밀한 그림 | **화면 안에서 가장 세밀** → 캐릭터·건물과 결이 다르다(바닥만 "그림", 나머지는 "도트") |
- 결론: 지금은 바닥과 나머지의 해상도 결이 섞여 있다. 정식 스타일을 정할 때 **캐릭터·배경·바닥을 한 해상도 결로 통일**해야 한다.

## 2. 정식 아트 스타일 제안 (스타일 기준서 1장으로 확정)
- **기준 그림:** 디자인(얼굴·복장·색·무기)은 03 윤무겸 설정화와 02 캐릭터 시트, 그리는 방식(도트 밀도·외곽선·명암)은 07 아틀라스·06 장면(둘 다 픽셀 일러스트라 게임 화면과 결이 가장 가깝다).
- **화면 해상도 결:** 게임 기본 화면 960×540 에서 3배 확대 도트(지금)가 아니라 **1~1.5배 수준의 세밀한 도트**. 캐릭터 화면 키 약 110~120px (윤무겸 111px, 도깨비는 더 크게, 원귀는 작게 — 지금 비율 유지).
- **색:** 03 "주요 색상" 견본(먹색·남청·회갈·주홍·금속·누런 백색) + 밤 장면 공통 빛(등불 주황 테두리 빛, 달빛 푸른 그림자).
- **외곽선·명암:** 07 처럼 어두운 색 외곽선 + 3단 명암. 배경은 캐릭터보다 채도·대비를 낮춰 캐릭터가 먼저 읽히게.
- **읽힘 규칙(손맛용):** 적의 공격 예고(windup) 그림은 실루엣만으로 구분될 것, 윤무겸 칼끝은 판정 끝(몸 중심 앞 57px)과 같을 것, 적 주먹 끝은 적 사거리(52px) 이하.

## 3. 만들 것 (전투 스프라이트)
| 대상 | 칸 수 | 비고 |
|---|---|---|
| 윤무겸 | 필수 14 + 선택 5 + 3타 전용 2(준비·회수) = 21 | `docs/sprite-spec.md` 이름 그대로. 잡기 4칸은 맨손, 점프 공격 `airKick` 은 발차기 |
| 원귀 | 14 + 선택 2(달려들기) | 예고 그림이 흰 소복에 묻히지 않게. 걷는 실루엣 몸 앞끝 약 27px (판정 hurtHalfWidth) |
| 도깨비 | 14 + 선택 2(달려들기) | 윤무겸보다 크고 위압적으로. 지금 코드 그림은 40칸 프레임 한계(117px)라 정식 시트에서 더 키울 수 있다 (시트는 칸 크기가 자유) |
| 배경 | 하늘·먼 산·뒷마을·마을 길 4겹 + 옆에서 본 바닥 띠 | 지금 바닥은 위에서 본 06 을 잘라 쓴 것이라 옆에서 본 원근으로 다시 그리기 |
| 합계 | 캐릭터 49칸 (윤무겸 21 + 원귀 14 + 도깨비 14) + 적 달려들기 선택 4칸 + 배경 5장 | 이펙트·UI 는 P1 범위 밖으로 두기 제안 |

### 3타 전용 3칸 (2026-10-28 오너 결정, PR #31 에서 넘어온 작업)
지금 임시 3타는 칼날을 48px 로 늘리려고 그림 전체를 15px 뒤로 물려, 준비 → 찌르기에서 상체가 앞으로 나가는 양이 12px → 0px 다 (`docs/sword-reach.md` 9·10절, `docs/sword-reach-3-thrust-seq.png`). 정식 스프라이트에서 그림만으로 해결한다.
| 칸 | 그림 | 지킬 것 |
|---|---|---|
| 3타 준비 | 상체·어깨를 뒤로 당김 (칼은 몸 쪽으로 거둬 겨눔) | 3타 준비 구간(10프레임)에만 쓰임. 1·2타 준비(`windup`)와 구분 |
| 3타 찌르기 | 앞발 내딛고 상체가 준비 칸보다 약 9~12px 앞으로 나가 보이게, 칼 수평 | 칼끝 57px, 칼날 45~51px, 판정 프레임·데미지·히트스톱·넉백 그대로 |
| 3타 회수 | 칼을 거두며 기본 자세로 돌아옴 | 회수 구간에만 쓰임 |
- 바뀌는 것은 그림뿐: 공격 프레임 수·데미지·히트스톱·넉백·캐릭터의 실제 이동 좌표(발 기준점)는 그대로. "앞으로 나가는 느낌"은 칸 안에서 몸을 앞에 그려서 낸다.

## 4. 만드는 방법 (선택지)
| 방법 | 장점 | 단점 |
|---|---|---|
| (가) 픽셀 아티스트에게 의뢰 | 칸끼리 얼굴·비율이 일정, 판정 규칙을 지켜 그려 줌 | 비용·기간 |
| (나) 이미지 생성 + 사람이 다듬기 | 빠름 | 14칸이 같은 인물로 보이게 맞추는 일이 가장 어렵고 손이 많이 감. 설정화처럼 한 장은 잘 나오지만 동작 연속은 약함 |
| (다) 지금 코드 그림을 더 세밀하게 | 비용 없음, 바로 적용 | 설정화 수준과는 거리가 남 |
- **추천: (가)**, 예산이 어려우면 (나)를 윤무겸 1명으로 먼저 시험.

## 5. 진행 순서와 확인 지점
1. **스타일 기준서 1장** (위 2절을 그림 예시와 함께) → 오너 확인
2. **시범** → `data/sprites.js` 에 넣어 게임 속에서 크기·발 위치·칼끝 위치만 확인 (`tests/sprites.js`, `tests/shots.js` 전후 사진) → 오너 확인. 시범 범위는 오너 판단:
   - (가) 윤무겸 3칸(서기·1타·공격 준비): 가장 싸다. 단 시트 칸과 코드 칸(굵은 도트)이 동작마다 번갈아 보여 "깨져 보일" 수 있음
   - (나) 추천(director 제안): 윤무겸 8칸(서기·걷기 4·준비·1타·2타) + 도깨비 2칸(공격 예고·펀치) — 걷는 동안 결이 섞이지 않고, 손맛에 영향 있는 적 예고 그림을 일찍 확인
   - **→ 오너 결정 (2026-10-28): (나) + 3타 전용 준비·찌르기·회수 3칸 = 윤무겸 11칸 + 도깨비 2칸.** 디자인 기준 03, 세밀한 도트 기준 06·07. 첫 결과물은 정식 스프라이트 시안 + 기존 전투 화면 적용 비교.
3. 윤무겸 21칸 완성 → 자동 측정 전체(`node tests/run-all.js`) + 실제 손 조작 확인
4. 도깨비·원귀 각 14칸 (적 예고가 읽히는지 director 검수)
5. 배경 5장 교체 → 전후 사진 비교
- 각 단계마다 자동 회귀 측정(전체 `node tests/run-all.js`, 칼끝·판정 `tests/reach.js` 포함)은 판 기록이 그대로여야 한다 (그림만 바뀜).

## 6. P1 에서 같이 정하면 좋은 것 (P0 검토에서 나온 것)
- **모바일 버튼 위치 (P1 과 따로, 작은 UI 단계로 제안):** 공격 버튼은 게임 화면 오른쪽 아래(게임 좌표 x 819~902, y 402~486), 점프 버튼은 오른쪽 위쪽 걷는 줄(x 703~787, y 283~367)을 덮는다. 자동 플레이 측정에서 적 몸 **중심점**이 버튼 아래 있는 비율은 1.6%(작업 전 2.8%), 주인공 바로 옆(120px 안) 적은 0% — 단 중심점만 센 값이라 몸이 일부 겹치는 경우는 더 많다(비교 사진 모바일 웨이브3 의 누운 적이 공격 버튼 아래). 버튼은 반투명(평소 흰색 12%, 누르는 동안 40%).
  - 화면 양옆 검은 여백은 기기마다 다르다: 915×412 약 91px, 844×390 약 75px, 2:1 기기·전체화면은 0~40px 라 지금 72px 버튼이 다 안 들어간다.
  - 선택지: (가) 여백이 버튼보다 넓으면 여백으로, 좁으면 지금 자리 + 더 투명하게 (나) 버튼을 화면 아래 끝 줄(걷는 깊이 아래)로 내리기 (다) 그대로. 기준: 걷는 줄 안 몸 상자 가림 0%. 결정은 오너.
- 누운 도깨비 몸통 색(지금 새끼줄 갈색이라 서 있을 때와 달라 보임) — 정식 시트에서 해결.
