## 6단계 결과 (2026-10-27)
- 적 능력치·웨이브·타격감 숫자를 `data/enemies.js`·`data/waves.js`·`data/feel.js` 로 옮김(숫자 그대로). 적 데이터에 그림 이름(art)·넘어뜨림(knockdown) 추가 → "brute 면 넘어짐" 같은 코드 속 이름 판단 없앰. 처치 번쩍임 2배도 feel.js 로.
- 무작위 3곳(적 등장 깊이·파티클·적 공격 간격)을 시드 고정 난수 1개로. 다시 시작할 때마다 같은 시드부터. 흔들림은 원래 무작위가 아닌 카메라 킥이라 바꿀 것 없음. 소리 잡음은 판에 영향 없어 그대로.
- 데이터 이름 오타 점검: 페이지를 열 때 틀린 적 이름·그림 이름이 있으면 어느 파일 어느 이름인지 알림창.
- 느낌 그대로: 측정 25종 전·후 전체 출력 250줄 비교 → 실제 시간 기반 터치 측정의 걷기 거리(원래 매번 다름)만 다르고 차이 0. 히트스톱 4/10프레임, 카메라 킥 2px·3프레임 / 7px·8프레임, 넉백 약 4/65px 그대로.
- 같은 입력 반복: 클리어까지 한 판(2480프레임) × 3번 기록 완전히 같음(바꾸기 전엔 3번 모두 다름).
- 데이터만 고쳐 적 추가 시험(사본): boss(덩치 그림, 체력 120, 데미지 20, 넘어뜨림) 등장·값 반영·주인공 넘어짐 확인. 실제 게임엔 추가 안 함.
- 그림 자동 비교 제안: Playwright 는 이미 이 작업 환경의 모든 측정에 쓰는 중이라 "도입"이 아니라 "고정 프레임 사진 비교를 더할지" 문제. 장점: 숫자 측정이 못 잡는 그림·배치 깨짐을 잡음, 시드 고정 덕에 같은 프레임이 매번 같은 그림. 단점: 그림·글자를 조금만 바꿔도 "다름"이 나와 기준 사진을 다시 찍어야 함, 오너가 직접 돌리긴 어려움(Node 필요). 별개로 측정 스크립트들이 지금 작업 환경 임시 폴더에만 있어 세션이 끝나면 사라짐 → 저장소(`beltscroll/tests/`)에 넣는 것도 함께 제안.
- director 즉시 수정 반영: 데이터 오타 시 화면이 말없이 굳던 문제(알림창), 처치 번쩍임 배수를 feel.js 로, 문서 문구(던져 처치는 "쿵"만).

## 진동 (오너 요청, 2026-10-27)
- 휴대폰 진동 1종: 약타격 12ms, 강타격 35ms, 주인공이 맞을 때 35ms(오너 결정, 때릴 때와 구분). 기본 꺼짐, 진동 버튼(📳, 소리 버튼 왼쪽). 켤 때 확인 진동. 한 프레임에 가장 센 것 1번.
- 휴대폰·태블릿(손가락이 기본인 기기)에서만 버튼이 보임. 아이폰 사파리는 웹 진동이 없어 숨김. PC 크롬은 숨김. 터치 노트북은 실제 기기에선 숨겨질 것으로 보지만 측정 도구 흉내에선 보였다(실기기 미확인).
- claude.ai 화면 안에서도 진동 버튼을 한 번 탭하면 그 뒤로 진동이 허용된다(director 측정: 다른 출처 iframe 에서 탭 뒤 true). 켤 때 확인 진동이 오면 정상.
- director 즉시 수정 반영: PC 에서 진동 버튼이 보이던 문제.
- 오너 결정(2026-10-27): 넘어질 때 소리는 약타격 유지, 맞을 때 진동 35ms, 진동 세기는 12/35ms 로 먼저 써보기(약하면 20/60ms). director 통과.

## 5단계 결과 (2026-10-27)
- 타격음 1종, 코드로 합성(파일 없음): 낮은 "퍽"(음높이가 떨어지는 사인파) + 짧은 "탁"(잡음). 약타격 220Hz, 강타격 110Hz. 설정 길이 0.09/0.20초, 실제로 들리는 길이 약 0.04/0.09초(멈춤 안에서 끝남).
- 기본 꺼짐. PC는 M 키, 휴대폰·PC 공통으로 화면 오른쪽 위 소리 버튼(🔇/🔊). 켤 때 확인음 1번. 켜져 있으면 오른쪽 아래에 SOUND 표시. 재시작해도 켠 상태 유지.
- 어떤 타격이 어떤 소리인지는 타격감을 따른다(1·2타·피격 약, 3타·처치·점프 공격·던지기 착지 강). F로 타격감을 강제하면 소리도 따라감. 한 프레임에 여러 명을 맞혀도 가장 센 소리 1번.
- 강타격 소리의 에너지 76%가 200Hz 아래 저음이라 휴대폰 스피커로는 차이가 잘 안 들린다 → 비교는 PC 스피커나 이어폰으로 (director 측정).
- director 즉시 수정 반영: 한 프레임에 소리가 순서에 따라 2번 겹치던 문제와 재시작 뒤 소리가 드물게 삼켜지던 문제 → 프레임 끝에 가장 센 소리 1번으로 바꿈.
