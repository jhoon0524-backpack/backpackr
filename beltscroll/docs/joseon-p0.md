# 조선 퇴마전 에셋 적용 (P0, 시각 세계관 전환)

오너 지시문: "Claude Code 작업 지시문 — 조선 퇴마전 벨트스크롤 에셋 적용 (P0)" + 추가 지시 (2026-10-27).
전투 로직·타격감은 손대지 않고 그림만 바꾼다. 원래 버전은 브랜치 `ccr-05037f70-jcsww6` 에 그대로 있다.

## 1. 구조와 기준선
- 브랜치: `joseon-p0-assets` (출발점 `ccr-05037f70-jcsww6` 의 f66552b). 원래 브랜치에는 덮어쓰거나 강제 푸시하지 않음.
- 실행: `beltscroll/index.html` 더블클릭 (같은 폴더에 `art.js`, `data/`, `assets/joseon/floor_dirt.png`).
- 렌더링 경로: 캐릭터·배경은 `art.js` 가 코드로 그린 픽셀 그림을 `index.html` 이 3배로 키워 그린다. 판정·이동·입력은 index.html, 숫자는 data/.
- 테스트: 지시문의 "28개"는 저장소 보관 당시 수이고, director 검수로 회귀 측정 3개(action·fix3·fix4)가 더해져 작업 전 **31개** (`beltscroll/tests`, `node run-all.js`). 작업 전 기준선 31개 전부 정상 실행. 이번 작업에서 `sprites` 1개 추가 → 32개.

## 2. 에셋 검수와 분류
7장 모두 투명 배경이 없는 RGB 시트(1536×1024, 06만 1254×1254)다. 한 그림에 여러 컷이 붙어 있고, 동작별 프레임이 없다.
**오너 지시: 7장은 공식 아트 스타일 기준.** 원본을 `assets/reference/` 에 그대로 보존 (게임은 직접 읽지 않음).
- 판본 2가지 (상세 `assets/reference/README.md`): 처음 받은 **경량 WebP 7장**(손실 압축, 투명도 없음)과 오너가 나중에 올린 **PNG 원본 7장**(`assets/reference/png-originals/`, 무손실, 복구 안내문 포함). 해상도는 같다(1536×1024, 06 만 1254×1254) — "고해상도"가 아니라 무손실·투명도 보존 원본이다.

## 5. 검증
- 자동: 작업 전 31개를 같은 순서로 다시 돌려 기준선과 비교 → 28개 출력 완전히 같음. 다른 3개: `touch`·`test` 는 실제 시간으로 기다리며 노는 측정이라 같은 버전끼리도 매번 다름(같은 버전 2번 비교로 확인), `typo` 는 알림창 문구에 새 그림 이름이 들어가 바뀜(오류 0). 추가한 `sprites` 정상.
- 같은 입력이면 같은 판(determ): 기준선과 같은 기록. director 재실행: 연타·멈춤·카메라 킥·잡기·벽 324가지 등 8개 기준선과 같음.
- 바닥 그림 지운 사본: 파일 1개 못 불러옴, 오류 0, 코드 흙길로 플레이 정상 (`docs/joseon-p0/after-fallback-no-floor-image.png`).
- 스프라이트 교체(sprites): 가짜 시트 → idle0 만 시트 그림(64px·1.5배), 시트에 없는 kick 은 코드 그림, HUD 얼굴 시트에서. 시트 파일 없음 → 코드 그림, 오류 0. 세 경우 판 기록 같음.
- 전후 사진: `docs/joseon-p0/before-*.png`, `after-*.png` (PC 타이틀·웨이브1·웨이브3, 휴대폰 가로 웨이브1).
- director 2차(http 로 띄워 픽셀 실측): 잡기·무릎·던지기 5장면 칼 픽셀 0, 준비·1·2타에서 칼 보임. 가짜 시트+코드 칸 섞어도 발 높이 같음, 좌우 뒤집기·번쩍임·무적 깜빡임 적용. 술·가슴끈 칸 보임.
- 그림 크기 실측(불투명 칸, 외곽선 포함): 윤무겸 111px, 원래 주인공·잡졸·덩치 87px, 원귀 78px, 도깨비 99px. 칼끝 몸 중심 앞 39px, 칼날 가로 10칸·세로 15칸(대각 54px).

## 6. 남은 문제
- 지금 윤무겸은 설정화를 기준으로 한 **임시 전투 스프라이트**(약 32칸 키 픽셀 그림)다. 설정화의 얼굴 표정·옷 무늬 수준은 정식 스프라이트가 필요하다. 필요 칸: `docs/sprite-spec.md` 의 14개(+ 잡기용 4개는 없으면 punch·stomp·windup·punch2 칸을 씀).
- 칼 길이: 오너 결정(2026-10-27) 대각선 54px 유지, 공격 범위·타격감 그대로.
- 도깨비 키: 40칸 프레임 한계(117px)까지 키움. 더 위압적으로 하려면 프레임 확장(구조 변경, 오너 확인 필요) 또는 정식 스프라이트.
- 판정 크기 `h` 는 그대로다. 그래서 H 키(판정 표시)로 보는 몸 상자와 그림 키는 다르다(판정은 x·깊이·높이 z 로만 하므로 플레이 영향 없음).
- 바닥: 이음매는 없앴지만 섞은 구간(150px)은 두 그림이 반투명으로 겹쳐 살짝 흐리다. 고리 길이 801칸이라 스테이지(1204칸)에서 한 번 반복된다.
- **GitHub 의 Vercel 실패 표시 (게임 코드와 무관):** PR #30 의 Vercel 상태 3개(joseon-exorcist·dropbid·backpackr)가 모두 "Deployment rate limited — retry in 24 hours" 로 실패. 이 PR 과 상관없는 dropbid 프로젝트도 같은 문구라 **빌드 횟수 한도** 때문이다. 이 게임은 빌드가 필요 없는 정적 파일이고, GitHub Actions 검사는 0개. 한도가 풀리면 다시 배포하면 된다.
- 원귀·도깨비 선택: 설정화의 귀화는 사람 모양이 아니라 지금 포즈를 못 써서 원귀·도깨비를 골랐다.
- 바닥 질감은 위에서 본 그림이라 원근이 조금 다르다(디딤돌 줄이 경계를 가려 사진상 크지 않음). 원본 PNG 는 받아 보관했지만(`assets/reference/png-originals/`) 해상도가 같아 바닥은 WebP 에서 만든 그대로 둠.
- 타이틀 글꼴은 구글 글꼴에서 받는다(오프라인이면 기본 글꼴, 기존 Press Start 2P 와 같은 의존).
- file:// 로 열면 바닥·시트 그림 때문에 화면 캔버스 픽셀을 읽을 수 없다(브라우저 보안). 지금 게임·측정은 픽셀을 읽지 않아 영향 없음. 나중에 그림 자동 비교는 스크린샷 비교로 해야 한다.
- assets.html 의 설명 글자 일부("먼 빌딩·가게 거리")는 옛 문구.
