# P1 도트 밀도 비교: 1px 시안 vs 2px 시험 (2026-10-28)

오너 결정(2026-10-28): 1px 시안을 바로 버리거나 2px 를 확정하지 않고, 윤무겸 서기·1타 2칸만 2px 로 다시 그려 실제 화면에서 비교. 최종 결정 뒤에 나머지 칸을 만든다.

## 1. 비교한 것
| 판 | 칸 | 그림 1칸 = 화면 | 키 | 1타 칼끝 / 판정 |
|---|---|---|---|---|
| 지금 코드 그림 | 40×40 | 3px | 111px | 57 / 57 |
| 1px 시안 | 128×128 | 1px | 110px | 57 / 57 (칼끝 높이 30) |
| 2px 시험 (`assets/sprites/trial/mugyeom-2px.png`, 게임엔 안 씀) | 64×64 | 2px | 110px | 56 / 57 (칼끝 높이 31) |
- 2px 판은 1px 판과 같은 관절 자리·옷·색·자세로 다시 그렸다 (`tools/p1-draft/draw.js` `makeDrawer(2)`). 1px 를 줄인 것이 아니다. 2px 도트답게 바깥 윤곽만 외곽선, 부위 경계는 그림자색, 그림자 띠는 1칸, 눈은 얼굴 안쪽 1칸으로 손봄.
- 발바닥 높이·키·칼끝 모두 `tests/sheets.js` 기준 안 (2px 판은 `GAME_URL=…/tests/out/density/game-2px/index.html node tests/sheets.js`).

## 2. 화면에 어떻게 그려지나 (보간·배율 확인)
- 게임 화면은 항상 960×540 그림 한 장이고, 브라우저가 화면 크기에 맞춰 늘리거나 줄인다. 이때 **섞지 않고 가장 가까운 픽셀만 고른다** (`image-rendering: pixelated`, 그리기도 `imageSmoothingEnabled = false`). 그래서 흐려지지는 않지만, 줄일 때는 픽셀 줄이 통째로 빠질 수 있다.
- 실험 (흰 1px 세로줄 240개를 그린 960px 그림을 915×412 화면 게임 폭 733px 에 띄움):

| 기기 화면 배율 | 기기 픽셀 폭 | 남은 1px 줄 | 섞인(회색) 칸 |
|---|---|---|---|
| 1 (저해상도 기기·작은 창) | 733 | **184 / 240 (23% 빠짐)** | 0 |
| PC 1440×900 창, 배율 1 (오너 PC 실측: 게임 1408×792 = 1.47배) | 1408 | 240 / 240, 단 **굵기 1px 53% · 2px 47% 로 들쭉날쭉** (같은 실험에서 2px 줄 160개는 모두 3px 로 고름) | 0 |
| 2 | 1466 | 240 / 240 (굵기 1·2px 로 고르지 않음) | 0 |
| 2.625 (Pixel 7 같은 보통 폰) | 1924 | 240 / 240 (모두 약 2px) | 0 |
- 계산으로 본 "그림 칸이 화면에 하나라도 남는 비율" (가로·세로 모두): 배율 1 — 1px 칸 58%, 2px 칸 100%, 3px 칸 100% · 844×390 배율 1 — 1px 칸 52%, 2px·3px 100% · 배율 2 이상 — 모두 100%.
- **결론: 1px 시안이 화면 맞추기 방식 때문에 불리한 경우는 두 가지** — ① 비정수 확대(오너 PC 1.47배: 선 굵기가 1·2px 로 섞여 얇은 선이 고르지 않음) ② 배율 1 축소 화면(1px 줄 23% 빠짐). 요즘 휴대폰(배율 2 이상)은 1px 칸이 하나도 빠지지 않는다. 2px 는 두 경우 모두 영향이 거의 없다.
  - 지난 보고의 `docs/p1/compare-mobile.png` 는 휴대폰 사진을 비교 그림에 붙이면서 다시 절반 가까이 줄여(섞어서) 1px 시안이 실제보다 뭉개져 보였다 → 이번 사진은 모두 기기 픽셀 그대로 붙였고, `compare-mobile.png` 도 다시 만들었다.
- 그래도 남는 차이 = **실제 크기**. Pixel 7(약 416ppi) 가로 화면에서 게임 1px = 기기 2px = 약 0.12mm. 30cm 거리에서 1px 는 시력 한계(각도 1분) 근처(약 1.4분), 2px 는 약 2.8분, 3px 는 약 4.2분. 즉 보통 폰에서 1px 눈·술·장식은 "있지만 잘 안 보이는" 크기다.

## 4. 항목별 비교 (자체 평가, 오너 확인 필요)
| 항목 | 1px 시안 | 2px 시험 |
|---|---|---|
| PC 원본 화면 | 창이 정확히 960 폭이면 가장 세밀(눈·앞머리·술·띠 장식까지). 오너 PC(1.47배)에선 선 굵기가 1·2px 로 섞여 칼날·외곽선이 고르지 않음 | 덩어리가 또렷하고 단단해 보임. 얼굴은 눈 1칸 정도로 단순 |
| 휴대폰 915×412 (보통 폰) | 픽셀은 안 빠지지만 눈·술·장식이 0.12mm 라 거의 안 읽힘. 칼날이 가늘어(약 2px) 1타 궤적이 약하게 보임 | 얼굴 윤곽·상투·도포 덩어리·칼날이 한 단계 굵게 읽힘. 칼날이 가장 잘 보임 |
| 배율 1 화면 | 1px 줄의 약 4분의 1 이 빠져 눈·외곽선·칼날이 군데군데 끊김 | 빠지는 칸 없음 (굵기만 조금 고르지 않음) |
| 배율 2 화면 | 1px 선 굵기가 1·2px 로 들쭉날쭉 | 굵기 3·4px — 덜 들쭉날쭉 |
| 얼굴·상투 | 1px: 눈·눈썹·앞머리 가닥·관·붉은 끈 모두 표현 가능 | 눈 1칸·눈썹 1~2칸, 관·끈은 2~3칸 덩어리. 표정 표현은 어렵다 |
| 실루엣과 배경 | 몸 윤곽선이 1px 라 흙바닥(중간 갈색)과 경계가 약함 | 바깥 윤곽 2px 로 배경과 분리가 잘 됨. 배경(06 을 1/3 로 줄인 바닥, 3px 건물)과 굵기 결이 1px 보다 가깝다 |
| 공격 순간 칼끝 | 57px (차이 0), 칼날 가늘다 | 56px (차이 1, 2px 칸 단위라 홀수 57 에 정확히 못 맞춤), 칼날 굵고 밝다 |
| 07 설정화 결 | 07 인물은 키 약 230~330px 로 그려진 그림이라, 키 110px 에서는 1px 로도 07 만큼 세밀할 수 없다 — 1px 가 07 의 "느낌"에 더 가깝다 | 07 보다 굵은 도트. "세밀한 도트"보다 "또렷한 도트" |
| 제작 비용 | 칸당 그릴 픽셀이 2px 의 약 4배 → 칸당 시간 가장 큼 | 1px 의 약 1/2 시간 (명세서 8절 어림) |

## 5. 추천
- 이 비교가 보는 것은 **선 굵기·크기에 따른 가독성**(선이 보이나, 칼이 보이나, 윤곽이 배경과 떨어지나)뿐이다. 2px 판은 1px 의 관절 자리를 옮겨 손본 것이라 사람이 2px 로 처음부터 그린 것보다 얼굴·덩어리 설계에서 불리하고, 얼굴 완성도는 1px·2px 모두 시안 수준이다 — 얼굴은 판단 기준에서 뺀다.
- **(나) 2px 를 게임 속 전투 스프라이트의 기본 밀도로 추천.** 근거 순서:
  1. 실제 크기: 보통 폰(Pixel·아이폰 공통 수준)에서 게임 1px 는 약 0.12mm, 30cm 거리에서 시력 한계 근처(약 1.4분각) — 1px 눈·술·장식은 픽셀이 남아도 거의 안 읽힌다. 2px 는 약 2.8분각.
  2. 오너 PC 화면(1.47배 비정수 확대): 1px 선은 1·2px 로 섞여 들쭉날쭉, 2px 선은 3px 로 고르다.
  3. 칼날·윤곽 가독성: 휴대폰 확대 사진(`density-phone-closeup-x2.png`)에서 2px 칼날이 가장 또렷하고 바깥 윤곽이 흙바닥과 잘 떨어진다 — 손맛에 직접 걸린 정보.
  4. (보조) 배율 1 화면에선 1px 줄이 빠진다 — 다만 이런 기기의 실제 비율은 확인하지 못했다.
  5. (보조) 제작 시간이 1px 의 약 절반.
- 1px 의 세밀함(07 결·표정)은 전투 스프라이트 대신 **HUD 얼굴·타이틀·대화창 초상화**(크게 보이는 곳)에 쓰는 것을 함께 제안 (이번 범위 밖, 오너 판단).
- (가) 1px 유지가 나은 경우: PC 를 주요 화면으로 정하고 창 크기를 게임 크기의 정수배로 맞추거나, 화면 확대(카메라를 가까이)를 함께 바꿀 때.
- (다) 3px(지금 코드 그림 밀도): 휴대폰에서 가장 굵게 읽히지만 03 설정화의 옷 구성(망토·술·속자락)을 담기 어렵다.
- 결정 방법 제안: 오너가 자기 폰·PC 로 시안판 링크를 열어 "칼날이 보이나, 윤곽이 배경과 떨어지나"만 보고 정한다 (2px 시험 2칸은 비교 사진으로만 — 게임 시안판은 1px).
