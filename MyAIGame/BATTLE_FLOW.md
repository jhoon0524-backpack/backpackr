# 전투 흐름 설계 (Battle Flow)

`scripts/battle_rules.gd` 의 계산식을 실제 턴 진행에 끼워 넣는 순서를 정한다.
구현 전에 이 문서를 먼저 읽고, 구현 중 규칙이 바뀌면 이 문서부터 고친다.

## 상태 목록

| 상태 | 하는 일 | 다음 상태 |
|---|---|---|
| `BATTLE_START` | 전투 진입 연출, "야생 OO 이(가) 나타났다" 출력 | `TURN_START` |
| `TURN_START` | 턴 수 +1, 명령 가능 여부 갱신 | `COMMAND_SELECT` |
| `COMMAND_SELECT` | 플레이어가 기술/후원/교체/도망 중 선택 | `MOVE_SELECT` 또는 `ENEMY_DECIDE` |
| `MOVE_SELECT` | 기술 4개 중 선택. 취소하면 되돌아감 | `ENEMY_DECIDE` |
| `ENEMY_DECIDE` | 적 AI가 보유 기술 중 하나를 무작위 선택 | `RESOLVE` |
| `RESOLVE` | 양쪽 행동을 순서대로 실행 | `TURN_END` |
| `TURN_END` | 종료 조건 확인 | `TURN_START` / `FORCED_SWAP` / `BATTLE_END` |
| `FORCED_SWAP` | 내 아이디가 쓰러졌고 파티에 남은 아이디가 있을 때 강제 교체 | `TURN_START` |
| `BATTLE_END` | 결과 처리 후 필드로 복귀 | (씬 전환) |

```
BATTLE_START
     |
     v
TURN_START <-------------------+
     |                         |
     v                         |
COMMAND_SELECT --> MOVE_SELECT |
     |                  |      |
     +--------+---------+      |
              v                |
        ENEMY_DECIDE           |
              |                |
              v                |
          RESOLVE              |
              |                |
              v                |
          TURN_END ------------+
              |         \
              |          +--> FORCED_SWAP --+
              v
         BATTLE_END
```

## 행동 순서

`RESOLVE` 는 두 행동을 다음 우선순위로 정렬해 하나씩 실행한다.

1. **도망** — 가장 먼저 처리한다
2. **교체** — 그다음
3. **후원(영입)** — 그다음
4. **기술** — 마지막. 기술끼리는 `speed` 가 높은 쪽이 먼저,
   같으면 무작위

즉 플레이어가 후원이나 교체를 고르면 적의 기술보다 항상 먼저 실행된다.
느린 아이디로도 영입을 시도할 수 있어야 하기 때문이다.

앞선 행동으로 전투가 끝나면 뒤 행동은 실행하지 않는다.
(영입에 성공했는데 적이 반격하는 일이 없어야 한다)

## 행동별 처리

### 기술
1. `BattleRules.element_multiplier(기술 속성, 상대 속성)` 으로 배율을 구한다
2. `BattleRules.calculate_damage(공격, 방어, 위력, 배율)` 로 데미지를 구한다
3. 상대 HP 를 깎는다. 0 밑으로는 내려가지 않는다
4. 배율이 2.0 이면 "효과가 굉장했다" 메시지를 덧붙인다

### 후원 (영입)
1. `BattleRules.capture_chance(현재 HP, 최대 HP)` 로 성공률을 구한다
2. 후원 카드를 1장 소모한다
3. 난수 판정. 성공하면 파티에 추가하고 `BATTLE_END` 로 간다
4. 실패하면 메시지만 출력하고 턴을 넘긴다

### 교체
1. 파티에서 살아 있는 다른 아이디를 고른다
2. 교체 후에도 상대의 행동은 그대로 실행된다

### 도망
1. 항상 성공한다. 확률을 두지 않는다
2. 가벼운 톤을 위한 선택이다. 지고 다시 오는 데 마찰이 없어야 한다

## 명령 비활성 조건

`TURN_START` 에서 매 턴 다시 판정한다.

| 명령 | 비활성 조건 |
|---|---|
| 후원 | 후원 카드 0장 / 파티가 3마리로 꽉 참 / 보스전 |
| 교체 | 살아 있는 다른 아이디가 없음 |
| 도망 | 보스전 |

## 전투 종료 조건

`TURN_END` 에서 위에서부터 순서대로 확인한다.

1. 영입 성공 → `영입` 결과로 종료
2. 도망 → `도망` 결과로 종료
3. 상대 HP 0 → `승리`. 후원금을 획득하고, 목표 금액에 닿았으면 진화 처리
4. 내 파티 전원 HP 0 → `패배`. 마지막 거점으로 복귀
5. 내 아이디만 HP 0, 파티에 남은 아이디 있음 → `FORCED_SWAP`
6. 그 외 → `TURN_START` 로 돌아가 다음 턴

## 구현 메모

- 상태는 `enum State` 와 `_change_state(next)` 하나로 관리한다.
  노드를 상태별로 나누지 않는다. 상태가 9개뿐이라 과한 구조다
- 각 상태는 진입할 때 할 일을 하고, 다음 상태로 넘어갈 조건만 본다
- 메시지 출력은 상태 전환을 막는다. 텍스트가 다 나온 뒤 다음으로 넘어간다
- 데미지 난수 때문에 디버깅이 어려우면 `calculate_damage` 의 `roll` 인자에
  1.0 을 넘겨 고정할 수 있다
