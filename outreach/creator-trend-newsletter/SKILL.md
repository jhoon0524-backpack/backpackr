# 크리에이터 트렌드 뉴스레터 스킬

텀블벅 프로젝트 URL들을 입력받아 창작자 대상 트렌드 뉴스레터를 작성하고, Notion 붙여넣기용 .md 파일로 출력한다.

## 입력 형식

사용자가 다음 중 하나의 방식으로 URL을 제공한다:
- 텍스트로 나열: `https://tumblbug.com/xxx`
- 마크다운 링크: `[프로젝트명](https://tumblbug.com/xxx)`
- 혼합 방식

URL이 없으면 사용자에게 URL을 먼저 요청한다.

## 실행 절차

### Step 1 — 브라우저로 각 프로젝트 페이지 읽기

`Claude in Chrome` 도구를 사용해 각 URL을 순서대로 방문하고 `get_page_text`로 전문을 읽는다.

수집할 핵심 데이터:
- 프로젝트명, 창작자명
- 달성률, 후원자 수, 모인금액, 목표금액
- 펀딩 기간 (완료 여부 포함)
- 프로젝트 소개 전문
- 리워드 구성 및 가격대
- 팀 소개 (창작자 배경)
- 후기 온도 (있으면)

### Step 2 — 트렌드 분석

수집한 데이터를 바탕으로 다음을 분석한다:

**공통 패턴 발굴**
- 카테고리/장르 공통점
- 성공 요인 (가격, 리워드 구조, 세계관, 마케팅 등)
- 소비자 수요 신호
- 창작자 배경의 공통점

**트렌드 네이밍**
- 이 묶음을 한 문장으로 설명할 수 있는 트렌드 명칭을 만든다
- ex. "덕업일치형 생산성 툴", "로컬 감성 굿즈", "세계관 수집형 IP"

**창작자 팁 도출**
- 분석에서 얻은 실제 인사이트를 구체적 행동 팁으로 변환
- 추상적 조언 금지, 프로젝트 사례를 근거로 제시

### Step 3 — 뉴스레터 초안 작성

`references/template.md`의 형식을 그대로 따른다. 형식 규칙은 아래 참고.

### Step 4 — .md 파일 출력

파일명: `tumblbug_creator_newsletter_YYYYMM.md`  
저장 경로: `/mnt/user-data/outputs/`  
작성 후 `present_files`로 사용자에게 전달한다.

## 뉴스레터 형식 규칙

> 상세 템플릿은 `references/template.md` 참고. 아래는 핵심 규칙 요약.

### 헤더
```
# 텀블벅 크리에이터 뉴스레터
## "[트렌드 명칭]" 트렌드 리포트

**발행:** YYYY년 MM월 | 텀블벅 MD팀  
**대상:** [해당 카테고리] 분야 창작자
```

### 섹션 구조 (순서 고정)
1. **이번 달 MD가 주목한 트렌드** — 트렌드 한 줄 정의, 왜 주목했는지
2. **실제로 터진 프로젝트 N개** — 프로젝트별 분석 블록
3. **MD가 발견한 공통 패턴** — 구조 도식 + 핵심 관찰
4. **창작자를 위한 기획 팁** — 번호 목록, 각 팁마다 근거 프로젝트 언급
5. **이 카테고리가 잘 맞는 창작자 유형** — 불릿 리스트
6. **마치며** — CTA 포함

### 프로젝트 분석 블록 형식
```markdown
### ① [프로젝트명] ([URL](링크)) — 달성률 N%, [완료/진행 중]

> *"[프로젝트 부제목]"*

[2-3문장 소개]

**왜 터졌나:**
- [근거 기반 포인트]
- [근거 기반 포인트]
- [근거 기반 포인트]
```

### 문체 규칙
- 창작자에게 말 걸듯 2인칭 ("~하세요", "~입니다")
- MD의 관찰자 시점 유지 ("저희 MD팀은", "MD가 발견한")
- 수치는 반드시 실제 데이터 사용 (임의 작성 금지)
- 각 팁은 추상적 조언이 아닌 프로젝트 사례 기반
- 과도한 이모지 자제 (섹션 헤더 1개 이하)

### Notion 붙여넣기 호환 규칙
- `#`, `##`, `###` 헤딩 사용
- 인용구는 `>` 사용
- 코드블록은 ` ``` ` 사용
- 볼드는 `**`, 이탤릭은 `*`
- 수평선은 `---`

## 품질 체크리스트

출력 전 다음을 확인한다:

- [ ] 모든 프로젝트 링크가 실제 URL로 포함되어 있는가
- [ ] 달성률, 후원자 수, 금액이 실제 데이터인가 (추정 금지)
- [ ] 트렌드 명칭이 구체적이고 기억하기 쉬운가
- [ ] 각 팁에 근거 프로젝트가 명시되어 있는가
- [ ] 섹션 순서가 template.md와 동일한가
- [ ] 파일명에 YYYYMM이 실제 날짜로 들어갔는가
